Tags/Forms and security/validator:*

{validator:*}

The browser's checker of the validation rules as one inline script, for a form a component draws.

Forms and security Single tags

Syntax 

{input:validator/}

Description

{input:validator} writes the browser's half of padValidate into the page as one inline script: the runtime, www/assets/rules/validate.js, with the script of every rule beside it - the same rules, the same messages. The rules are the files of pad/subs/rules/types/, each with its script in www/assets/rules/: accepted, after, after_or_equal, alpha, alphanum, before, before_or_equal, between, color, date, different, digits, distinct, email, ends_with, gt, gte, iban, in, integer, ip, isbn, json, lowercase, lt, lte, max, max_items, max_words, min, min_items, min_words, multiple_of, not_in, numeric, regex, required, required_if, required_unless, required_with, required_without, same, semver, slug, starts_with, time, timezone, ulid, uppercase, url, uuid. It is written once a page - a second {input:validator}, or one after a {input:form ..., client} that brought it already, writes nothing.

It is for forms the template does not write as a {input:form} - a form a React, Vue or Alpine component draws, or a plain HTML form. Keep the rules in the page's PHP: padValidate ( $rules ) checks the post, and padValidateClient ( $rules ) exports the same list for the browser, each rule with the message padValidate would give.

The script defines padValidate.check ( rules, values ) (the message of every field that broke a rule), padValidate.field ( spec, value, values ) (one field's, empty when it holds) and padValidate.form ( form ). Every form with a data-pad-rules attribute is checked by itself: when it is sent, and a field again when it is left. A regex: rule JavaScript cannot read as PCRE does passes in the browser and is left to the server, which checks every post anyway.

Under a Content-Security-Policy that names 'nonce' the script carries this request's {pad:nonce}.

Validation rules

Each kind has its own description and usage example:

accepted, after, after_or_equal, alpha, alphanum, before, before_or_equal, between, color, date, different, digits, distinct, email, ends_with, gt, gte, iban, in, integer, ip, isbn, json, lowercase, lt, lte, max, max_items, max_words, min, min_items, min_words, multiple_of, not_in, numeric, regex, required, required_if, required_unless, required_with, required_without, same, semver, slug, starts_with, time, timezone, ulid, uppercase, url, uuid

Examples

Rules from PHP, checked in the browser

The page exports its rules with padValidateClient; any form carrying them in data-pad-rules is checked by the script {input:validator} writes.

Templateexamples/validator/1-plain-form.pad 
<form method="get" novalidate data-pad-rules="{^signupRules}">
  <label for="v-email">E-mail</label> <input name="email" id="v-email">
  <label for="v-age">Age</label> <input name="age" id="v-age" type="number">
  <button>Check</button>
</form>
{input:validator/}
PHPexamples/validator/1-plain-form.php 
<?php

  $signupRules = padValidateClient ( [
    'email' => 'required|email',
    'age'   => 'required|integer|min:18' ] );

?>

A component asks the checker

An Alpine form drawn in the browser checks with padValidate.check - the same rules and messages padValidate ( $rules ) gives the post.

Templateexamples/validator/2-component.src 
{# signup.php: $rules = [ 'email' => 'required|email' ]; $check = padValidateClient ( $rules ); #}
<div x-data="{ rules: {^check}, form: {}, errors: {} }">
  <input x-model="form.email" @blur="errors = padValidate.check(rules, form)">
  <span class="error" x-text="errors.email"></span>
</div>
{input:validator/}

Rules that look at another field

required_if and after name another field of the form: the checker checks the field again when that one changes, so its message follows it.

Templateexamples/validator/3-conditional.pad 
<form method="get" novalidate data-pad-rules="{^tripRules}">
  <label for="c-delivery">Delivery</label> <select name="delivery" id="c-delivery"><option>collect</option><option>ship</option></select>
  <label for="c-address">Address</label> <input name="address" id="c-address">
  <label for="c-start">Start</label> <input name="start" id="c-start" type="date">
  <label for="c-end">End</label> <input name="end" id="c-end" type="date">
  <button>Check</button>
</form>
{input:validator/}
PHPexamples/validator/3-conditional.php 
<?php

  $tripRules = padValidateClient ( [
    'address' => 'required_if:delivery,ship',
    'end'     => 'after:start' ] );

?>

Rules that compare

different holds a value apart from another field, multiple_of a number to whole steps, gt a number above another, after_or_equal a date on or after another; the checker judges them as padValidate does, again when the other field changes.

Templateexamples/validator/4-comparing.pad 
<form method="get" novalidate data-pad-rules="{^accountRules}">
  <label for="m-current">Current password</label> <input name="current_password" id="m-current" type="password">
  <label for="m-password">New password</label> <input name="password" id="m-password" type="password">
  <label for="m-bottles">Bottles</label> <input name="bottles" id="m-bottles" inputmode="numeric"> <small>by the crate of six</small>
  <label for="m-low">Lowest price</label> <input name="min_price" id="m-low" inputmode="decimal">
  <label for="m-high">Highest price</label> <input name="max_price" id="m-high" inputmode="decimal">
  <label for="m-arrive">Arrive</label> <input name="arrive" id="m-arrive" type="date">
  <label for="m-leave">Leave</label> <input name="leave" id="m-leave" type="date">
  <button>Check</button>
</form>
{input:validator/}
PHPexamples/validator/4-comparing.php 
<?php

  $accountRules = padValidateClient ( [
    'password'  => 'required|min:8|different:current_password',
    'bottles'   => 'integer|multiple_of:6|max:120',
    'max_price' => 'numeric|gt:min_price',
    'leave'     => 'after_or_equal:arrive' ] );

?>

Rules that count

A field named guests[] posts a list: distinct refuses a value it holds twice, the fields left blank left out; min_items and max_items count the boxes ticked, max_words the words of a text.

Templateexamples/validator/5-lists.pad 
<form method="get" novalidate data-pad-rules="{^partyRules}">
  <fieldset>
    <legend>Guests</legend>
    <label>First <input name="guests[]" type="email"></label>
    <label>Second <input name="guests[]" type="email"></label>
    <label>Third <input name="guests[]" type="email"></label>
  </fieldset>
  <fieldset>
    <legend>Toppings, two or three</legend>
    <input type="checkbox" name="toppings[]" value="cheese" id="l-cheese"> <label for="l-cheese">Cheese</label>
    <input type="checkbox" name="toppings[]" value="olives" id="l-olives"> <label for="l-olives">Olives</label>
    <input type="checkbox" name="toppings[]" value="basil" id="l-basil"> <label for="l-basil">Basil</label>
    <input type="checkbox" name="toppings[]" value="onion" id="l-onion"> <label for="l-onion">Onion</label>
  </fieldset>
  <label for="l-note">A note for the host</label> <textarea name="note" id="l-note" rows="2"></textarea>
  <button>Check</button>
</form>
{input:validator/}
PHPexamples/validator/5-lists.php 
<?php

  $partyRules = padValidateClient ( [
    'guests[]'   => 'required|distinct',
    'toppings[]' => 'required|min_items:2|max_items:3|in:cheese,olives,basil,onion',
    'note'       => 'max_words:12' ] );

?>
