# Location inputs and identifier validation

`timezonepicker` submits an IANA identifier. Its native select works without JavaScript; the enhancement adds a keyboard-accessible filter. `reference=` is an explicit ISO instant with an offset, used to show DST-correct UTC offsets. The deterministic default is 2000-01-01 UTC; applications should supply the relevant meeting date. Pair it with `rules='timezone'`. Invalid posted values stay visible for correction.

`coordinatepicker` submits `name[latitude]` and `name[longitude]` in decimal WGS84 degrees. Native numbers provide bounds (-90..90 and -180..180). Validate both fields on the server with `numeric|between:-90,90` and `numeric|between:-180,180`; the widget neither requests geolocation nor calls a geocoder. Nested field names and native form reset/disabled behavior are preserved. `label=` names the fieldset; each input has its own Latitude or Longitude label. Child validation messages attach to their inputs, whose IDs are the group ID followed by `-latitude` or `-longitude`. The default IDs match `{widget:errorsummary/}`; with `id='place'`, use its `fields=['name[latitude]'=>'place-latitude','name[longitude]'=>'place-longitude']` mapping for summary links.

`hostname` accepts ASCII DNS labels and punycode A-labels, including a single trailing root dot. It rejects Unicode, IP literals, leading/trailing label hyphens and overlength labels. It performs no DNS lookup. `cidr` accepts IPv4/IPv6 with a decimal prefix in the family range; host bits are allowed, zone IDs and padded prefix numbers are rejected. `luhn` validates 2 to 32 digits with optional spaces/hyphens and says nothing about an identifier's existence. The form engine retains its shared empty-value convention; add `required` where needed. Browser implementations match the PHP fixtures.
