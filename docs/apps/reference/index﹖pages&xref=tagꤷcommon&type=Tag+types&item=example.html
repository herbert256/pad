App: manual - Page: pages/app_tests
PHP
 HTML
pages/app_tests.pad 		Result 
{pad:meta title='Application tests'/}

<p>An application keeps its own tests in <code>_tests/</code>. A test is a page there -
<code>cart.pad</code>, with <code>cart.php</code> when it needs data - next to its answer,
<code>cart.txt</code>. <code>pad test shop</code> renders every test page and compares:</p>

{pad:ignore}
<code>$ pad test shop
shop
  ok    cart
  FAIL  checkout
        want: <p>Total 42</p>
        got:  HTTP 500 - assert failed: $total eq 42
              apps/shop/_tests/checkout.pad:1:1  {pad:assert $total eq 42/}
  2 tests, 1 failed</code>
{/pad:ignore}

<h2>The answer</h2>

<ul>
  <li>the exact output of the page, trimmed;</li>
  <li><code>/a pattern/</code> matched over it - for output that changes, a date or a count;</li>
  <li><code>HTTP 500</code>, with an optional <code>/pattern/</code> on the next line, for a test that is meant to fail.</li>
</ul>

<p>A test without an answer counts against the run; <code>pad test shop --record</code> writes
the missing answers from what the pages render now, and never overwrites one.
<code>pad test --all</code> runs every application that has tests, and <code>./ci.sh</code>
does that as its <code>apptests</code> line.</p>

<h2>Asserts</h2>

<p>{app:tag 'assert'/} holds a page to a condition during a test run: false, and the test fails
with the condition and the message as its report. Anywhere else it is silent - the
condition is not even evaluated - so it can stay in the application's own pages. The switch
is <code>$padAssert</code>, which <code>pad test</code> turns on; this example turns it on in
its PHP:</p>

{common:example 'fragments/app_tests_1'/}

<h2>A test page</h2>

<p>It is a page like any other, rendered bare - without the application's wrappers - and no
URL reaches it. It can bring in a real page with <code>{pad:page 'cart'/}</code>, or
include the page's own PHP and check the data it sets:</p>

{pad:ignore}
<code>_tests/cart.php    <?php include APP . 'cart.php'; ?>
_tests/cart.pad    {pad:assert $total eq 42, 'the cart total'/}
                   <p>Total {$total}</p>
_tests/cart.txt    <p>Total 42</p></code>
{/pad:ignore}

App: manual - Page: pages/application_options
PHP
 HTML
pages/application_options.pad 		Result 
{pad:meta title='Options of your own'/}

<p>A file in the application's <code>_options/</code> directory makes its name an option
of every tag - written bare, <code>{local:staff words}</code>, or with a value,
<code>{local:staff wrap='em'}</code>. Where the file stands decides when it runs:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>file</th><th>runs</th><th><code>$padContent</code> is</th></tr>
  <tr><td><code>_options/name.php</code></td><td>before the tag renders</td><td>the template between the tags</td></tr>
  <tr><td><code>_options/end/name.php</code></td><td>after the tag rendered</td><td>the result - every occurrence, joined</td></tr>
</table>

<p>&nbsp;</p>

<p>The handler changes <code>$padContent</code>, and the option's value is in
<code>$padGetName</code> - TRUE when the option is written bare. An end option sees the
fields filled in, so it can count, mark or tidy what the tag produced. Here
<code>fragments/options/_options/end/words.php</code> appends a word count:</p>

{pad:ignore}
<code><?php                                   // _options/end/words.php

  $padContent .= '(' . str_word_count ( strip_tags ( $padContent ) ) . ' words)';

?></code>
{/pad:ignore}

{common:example 'fragments/options/options_1'/}

<p>With a value - <code>_options/end/wrap.php</code> puts the result in the element it is
given:</p>

{pad:ignore}
<code><?php                                   // _options/end/wrap.php

  $padContent = "<$padGetName>" . trim ( $padContent ) . "</$padGetName>";

?></code>
{/pad:ignore}

{common:example 'fragments/options/options_2'/}

<p>An option may have both files: the first works on the template, the second on what it
became. The end options run before the built-in <code>toContent</code>, <code>toData</code>
and <code>tidy</code> - those store or tidy what the end option made - and before the closing
tag's pipe. Like tags and callbacks they are looked up from the page's directory up to the
application root.</p>

App: manual - Page: pages/arrays
PHP
 HTML
pages/arrays.pad 		Result 
{pad:meta title='Array helpers'/}

<p>A page's PHP file mostly works on arrays: a row from the database, a list of rows, a
decoded JSON answer, nested settings. The array helpers do the everyday work on them - read
a value deep inside, take one field of every row, keep the rows that pass, group, sort and
sum - so the PHP stays a few lines and the template gets data ready to show. They are plain
functions with a <code>padArr</code> name, loaded on every request like the rest of
<code>pad/lib/</code>, and they work on objects too: an <code>ArrayAccess</code> object
through its offsets, any other object through its public properties.</p>

<h2>Dot paths</h2>

<p>A dot path names a value inside nested arrays: <code>'customer.address.city'</code>, with
an integer key as a segment - <code>'lines.0.sku'</code>. A <code>*</code> segment reads every
item of that level and answers a list: <code>'lines.*.sku'</code> is every product.
<code>padArrGet</code> answers the default when the path is not there - a Closure as the
default is called only then - and <code>padArrSet</code> makes the levels on the way.</p>

{common:example 'fragments/arrays_1'/}

<p><code>padArrHas</code> is true when every path given exists, also when its value is NULL
- where <code>isset()</code> says no. <code>padArrSet</code> and <code>padArrForget</code>
change the array they are given and answer it as well.</p>

<h2>Picking keys</h2>

<p><code>padArrOnly</code> keeps the top-level keys given, in the order they are given;
<code>padArrExcept</code> drops them, and takes dot paths. Keys are an array or a
comma-separated string.</p>

{common:example 'fragments/arrays_2'/}

<h2>Working with rows</h2>

<p><code>padArrPluck</code> takes one field of every row, keyed by another field when one is
given - the id and name pairs of a select box. <code>padArrKeyBy</code> keys the rows
themselves, to find one without a loop.</p>

{common:example 'fragments/arrays_3'/}

<p><code>padArrWhere</code> keeps the rows that pass, with their keys: a field equal to a
value, a field compared with an operator, or a callback. The operators are
<code>= == === != <> !== < > <= >=</code> (and PAD's own <code>eq ne lt gt
le ge</code>), <code>in</code> and <code>not in</code> with a list, and <code>like</code> with
SQL's <code>%</code> and <code>_</code>, ignoring case. Equality is PHP's loose
<code>==</code>, so the string <code>'5'</code> a database answers equals a 5 written in PHP.
<code>padArrSortBy</code> sorts by a field, stable, ascending or with <code>TRUE</code> or
<code>'desc'</code> descending; <code>padArrFirst</code> and <code>padArrLast</code> answer the
first and last row a callback passes.</p>

{common:example 'fragments/arrays_4'/}

<h2>Groups and numbers</h2>

<p><code>padArrGroupBy</code> answers the rows in groups - the groups in the order their
first row came, each group a list. <code>padArrSum</code>, <code>padArrAvg</code>,
<code>padArrMin</code> and <code>padArrMax</code> work on the numbers among the values, or
among a field of every row: a NULL or a text that is no number is left out rather than
counted as 0. The sum of no numbers is 0, the others answer NULL.</p>

{common:example 'fragments/arrays_5'/}

<h2>Reshaping</h2>

<p><code>padArrDot</code> makes a nested array one level with dot path keys, and
<code>padArrUndot</code> makes it nested again. <code>padArrFlatten</code> answers the values
of nested arrays as one list, to a depth when one is given; <code>padArrWrap</code> makes any
value an array - NULL none, an array itself, anything else one item.</p>

{common:example 'fragments/arrays_6'/}

<h2>The functions</h2>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>function</th><th>what it answers</th></tr>
  <tr><td><code>padArrGet ( $target, $key, $default = NULL )</code></td><td>the value at a dot path, or the default; a NULL key is the target itself</td></tr>
  <tr><td><code>padArrSet ( &amp;$array, $key, $value )</code></td><td>sets the value at a dot path, making the levels on the way; the array</td></tr>
  <tr><td><code>padArrHas ( $array, $keys )</code></td><td>whether every dot path given exists - a NULL value exists</td></tr>
  <tr><td><code>padArrForget ( &amp;$array, $keys )</code></td><td>removes one or several dot paths; the array</td></tr>
  <tr><td><code>padArrOnly ( $array, $keys )</code></td><td>the top-level keys given, in the order given</td></tr>
  <tr><td><code>padArrExcept ( $array, $keys )</code></td><td>the array without the keys given - dot paths too</td></tr>
  <tr><td><code>padArrPluck ( $rows, $value, $key = NULL )</code></td><td>one field of every row, keyed by another field when given</td></tr>
  <tr><td><code>padArrWhere ( $rows, $key, $operator, $value )</code></td><td>the rows that pass, keys kept</td></tr>
  <tr><td><code>padArrFirst ( $array, $callback = NULL, $default = NULL )</code></td><td>the first value, or the first a callback passes, or the default</td></tr>
  <tr><td><code>padArrLast ( $array, $callback = NULL, $default = NULL )</code></td><td>the same from the end</td></tr>
  <tr><td><code>padArrGroupBy ( $rows, $key )</code></td><td>the rows in groups by a field, each group a list</td></tr>
  <tr><td><code>padArrKeyBy ( $rows, $key )</code></td><td>the rows keyed by a field, a later row winning</td></tr>
  <tr><td><code>padArrSortBy ( $rows, $key, $descending = FALSE )</code></td><td>the rows sorted by a field, stable; string keys kept, a list numbered again</td></tr>
  <tr><td><code>padArrFlatten ( $array, $depth = INF )</code></td><td>the values, nested arrays opened up</td></tr>
  <tr><td><code>padArrDot ( $array, $prepend = '' )</code></td><td>a nested array as one level with dot path keys</td></tr>
  <tr><td><code>padArrUndot ( $array )</code></td><td>dot path keys made nested arrays again</td></tr>
  <tr><td><code>padArrWrap ( $value )</code></td><td>the value as an array</td></tr>
  <tr><td><code>padArrSum / Avg / Min / Max ( $rows, $key = NULL )</code></td><td>the sum, average, smallest, largest of the numbers</td></tr>
</table>

<p>A field to work on - <code>$key</code>, <code>$value</code> - is a dot path or a callback
(a Closure, given the row and its key); a string is always a dot path. Where a list is
expected, NULL, an empty string or any other plain value is an empty list, so the answer of a
query that found nothing goes through without a check. A wrong argument - an unknown
operator, a negative depth, a key that is no key - is reported as a PAD error naming the
function.</p>

App: manual - Page: pages/charts
PHP
 HTML
pages/charts.pad 		Result 
{pad:meta title='Charts'/}

<p>{app:tag 'chart:bar'/} draws a chart as inline SVG on the server. There is no JavaScript, so the
chart prints, works where scripts do not run, and caches like any other output. A
<code>bar</code> chart puts columns on a zero baseline; a <code>line</code> chart draws a line
over a light wash with the last point marked.</p>

{common:example 'fragments/charts_1'/}

<p>The first word picks the kind of chart, after the job the data has to do:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>Kind</th><th>Shows</th><th>Options</th></tr>
  <tr><td><code>line</code></td><td>change over time</td><td><code>label</code>, <code>value</code></td></tr>
  <tr><td><code>bar</code> (or <code>column</code>), <code>hbar</code></td><td>categories compared</td><td><code>label</code>, <code>value</code>, <code>stacked</code></td></tr>
  <tr><td><code>pie</code>, <code>donut</code></td><td>parts of a whole</td><td><code>label</code>, <code>value</code></td></tr>
  <tr><td><code>scatter</code>, <code>bubble</code></td><td>how two numbers relate</td><td><code>x</code>, <code>y</code>, <code>size</code>, <code>label</code>, <code>color</code>, <code>trend</code></td></tr>
  <tr><td><code>heatmap</code></td><td>patterns in a grid of two categories</td><td><code>x</code>, <code>y</code>, <code>value</code></td></tr>
  <tr><td><code>sankey</code></td><td>flows from one stage to the next</td><td><code>source</code>, <code>target</code>, <code>value</code></td></tr>
  <tr><td><code>network</code></td><td>connections</td><td><code>source</code>, <code>target</code>, <code>value</code>, <code>layout</code>, <code>arrows</code></td></tr>
  <tr><td><code>treemap</code>, <code>sunburst</code></td><td>a hierarchy, each part's share</td><td><code>label</code>, <code>value</code>, <code>levels</code></td></tr>
  <tr><td><code>sparkline</code></td><td>a shape the size of a word</td><td><code>label</code>, <code>value</code></td></tr>
</table>

<p>An option left out takes the first field that fits: a numeric one for a number, another one
for a name.</p>

<p>Every kind is a file of <code>pad/subs/charts/types/</code>, and the files there are the kinds
there are - the <a href="../reference/">reference</a> lists them, each with the pages that draw
it. Select a kind with its qualified name: <code>{chart:pie data='budget'/}</code>.</p>

<h2>Where the numbers come from</h2>

<ul>
  <li><code>data='sales'</code> - a {app:tag 'data'/} store, a sequence store, an array of the page's PHP, or a <code>_data</code> file of that name.</li>
  <li><code>value=</code> names the field with the number, <code>label=</code> the field for the axis. Without them the first numeric field is the value and the first other field the label.</li>
  <li><code>sequence='fibonacci', rows=12</code> - the first terms of a sequence, for demo data straight away.</li>
</ul>

<h2>Several series</h2>

<p>A list of fields in <code>value=</code> draws a series each - bars side by side, or on top of
each other with <code>stacked</code>, or a line each, named at its end. A legend above the plot
names them in the fixed order of the colours; eight series at most.</p>

{common:example 'fragments/charts_3'/}

<h2>Horizontal bars</h2>

<p><code>hbar</code> lays the bars down, the names on the left - for long names or many
categories.</p>

{common:example 'fragments/charts_4'/}

<h2>Pie and donut</h2>

<p>Parts of a whole: only positive values count, clockwise from twelve o'clock, a legend with
each value and its share. Past eight parts the smallest are folded into one grey
<em>Other</em>. A donut shows the total in its middle.</p>

{common:example 'fragments/charts_5'/}

<h2>Scatter and bubble</h2>

<p>A dot per row on two numeric axes, <code>x=</code> and <code>y=</code>. <code>color=</code>
colours the dots by a field, <code>trend</code> draws the least-squares line. A bubble's
<code>size=</code> sets its area.</p>

{common:example 'fragments/charts_6'/}

<h2>Heatmap</h2>

<p>Two categories as columns (<code>x=</code>) and rows (<code>y=</code>), each cell coloured by
its value in seven steps of one hue, with the scale underneath.</p>

{common:example 'fragments/charts_7'/}

<h2>Sankey</h2>

<p>A row is a flow from <code>source=</code> to <code>target=</code>, as wide as its
<code>value=</code>. The columns follow the flows; flows that go round in a circle are an
error.</p>

{common:example 'fragments/charts_8'/}

<h2>Network</h2>

<p>A row is a link between two nodes. The default <code>layout='force'</code> pulls linked nodes
together - the same data always draws the same picture - and <code>layout='radial'</code> sets
them on a circle; <code>arrows</code> shows the direction.</p>

{common:example 'fragments/charts_9'/}

<h2>Treemap and sunburst</h2>

<p><code>levels=</code> lists the fields above the parts, the outermost first. A treemap nests
rectangles, a sunburst rings; the colour is that of the outermost level.</p>

{common:example 'fragments/charts_10'/}

<h2>Sparklines</h2>

<p>{app:tag 'chart:sparkline'/} is a line chart the size of a word, without axes, to stand in a sentence
or a table cell.</p>

{common:example 'fragments/charts_2'/}

<h2>Drawn in the browser</h2>

<p>With <code>client</code> the browser draws the chart: the server hands it the rows and the
options and draws nothing itself, and a script draws the same SVG - character for character -
where the chart stands. Every kind has it.</p>

{common:example 'fragments/charts_11'/}

<h2>Accessible and themeable</h2>

<p>Every chart is an image to a screen reader (<code>role="img"</code>), named by its
<code>title=</code> and described by a list of its values. Every bar, point, slice, cell, flow
and node carries its own tooltip; a sparkline has none. The colours are CSS custom properties - <code>--pad-chart-series</code>,
<code>--pad-chart-text</code>, <code>--pad-chart-grid</code>, <code>--pad-chart-surface</code>,
the categorical <code>--pad-chart-1</code> to <code>--pad-chart-8</code>,
<code>--pad-chart-other</code> and the heatmap's <code>--pad-chart-heat-0</code> to
<code>--pad-chart-heat-6</code> - set on <code>.pad-chart</code>, and their defaults follow the
page's <code>color-scheme</code>, light or dark.</p>

App: manual - Page: pages/clean_urls
PHP
 HTML
pages/clean_urls.pad 		Result 
{pad:meta title='Clean URLs'/}

<p>A page is named in the query string - <code>/shop/?products/42</code> - or by the path
behind the application: <code>/shop/products/42</code>. The path is mapped onto the files,
and a file or directory whose name is a bracketed variable name stands for any one segment.
The segment becomes that variable before the page's PHP runs:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>url</th><th>file</th><th>variables</th></tr>
  <tr><td><code>/shop/products/42</code></td><td><code>products/[id].pad</code></td><td><code>$id</code> is 42</td></tr>
  <tr><td><code>/shop/products/new</code></td><td><code>products/new.pad</code></td><td>a name of its own wins over a bracket</td></tr>
  <tr><td><code>/shop/blog/2026/hello-pad</code></td><td><code>blog/[year]/[slug].pad</code></td><td><code>$year</code> and <code>$slug</code></td></tr>
  <tr><td><code>/shop/docs/a/b</code></td><td><code>docs/[path+].pad</code></td><td><code>$path</code> is the rest, a/b</td></tr>
</table>

<p>The same names resolve wherever a page is named - here through
<code>{pad:page}</code>, with <code>shop/products/[id].pad</code> and
<code>shop/blog/[year]/[slug].pad</code> beside the fragment:</p>

{common:example 'fragments/clean_urls_1'/}

<ul>
  <li><code>?products/42</code> resolves the same way, so the application runs on a server
      that routes no paths, and <code>/shop/index.php/products/42</code> works everywhere.
      A bracketed file is never reached by its own name.</li>
  <li>Every <code>?page</code> link keeps working: on a clean URL, a query string that starts
      with a bare page name - the relative <code>href="?about"</code> - names that page.</li>
  <li><code>$padCleanUrls = TRUE</code> in <code>_config/config.php</code> makes
      <code>$padGo</code> write <code>/shop/products/42</code>. Apache needs one line,
      <code>FallbackResource /shop/index.php</code>; <code>php -S</code> needs nothing.</li>
</ul>

App: manual - Page: pages/client_validation
PHP
 HTML
pages/client_validation.pad 		Result 
{pad:meta title='Validation in the browser'/}

<p>The rules a form's fields carry are checked on the server, after the post. With
<code>client</code> on the {app:tag 'form'/} the browser checks them too, as the visitor types and
before the form leaves - with the same rules and the same messages, so the two never
disagree. The server still checks every post: the browser's check only saves a round trip.</p>

{common:example 'fragments/client_validation_1', skipResult/}

<ul>
  <li>The form gets its rules in a <code>data-pad-rules</code> attribute, and the first such form
      of the page brings a small script along. A field is checked when it is left, again
      while it is typed in once it showed a message, and every field when the form is sent - a
      form that fails is not sent, and the first field with a message gets the focus.</li>
  <li>The messages stand where {app:tag 'input'/} puts the server's - a
      <code><span class="error"></code> after the field, tied to it with
      <code>aria-invalid</code> and <code>aria-describedby</code> - in the words of the field's
      label; the form's <code>error=</code> shows above the fields.</li>
  <li>A form with <code>client</code> needs a name and fields with <code>rules=</code>. A
      <code>regex:</code> rule JavaScript cannot read as PCRE does is left to the server.</li>
</ul>

<h2>Forms a component draws</h2>

<p>A React, Vue or Alpine form is no {app:tag 'form'/} of the template. Keep the rules in the page's
PHP instead - one list for both sides: <code>padValidate ( $rules )</code> checks the post, and
<code>padValidateClient ( $rules )</code> exports the same list for the browser, every rule
with the message padValidate would give:</p>

{common:example 'fragments/client_validation_2'/}

<p>{app:tag 'validator'/} in the template brings the checker without a form, and the component asks
it:</p>

{pad:ignore}
<code><div x-data="{ rules: {^rules}, form: {}, errors: {} }">
  <input x-model="form.email" @blur="errors = padValidate.check(rules, form)">

{pad:meta title='Barcodes and QR codes'/}

<p>{app:tag 'barcode:auto'/} and {app:tag 'barcode:qr'/} write a code a scanner reads. It is encoded on the server and
drawn as inline SVG - no image library, no font, no remote service - so a page with a code prints,
caches and goes in an e-mail like any other. There are {pad:echo php:count(padKinds('codes'))/}
symbologies, every one a file of <code>pad/subs/codes/types/</code>. Twelve or thirteen digits are an
EAN-13, with the check digit added when it is left off; any other text is Code 128.</p>

{common:example 'fragments/codes_1'/}

<h2>Two ways to write one</h2>

<p>The name after <code>barcode:</code> selects the symbology: <code>{barcode:upce '0425261'/}</code>.
The barcode type does the same, <code>{barcode:upce '0425261'/}</code>.
Both forms require their type prefix and draw the same UPC-E.</p>

{common:example 'fragments/codes_2'/}

<h2>Products, parcels and labels</h2>

<p>The product codes - <code>ean13</code>, <code>ean8</code>, <code>upca</code> and
<code>upce</code> - check the digit a number ends in, or add it; <code>databar</code>, GS1 DataBar, writes a
GTIN in the small symbol of loose fruit and vegetables. Code 128 and Code 93 take printable
ASCII, Code 39 capital letters, digits and a few signs, with <code>check</code> for its check
symbol. <code>itf</code> and <code>itf14</code> are the digits of cartons, <code>codabar</code> the
code of libraries and blood banks, <code>msi</code> that of shelf labels.
<code>gs1128</code> writes the GS1 element strings of a logistics label -
<code>(01)09501101530003(17)261231(10)AB-123</code> - with every value checked as GS1 defines it;
<code>datamatrix</code> with <code>gs1</code> writes them as GS1 DataMatrix, the code of medicine packs.
<code>bookland</code> is the barcode of a book, its ISBN as an EAN-13 with the ISBN above the bars,
and <code>addon=</code> puts two or five more digits beside an EAN or UPC - a magazine's issue, a
book's price.</p>

{common:example 'fragments/codes_3'/}

<h2>Two-dimensional codes</h2>

<p><code>qr</code> is the code of {app:tag 'barcode:qr'/}, which a phone camera reads; <code>datamatrix</code>
the square code of parts and medicine packs. Both take any text and choose the smallest symbol that
holds it, and both take <code>size=</code> in pixels in place of the height and scale of the bars.
<code>aztec</code>, the code of train tickets and boarding passes with a bullseye in its middle, does
the same, with <code>ecc=</code> for the share of its codewords that corrects errors.
<code>pdf417</code>, the code of boarding passes and driving licences, stacks rows of codewords
instead, each row telling the scanner where it stands; <code>columns=</code> sets how wide it is
and <code>level=</code> its error correction.</p>

{common:example 'fragments/codes_4'/}

<ul>
  <li>The colours are black on white unless <code>color=</code> and <code>background=</code> say
  otherwise - fixed, whatever the page's colour scheme, as a scanner needs the contrast.</li>
  <li>The SVG is <code>role="img"</code> with the text, or <code>title=</code>, as its name.</li>
  <li>A wrong check digit, a character the symbology has no bars for or a text too long for it is
  an error under the strict check, and nothing is drawn.</li>
</ul>

<p>PAD has two comment forms. Both are taken out of the template before it is scanned, so a tag written inside one never runs and nothing of it reaches the output.</p>

<h2>Rules</h2>

<ul>
  <li>A comment closes at the first <code>#}</code> or <code>--}</code> after it, and may span lines.</li>
  <li><code>{--</code> must be followed by whitespace: a CSS custom property inside an {app:tag 'ignore'/} block, <code>:root{--gap:4px}</code>, is CSS and stays as it is.</li>
  <li><code>{#name}</code> is not a comment but the option sigil - the value of the tag option <code>name</code>.</li>

<h2>Slots</h2>

<ul>
  <li>A <code>{pad:slot 'footer'}...{/pad:slot}</code> pair standing directly in the content of the tag is a fill: it is taken out of the content and goes where the template has its <code>{pad:slot 'footer'}</code>. The rest of the content goes to {app:construct 'content'/}.</li>
  <li>In the template, the content of a <code>{pad:slot}</code> is its default, rendered when the caller gave no fill. <code>{pad:slot 'header'/}</code> in the caller's content is an empty fill.</li>
  <li>A default holding {app:construct 'content'/} is a frame: <code>{pad:slot 'footer'}<small>&#64;content&#64;</small>{/pad:slot}</code> renders the frame round the fill, and nothing - or its {app:construct 'else'/} part - when there is no fill.</li>
  <li>A fill is the caller's text: it renders with the caller's variables, and a <code>{#name}</code> or a <code>{pad:slot}</code> inside it belongs to the caller's tag - which is how a template passes a slot of its own on to a tag it uses.</li>
</ul>

<h2>Every use has its own</h2>

<p>The fills belong to one use of the tag, so a card inside a card keeps its own footer:</p>

{common:example 'fragments/components_2'/}

<h2>Declared parameters</h2>

<ul>
  <li><code>{pad:parms title, tone='plain'/}</code> at the top of the template declares the parameters: a name alone is required, <code>name=default</code> fills in what the caller left out. Both read as <code>{#title}</code>.</li>
  <li>A required parameter left out is an error, and so - under the strict check - is a parameter the tag does not declare: <code>{app:card title='x', titel='y'}</code> is reported by name.</li>
</ul>

<h2>Components written in the template</h2>

<p>A component used on one page only needs no file of its own. <code>{pad:define 'name'}...{/pad:define}</code> writes it in the template: from there on <code>{define:name}</code> renders the body as <code>_tags/name.pad</code> would - <code>{pad:parms}</code>, <code>{#name}</code>, {app:construct 'content'/} and slots work alike.</p>

{common:example 'fragments/components_3'/}

<p>A <code>{pad:macro}</code> is called the way a function is: its parameters are declared on it - a name alone required, <code>name=default</code> filling in - given in their order or by name, and read as fields, <code>{$label}</code>.</p>

{common:example 'fragments/components_4'/}

<ul>
  <li>Both render at every use, in its place and with its fields; both can use themselves, for the rows below the current one.</li>
  <li>A define or macro exists from the point it is walked, as a <code>{pad:content}</code> store does: a use before it is an unknown tag.</li>
  <li>A macro given too many values, missing a required one, or given a name it does not declare is an error.</li>
</ul>

{pad:meta title='Template coverage'/}

<p>A test suite says what it checks; coverage says what it reaches. With coverage on, every
local request notes which templates it read, which of their tags ran, and which branch each
{app:tag 'if'/} and {app:tag 'case'/} took. The report then shows each template with the parts that
never ran marked.</p>

{common:example 'fragments/coverage_1'/}

<ul>
  <li><code>$padCoverage = TRUE</code> in <code>_config/config.php</code> records into the run
      <code>default</code>; a name instead of TRUE records into a run of that name, and
      <code>?page&amp;padCoverage=name</code> records one request.</li>
  <li><code>develop/?coverage&amp;start=suites</code> records every local request of every
      application until <code>develop/?coverage&amp;stop</code> - start it, run the suites,
      stop it, and <code>develop/?coverage&amp;run=suites</code> lists every template with the
      share of its tags and branches that ran, and the files no request read at all.</li>
  <li>A run is a file of JSON lines, <code>DATA/coverage/<run>.jsonl</code>, one line per
      request. Only local requests are recorded.</li>
  <li>An {pad:if} without an {pad:else} has one branch more: the run in which
      its condition was false. It is marked on the {/pad:if}.</li>
</ul>
