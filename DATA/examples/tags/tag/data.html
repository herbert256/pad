{pad:data 'name'} ... {/pad:data} reads its content as data and keeps it under that name; it prints nothing. A later {data:name} ... {/data:name} iterates it like any page array - fields, properties, the handling options (sort, where, first ...) - and so do data='name' on another tag, {data:name}, {pad:tree} and the lookup pipe.

Formats

The format is recognised from the content itself:

  • JSON - starts with [ or {. An array of objects gives rows with fields; a plain array gives values, read with {$name}.
  • XML - starts with <. The elements under the root are the rows, their attributes and child elements the fields.
  • YAML - starts with ---, or with a - item or key: value line. It needs PHP's yaml extension.
  • A list - ('a', 'b', 2 * 3) in parentheses: every element is evaluated as an expression.
  • A range - 1..10 or a..z.
  • CSV - anything else of several lines: the first line names the fields, each further line is a row.

When the start does not tell, format='toml' or type='csv' names the reader explicitly. A one-line name of a file in the application's _data/ directory reads that file.

Other forms

Without content, a second parameter is the source: {pad:data 'steps', '1..5'}. A value from a field there is data, never template: a field holding a parenthesised list is refused, since its elements would run as expressions. With the name on the closing tag - {pad:data} ... {/pad:data 'name'} - the content is rendered first and the result read as data, so fields and tags inside it are resolved.

Content with braces - JSON objects - is read as written: a JSON object in the content is not taken for a tag. Under the strict syntax check a {pad:data} without a name is an error, and so is a name that is already a built-in or application tag, since {data:name} would never reach the store.

A file of _data/ selects its reader by extension, for example {local:delivery.toml} or {local:sales.xlsx sheet='Notes'}. XLSX is binary: keep it in a file or pass the original bytes to padFormatRead; do not paste it into a template. JSON text sequences use the jsonseq format name explicitly because they have no registered file extension.

From PHP, padFormatRead ( 'toml', $contents ) reads a document and padFormatWrite ( 'toml', $data ) writes one. A page can return its exposed data with padFormat=toml. These helpers parse or serialize data; the separate list and range readers are template expressions, not interchange formats.
