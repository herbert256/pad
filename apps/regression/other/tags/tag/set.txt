<p><code>{set $name = value}</code> evaluates the value and assigns it to a global variable,
which every tag after it can read as <code>{$name}</code>. Several assignments go in one tag,
separated by commas. The tag prints nothing.</p>

<p>The assignment sticks: a <code>{set}</code> inside a loop, an <code>{if}</code> or any other
level outlives it, so a loop can add up a total that is still there after the loop. That is
the difference with a <code>$name = value</code> written on another tag -
<code>{orders $n = 5}</code> - which is that level's own and is unwound when the level
closes, and with <code>%name = value</code>, which is set again for every occurrence.</p>

<p>The values of one <code>{set}</code> are evaluated before any of them is assigned: in
<code>{set $a = 1, $b = $a + 1}</code> the <code>$a</code> on the right is the value from before
the tag (an error when there was none). Write two <code>{set}</code> tags when one value builds
on another.</p>

<p>Under the strict syntax check a <code>{set}</code> written as a pair, or one whose words
hold no <code>$name = value</code> assignment (a missing <code>$</code>, a missing value), is an
error. To count, <a href="?tag/increment">{increment}</a> and
<a href="?tag/decrement">{decrement}</a> are shorter; to keep a list or a piece of template,
<a href="?tag/data">{data}</a> and <a href="?tag/content">{content}</a>.</p>
