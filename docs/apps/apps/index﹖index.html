_common Shared resources and utilities the engine adds to every PAD application while $padCommon is TRUE, the default. edit
admin The web console of the PAD installation: every application with what it has, its files and pages, the pad command from the browser, maintenance mode, queues, schedules, logs, error dumps, the mail outbox, DATA/ storage, PHP, the PAD settings, git and its own users - behind a login, this machine only by default. edit

calendars Nine calendar views from `pad/subs/calendars/types/`: month, mini, week, day, agenda, quarter, year, timegrid and resources. The home page is a browsable month; each view has a rendered example and its complete template and event data, with links to the live and WASM editors. Run at `/pad/calendars/`. The menu and view catalog follow the files in the subsystem. `calendar:kind` selects a view; `calendar:month` shows the month grid. See [the subsystem](../../pad/subs/calendars/README.md) for parameters and pair row shapes. The [timegrid example](_examples/timegrid.pad) uses explicit-offset intervals, overlapping appointments, an all-day event and an interval crossing midnight. The [resources example](_examples/resources.pad) maps bookings to two rooms and shows their overlaps separately. Open `?timegrid` or `?resources` in the application. Both examples include paired `{format:auto}` blocks, so their editor links run without external data. Timed views render with a self-closing tag; calendar pair rows, date-field guessing, holidays and query navigation belong to the seven date views. See the [timegrid contract](../../docs/subsystems/calendars/timegrid.md) and [resource contract](../../docs/subsystems/calendars/resources.md) for interval fields, timezones and limits. edit
charts A showcase of the `{chart:bar}` tag: every kind of chart it draws, each with a few worked examples, in the frame every PAD application shares - the brand and the menu in the side, the page's title and the theme switcher in the bar. The menu has a heading per chart family and a link per example under it; the home page shows every example as a card with its chart drawn live. An example page has three cells - the data (JSON, YAML or PHP), the `{chart:bar}` tag that draws it, and the result - and both source cells are read from the page's own files, so what is shown is exactly what runs. An example written as a pair, `{chart:bar ...}` with its data (CSV, JSON, YAML or XML) between the tags, has one source cell for both. The page fits what the bar leaves of the window: the cells keep the same size on every example, so the previous and next links stay in one place. edit
classicModels Some PAD pages built on the Classic Models sample database, demonstrating the PAD Select subsystem: declared tables, relations between them, and the joins PAD derives from those. These pages were part of the manual until its examples were reorganised, after which the manual kept a page referring to them but the examples themselves were gone. They are recovered here, from commit ac148cccd, as an application of their own. edit

examples A search box over the harvested examples in `DATA/examples/` - the store the build's harvest fills with every page's `.php` and `.pad` sources and its rendered `.html`. A hit opens the example with the two sources on the left, coloured, and the rendered result beside them; on a narrow screen the result drops below the sources. The search matches the example's name first and the contents of its three files second, so `sequence/random` and `upper` both find their way. edit

The games are the files of `pad/subs/games/types/` - the list, the names and the descriptions are read from them (`_lib/games.php`), so a game added to the engine is here without a change to this application. edit

images Every pattern of the engine's patterns subsystem - seeded SVG backgrounds and generative art - to look at: the home page has a card per pattern, a pattern's page draws it large beside the template that does, with links to the seeds next to the one shown (`?topography&seed=8`), then the example the pattern's own file gives and the pattern as the background of a box, written with `as='url'`. The patterns are the files of `pad/subs/patterns/types/` - the list, the names, the descriptions and the examples are read from them (`_lib/patterns.php`), so a pattern added to the engine is here without a change to this application. The filters page does the same for the image filters of `{image:thumbnail}`, the other subsystem shown here: every filter on one picture. edit
inputs Every rich form field of the engine's inputs subsystem, to try: the home page has a card per kind, a kind's page puts it in a form that posts back and shows what the page's PHP received, whether the post kept the rules of the template, and the template itself. One form holds every kind with rules, checked in the browser too (`client`). The kinds are the files of `pad/subs/inputs/types/` - the list and the descriptions are read from them (`_lib/inputs.php`), and a kind without a page of its own here is shown by `[kind].pad`. edit
islands One runtime mounts components of any framework - React, Vue, Svelte, Preact, Solid - on the islands a PAD page writes; Vite builds them and {pad:vite} links the build. edit

padSelect A showcase of the PAD Select subsystem: the tables of a database declared once in `$padSelect`, the relations between them in `$padRelations`, and templates that walk them as tags - nested tables follow their relations, views stand on tables, joins, groups, totals, pages and unions - without a join written in a template. Every example is a page of four cells: the declarations it reaches, its template, the result, and the SQL PAD sent for it - each shape of statement once, with how many were sent. edit

The sample data comes from `{fake:rows}` with fixed seeds, the same on every request. edit

tables Spreadsheets in a page, made with the `{sheet:grid}` tag of the formulas subsystem: the cells are lines of text with a comma between them, or the rows of `data=`, and their formulas - spreadsheet syntax, read by a parser of the engine's own - are computed on the server with the functions of `pad/subs/formulas/types/`, which answer what Excel answers. Each example page runs its template and shows it, with the WASM editor and live icons; the functions page lists every function as its file describes it, each example computed on a sample sheet - a function added to the engine is there without a change to this application. edit
tags A page for every PAD tag, named with its type prefix: every built-in tag - `{pad:if}` - every kind of the seventeen subsystems with tag prefixes - `{chart:pie}`, `{game:memory}`, `{toy:life}`, `{diagram:state}`, `{widget:tabs}`, `{barcode:ean13}`, `{embed:youtube}`, `{input:slider}`, `{icon:star}`, `{fake:email}` - and every sequence type, `{sequence:fibonacci}`: its name and what it does in one line, its syntax with the options that belong to that tag (not the handling options every tag takes), a longer description, and examples - each runnable one rendered live beside its template, by the tag it documents. Over the pages stand the indexes: by name (A-Z), by group (what a tag is for), by form (single tag, pair, or either), by option (every option and the tags that take it), a cheat sheet with the syntax of every tag, and a search. edit
test A scratch application for trying things out. `_common` is switched off in its configuration, so everything a page here uses has to come from this application itself. edit
types A page for every type of PAD tag - the prefix before the colon of `{pad:if}`, `{chart:pie}`, `{field:name}`, `{sequence:fibonacci}`: what the type reaches in one line, how it is written with its required prefix (every named tag is reached by its prefix alone), its section of `docs/reference/TYPES.md` and the comment of its handler, the tags it reaches by name - the built-in tags of `pad:`, the kinds of a subsystem, the sequence types, the sequence actions, the pipe functions, the tags of `_common` - each linked to its page in the tags application, and live examples. Over the pages stand the indexes: by name, by required prefix, by group, a cheat sheet with the syntax of every type, and a search. It is the tags application's companion: that one has a page per tag, this one a page per kind of tag. edit

widgets The related page-design families of the engine, shown at work: the sections (`pad/subs/sections/`) - the blocks a landing page is built of -, the effects (`pad/subs/effects/`) - motion and decoration -, the themes (`pad/subs/themes/`) - the frame's colours swapped - and the palettes (`pad/subs/palettes/`) - colour scales for charts and anything else. The home page is a landing page built from sections and effects; the theme switcher, `{widget:themes/}`, stands in the bar of every page. A page per group shows every kind with its examples, a page per kind its examples alone - a theme's page with the contrast of each of its texts on each of its backgrounds and a button that puts every page in it, a palette's with its swatches and charts in it. Every example is its template beside what it renders, with the icons that take it to the WASM editor and the live application. The kinds are read from the engine - the files of each subsystem's `types/` and the comment at the top of each (`_lib/sections.php`) - so a kind added to the engine is here without a change to this application. edit
