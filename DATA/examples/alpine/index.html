● Behaviour in the markup

PAD writes the page.
Alpine wakes it up.

Alpine adds behaviour to HTML with a few attributes - and PAD writes that HTML. Both like braces, so the trick is to let each have its own: PAD hands Alpine its state as JSON with the ^ sigil, and longer components live in a file of www/.

Start with state from PHPBraces, data and requests
<divx-data="{^profile}"><!-- $profile from the page's PHP --><h2x-text="name"></h2><button @click="likes++"> ♥ <spanx-text="likes"></span></button></div>

The template holds no brace of Alpine's: the state is the JSON of a PHP array.

Alpine lives in the HTML PAD writes. Its state comes from the page's PHP as JSON in the attribute - the ^ sigil writes it - or as the argument of a component registered in a file of www/.

State from PHP

x-data="{^profile}": the page's PHP prepares an array, the ^ sigil writes it as JSON into the attribute, and Alpine makes it live - no braces of Alpine's in the template at all.

Components in a file

Tabs, an accordion and a dialog registered with Alpine.data in www/alpine/ - the template calls them by name and hands them PAD's data as the argument: x-data="accordion({^faq})".
