<p>
PAD parses on the fly (on demand) it searches for the first <b>}</b>, then it takes the first <b>{</b> before it, and analyses it to see if it is a PAD tag or a PAD variable.
</p>

<p>
In below example, the <code style="color: #000000"><b>{<font color="green"><font color="red">$</font>myVar</font>}</b></code> part is parsed first and executed.
</p>



 



   
    <table border="1" cellpadding="10" cellspacing="0">
  

  

      

      <tr>
        
        
          <td style="vertical-align:top"><pre><code style="color: #000000"><b>{<font color="blue">pad </font><font color="red">myOption=<font color="black">'</font><b><font color="black">{</font><font color="green"><font color="red"><font color="red">$</font></font>myVar</font><font color="black">}</font></b><font color="black">'</font><font color="black">,</font> <font color="red">$</font>xyz=789</font>}</b><br>   ....<br><b>{/<font color="blue">pad</font><font color="red"></font>}</b></code></pre></td>
        
        
      </tr>

    

  
    </table>
  






<p>
Lets assume <code style="color: #000000"><b>{<font color="green"><font color="red">$</font>myVar</font>}</b></code> has the value ABC, then the result will be below, and now the <b>{pad}</b> tag will be processed.
</p>



 



   
    <table border="1" cellpadding="10" cellspacing="0">
  

  

      

      <tr>
        
        
          <td style="vertical-align:top"><pre><code style="color: #000000"><b>{<font color="blue">pad </font><font color="red">myOption=<font color="black">'</font>ABC<font color="black">'</font><font color="black">,</font> <font color="red">$</font>xyz=789</font>}</b><br>   ....<br><b>{/<font color="blue">pad</font><font color="red"></font>}</b></code></pre></td>
        
        
      </tr>

    

  
    </table>
  






<p>
Without quotes around <code style="color: #000000"><b>{<font color="green"><font color="red">$</font>myVar</font>}</b></code> the result is the same while <code>$padProtectValues</code> is on, the default: a field written into a tag's parameters is spliced in as a quoted string (a plain number as the number), so its value stays the text ABC - with it off, the value is read as the bare word below. Only a bare word written in the template itself, as below, is read as the PHP constant of that name when one is defined, and as the text when not - a quoted value is always the text
</p>
