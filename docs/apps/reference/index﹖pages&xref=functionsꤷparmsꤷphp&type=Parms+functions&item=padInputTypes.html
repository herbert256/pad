App: manual - Page: pages/inputs

pages/inputs.pad 		Result 
{pad:meta title='Rich form fields'/}

<p>Beside <code>{pad:input}</code> and <code>{pad:textarea}</code> a form can hold
fields that do more: a slider, a row of stars, a switch, a month to choose a day from, a tag input,
a signature, a Markdown editor with its preview. There are {pad:echo php:count(padInputTypes())/} of
them - every kind is a file of <code>pad/subs/inputs/types/</code>, its script and style in
<code>www/assets/inputs/</code>, and the <a href="../inputs/">inputs</a> application shows them all,
each in a form that posts back.</p>

{common:example 'fragments/inputs_1'/}

<h2>Writing a field</h2>

<p>The input: type names the kind, <code>{input:slider 'volume'/}</code>. The
first parameter is the field's name, <code>label=</code> its label, and every other item the kind
does not take is an attribute of its field, as with <code>{pad:input}</code>:
<code>required</code>, <code>placeholder=</code>, <code>autocomplete=</code>.</p>

<h2>A real value, with or without a script</h2>

<p>Every kind writes a native field that a form posts as it is - a range, a number, a date, a
time, a colour, a checkbox, radio buttons, a text field - and its script, written once a page with
the CSP nonce, makes more of it: a month over the date, the times to pick from, swatches beside the
colour. Without the script the form works all the same; only the signature needs it.</p>

{common:example 'fragments/inputs_2'/}

<p>Some fields post a text of their own making: a tag input the words joined with a comma, the boxes
of a one-time code the code, a signature a PNG as a data URL - each in a field with the name, which
a form without the script fills by hand. Choices come from a list - <code>options=</code>,
<code>suggestions=</code> - from a store named by <code>data=</code>, or a line each between the
tags.</p>

{common:example 'fragments/inputs_3'/}

<h2>Refilled, with the message beside it</h2>

<p>The fields are fields of the <a href="?pages/forms">{pad:form}</a> around them: after a
post of that form they show what was posted, and the message <code>padValidate</code> left for them
after their frame, in the words of their label. <code>rules=</code> on a field is read from the
template before the page's PHP runs, as on <code>{pad:input}</code>, and <code>client</code>
on the form checks the same rules in the browser. Here the post is pretended in the PHP:</p>

{common:example 'fragments/inputs_4'/}

<ul>
  <li>The kinds: {pad:echo php:implode(', ', padInputTypes())/}.</li>
  <li>The colours are custom properties on <code>.pad-input</code> - <code>--pad-input-accent</code>,
  <code>--pad-input-line</code>, <code>--pad-input-star</code> and their like - with light and dark

<?php

  $tagAbout   = 'A form field with its label that refills from what its form sent and shows the error validation found for it.';
  $tagGroup   = 'forms';
  $tagForm    = 'single';

  $tagSyntax  = <<<'PAD'
{pad:input 'name'/}
{pad:input 'email', type='email', label='E-mail', value='', id='mail', placeholder='you@example.org', required/}
{pad:input 'terms', type='checkbox', label='I agree', value='yes', checked/}
{pad:input 'email', type='email', label='E-mail', rules='required|email'/}
{input:slider 'volume', label='Volume', min=0, max=100/}
PAD;

  $tagParms   = [
    'name' => 'The field name - required. <code>user[email]</code> and <code>tags[]</code> are found where PHP files them; the id is the name with what an id cannot hold made a dash.' ];

  $tagOptions = [
    'type'    => 'The input type, <code>text</code> by default: <code>email</code>, <code>number</code>, <code>checkbox</code>, <code>radio</code>, <code>hidden</code>, <code>password</code>, <code>file</code>, <code>submit</code> ...',
    'label'   => 'A <code>&lt;label for&gt;</code> before the field - after a checkbox or radio - and the word its error message uses.',
    'value'   => 'The value before anything was sent; for a checkbox or radio its own value (<code>on</code> by default).',
    'id'      => 'The id, by default the name.',
    'checked' => 'Bare option: a checkbox or radio is checked before a post.',
    'rules'   => 'The field\'s rules - <code>required|email|max:80</code> - read from the page\'s own template and checked before its PHP runs. Only in a named <code>{pad:form}</code> of the page itself.' ];

{pad:ignore}
<p><code>{pad:input 'email', type='email', label='E-mail'/}</code> writes a
<code><label for></code> and an <code><input></code> with the name and an id - the
name with every character an id cannot hold made a dash, so <code>user[email]</code> gets the
id <code>user-email</code>. The name is required: a field without one is an error under the
strict check.</p>

<p>The tag takes <code>type</code>, <code>label</code>, <code>value</code>, <code>id</code>,
<code>checked</code> and <code>rules</code> itself; every other item is an attribute of the
input, written as <a href="?tag/attrs">{pad:attrs}</a> writes it - a bare word such as
<code>required</code> is a bare attribute, a false value leaves the attribute out.</p>

<p>Before a post a field shows <code>value=</code>. After a post of its own
<a href="?tag/form">{pad:form}</a> it shows the posted value, escaped, found where PHP files the
name (<code>user[email]</code> is <code>$_POST['user']['email']</code>). A checkbox or radio is
checked when the posted value is its own value - before a post when <code>checked</code> is
given - and its label comes after it. A password or file field is never refilled; a submit,
button, reset or image input has no label and no error.</p>

<p>When <code>padValidate</code> - or the field's own <code>rules=</code> - found something
wrong, the message follows the field in <code><span class="error" id="email-error"></code>,
worded with the field's label, and the field gets <code>aria-invalid="true"</code> and
<code>aria-describedby</code>, so a screen reader says the message with the field. A file
field shows why <code>padUpload</code> refused its file the same way. Outside a
<code>{pad:form}</code> the tag still writes the field, but it never refills.</p>

<p>The input: type writes the rich fields of <code>pad/subs/inputs/types/</code> the same way - named,
labelled, refilled, with their message and their <code>rules=</code> - each a native field its
script makes more of: <code>{input:slider 'volume', label='Volume'/}</code>. The prefix is required. The kinds are the files there:
{/pad:ignore}{pad:echo php:implode(', ', padInputTypes())/}{pad:ignore}; the
<a href="../inputs/">inputs</a> application shows each one in a form that posts back.</p>
{/pad:ignore}
