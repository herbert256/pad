App: regression/main - Page: index
PHP
index.php 		HTML
index.pad 		Result 
<?php

  // The overview the application opens on: one line per suite, each with the totals of
  // its last run. A page load never runs anything; each line links to the page where its
  // own Test lives, and Test here runs all eight suites.

  if ( isset ( $test ) ) {

    // Like the Build: a run starts from clean dumps and temp, so what stands afterwards
    // is what this run produced - ci calls this page, and without the wipe every green
    // run left another round of by-design dumps standing.

    padDeleteDataDir ( DATA . 'dumps' );
    padDeleteDataDir ( DATA . 'temp'  );

    getRegression ();

    padRedirect ( $padPage );

  }

  $rows = [];

  foreach ( array_keys ( getSuites () ) as $suite ) {

    $result = getSuiteLast ( $suite );

    $rows [] = [
      'name'   => ucfirst ( $suite ),
      'link'   => "?$suite/index",
      'result' => $result ['summary'],
      'ran'    => $result ['when'] ? date ( 'Y-m-d H:i', $result ['when'] ) : 'never',
      'status' => getSuiteVerdict ( $result )
    ];

  }

  $title = 'Regression';

?>
 
<p>
  The regression tests of the PAD framework. Every suite fetches real pages over HTTP -
  Pages from regression/pages, which runs with _common switched off, Common from regression/common,
  the pages that use it, and Framework from regression/framework, where every engine case is a page
  of its own; Errors from regression/errors, the tests that fail on purpose; and Regression,
  Sequence, Manual and Other fetch every page of the remaining applications and compare each
  with the prediction of the same name in their store. Each line reports the last run - Test
  on a suite's own page reruns it.
</p>

<table border="1" cellpadding="4" cellspacing="0">
  <tr><th>suite</th><th>last run</th><th>ran</th><th>status</th></tr>
  {rows}
    <tr>
      <td><a href="{$link}">{$name}</a></td>
      <td>{$result}</td>
      <td>{$ran}</td>
      <td>{$status}</td>
    </tr>
  {/rows}
</table>

App: regression/pages - Page: callback
PHP
callback.php 		HTML
callback.pad 		Result 
<?php

  // The row phase of a streaming callback reads the occurrence's fields as plain PHP variables.
  // A case rendered inside another request cannot show that: those fields are the nested
  // pass's locals rather than globals, so the callback never sees them. In a real request it
  // does, which is what the manual's staff example relies on and what this page pins.

  $rows = [
    [ 'n' => 1 ],
    [ 'n' => 2 ],
    [ 'n' => 3 ]
  ];

?>
 
{rows callback='stream.php'}{$n},{/rows}total={$sum}
