Tags/Navigation/jsonld:*

{jsonld:*}

Writes the structured data of a page - a <script type="application/ld+json"> holding a Schema.org object - for 17 kinds, from an article to a product, each field mapped by name, so nothing else of a row reaches the page.

Navigation Single tags

Syntax 

{jsonld:kind data='rows'/}
{jsonld:article headline=$title, author=$author, published=$date/}
{jsonld:article data='post', url=$url/}
{jsonld:faq data='questions'/}
{jsonld:breadcrumb/}
{jsonld:website name='Shop', search='?search&q='/}

Parameters

kind after colon
The kind, a file of pad/subs/jsonld/types/: article, breadcrumb, business, course, event, faq, itemlist, job, organization, person, product, profile, recipe, restaurant, software, video, website. The jsonld: prefix selects it - {jsonld:article .../}; a kind is never reached bare.

Options

data
The row or rows of the fields: a {pad:data} store, the page's array, a field holding a list or a _data file - one row of fields, or rows, which a kind of one object writes as a @graph and faq, breadcrumb and itemlist as their items. The handling options work on them.
id
The object's @id, an address made absolute - id='#org' - or an IRI of another scheme.

Description

{jsonld:article} writes the structured data of a page: one <script type="application/ld+json"> holding a Schema.org object, which search engines read for a rich result - an article's headline and date, an event's place and tickets, a product's price, the questions of an FAQ, the trail of a breadcrumb. Every kind is a file of pad/subs/jsonld/types/ that maps its fields onto Schema.org by name; the files there are the kinds there are.

The fields come from the row or rows data= names and from options of their names, which win over the row's. Only what a kind maps is written - never a row whole - so a password, a cost price or an e-mail address of the row cannot reach the page. An empty field is left out; a required one missing, a date that is none, a price written with a comma and an option the kind does not take are errors under the strict check.

Addresses are made absolute - relative to the application's address, as an <img> of its pages finds its file - and dates are ISO 8601, or written so from what PHP's date_parse reads in full. The JSON is safe in its element: a </script> in a value is written \u003C/script\u003E, and the braces of a value stay text. The script is a data block the browser never runs, so it needs no CSP nonce. The examples show it with the html pipe; on a page the tag alone writes it, unseen. In a page's PHP, padJsonLd ( 'article', $post ) answers the same object as an array.

Examples

An article from its options

The script the tag writes, made visible by the html pipe - a relative image made absolute, the date as ISO 8601.

Templateexamples/jsonld/1-article.pad 
<pre style="white-space:pre-wrap">{jsonld:article headline='Pages that drive themselves', author='Ann Smith', published='1 November 2026', image='cover.jpg' | html/}</pre>
Resultopen alone 
<script type="application/ld+json">{"@context":"https://schema.org","@type":"Article","headline":"Pages that drive themselves","image":"http://localhost/pad/tags/cover.jpg","author":{"@type":"Person","name":"Ann Smith"},"datePublished":"2026-11-01"}</script>

A row, and nothing else of it

Only the fields the product maps are written - the stock, the cost price and the supplier stay out; an option adds what the row lacks.

Templateexamples/jsonld/2-row.pad 
<pre style="white-space:pre-wrap">{jsonld:product data='product', availability='InStock' | html/}</pre>
PHPexamples/jsonld/2-row.php 
<?php

  $product = [ 'name' => 'Aurora kettle', 'sku' => 'AK-1', 'brand' => 'Aurora', 'price' => '39.95',
               'currency' => 'EUR', 'stock' => 12, 'cost' => '11.20', 'supplier' => 'Kettles Ltd' ];

?>
Resultopen alone 
<script type="application/ld+json">{"@context":"https://schema.org","@type":"Product","name":"Aurora kettle","sku":"AK-1","brand":{"@type":"Brand","name":"Aurora"},"offers":{"@type":"Offer","price":"39.95","priceCurrency":"EUR","availability":"https://schema.org/InStock"}}</script>

The questions of a page

Rows of question and answer, an FAQPage of them - the same rows can show the questions on the page.

Templateexamples/jsonld/3-faq.pad 
{pad:data 'questions'}
[ { "question": "Is it free?",              "answer": "Yes, under the GPL." },
  { "question": "Does it need a database?", "answer": "No - SQLite, MySQL or none." } ]
{/pad:data}
<dl>{data:questions}<dt>{$question}</dt><dd>{$answer}</dd>{/data:questions}</dl>
<pre style="white-space:pre-wrap">{jsonld:faq data='questions' | html/}</pre>
Resultopen alone
Is it free?
Yes, under the GPL.
Does it need a database?
No - SQLite, MySQL or none. 
<script type="application/ld+json">{"@context":"https://schema.org","@type":"FAQPage","mainEntity":[{"@type":"Question","name":"Is it free?","acceptedAnswer":{"@type":"Answer","text":"Yes, under the GPL."}},{"@type":"Question","name":"Does it need a database?","acceptedAnswer":{"@type":"Answer","text":"No - SQLite, MySQL or none."}}]}</script>

The site and its search

The address of the search with the term at its end - the placeholder search_term_string is written after it, its braces text.

Templateexamples/jsonld/4-website.pad 
<pre style="white-space:pre-wrap">{jsonld:website name='PAD', search='?search&q=' | html/}</pre>
Resultopen alone 
<script type="application/ld+json">{"@context":"https://schema.org","@type":"WebSite","name":"PAD","url":"http://localhost/pad/tags/","potentialAction":{"@type":"SearchAction","target":{"@type":"EntryPoint","urlTemplate":"http://localhost/pad/tags/?search&q={search_term_string}"},"query-input":"required name=search_term_string"}}</script>
