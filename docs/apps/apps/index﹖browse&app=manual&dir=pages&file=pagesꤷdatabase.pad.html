pages/database.pad 

{meta title='Database'}

<p>PAD talks to the application's database - configured in
<code>_config/config.php</code> - in two places: a page's PHP half calls
<code>db()</code>, and the template side has tags that ask directly. The examples here read
the <code>staff</code> table of the demo database - four people of its own, not the five of
the <code>staff.xml</code> file the manual's other examples use.</p>

<h2>db() from the page's PHP</h2>

<p>The first word of the statement says what shape comes back:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>word</th><th>answers with</th></tr>
  <tr><td><code>field</code></td><td>one value</td></tr>
  <tr><td><code>record</code></td><td>one row, as an array of fields</td></tr>
  <tr><td><code>array</code></td><td>all rows, ready for a tag to iterate</td></tr>
  <tr><td><code>check</code></td><td>whether a row exists - written <code>check table where ...</code>, with no column list</td></tr>
  <tr><td><code>insert</code> / <code>update</code></td><td>writes, taking their values from an array</td></tr>
</table>

<h2>Asking from the template</h2>

<p>The same questions can be asked where the answer is used: a <code>{field}</code>
tag drops one value into the page, and an <code>{array}</code> pair iterates its
query on the spot. Inside the quotes a comma is part of the query, so a column list is
written as it is - <code>{array "name, phone from staff"}</code> - and the example
keeps to <code>*</code>:</p>

{example 'fragments/database_3'}

<p>A <code>{record}</code> pair does the same for a single row.</p>

<h2>Named queries - a .sql file in _data</h2>

<p>A query can also live in a file of its own. <code>_data/staffByPhone.sql</code> holds:</p>

-- The staff whose phone number matches a pattern, at most so many of them.
select name, phone
  from staff
 where phone like {$pattern}
 order by name
 limit {$max}

<p>and the tag <code>{staffByPhone}</code> runs it. The file is never run as PAD:
each <code>{$name}</code> is bound as a placeholder - an option of the tag first,
then a variable of the page - so a value can never become SQL. The statement must read.</p>

{example 'fragments/database_4'}

<h2>Declared tables - the select subsystem</h2>

<p>For an application built around its tables there is a third way: declare the tables once
in the configuration and every one of them is a tag, relations and automatic joins
included - the <code>select:</code> prefix. The
<a href="{$padHost}classicModels/">classicModels application</a> is that subsystem
demonstrated over a whole database, and <code>docs/DATABASE.md</code> in the repository is
the reference.</p>
