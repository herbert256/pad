<p><code>{while condition}</code> tests its condition and, while it holds, renders its content
and tests again. Something inside the content has to change what the condition reads - an
<a href="?tag/increment">{increment}</a>, a <a href="?tag/set">{set}</a> - or the loop never
ends. The variables it counts with are ordinary globals, so their last value is still there
after the loop.</p>

<p>Written on the closing tag - <code>{while} ... {/while $i lt 10}</code> - the condition is
tested after each pass instead of before it: a do-while, whose content renders once even when
the condition is false from the start.</p>

<p><a href="?tag/until">{until}</a> is the same loop with the test turned round: it runs while
the condition is false. <a href="?tag/break">{break}</a> leaves the loop at once,
<a href="?tag/cease">{cease}</a> lets the current pass finish and asks for no further one, and
<a href="?tag/continue">{continue}</a> skips the rest of the current pass.</p>

<p>A loop whose condition never turns is stopped after 10000 passes (the sequences' ceiling,
<code>$padSeqDefaultTries</code>) instead of running until PHP's time limit; under the strict
syntax check that is an error naming the loop. A <code>{while}</code> without a condition or
without its closing tag is an error as well. To repeat over data or a fixed range, a data tag
or <a href="?tag/sequence">{sequence '1..10'}</a> is simpler.</p>
