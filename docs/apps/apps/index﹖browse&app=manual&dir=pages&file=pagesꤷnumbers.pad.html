pages/numbers.pad 

{meta title='Number helpers'}

<p>Numbers written for people from a page's PHP: grouped with the locale's marks, shortened
to 1.5K or 1.5 million, as a place, a percentage or a file size - and kept between bounds.
These are the functions of Laravel's <code>Number</code> class, as plain functions. The
<code>abbreviate</code> and <code>ordinal</code> pipes do the same in a template.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>function</th><th>what it does</th></tr>
  <tr><td><code>padNumberFormat ( $number, $decimals, $locale )</code></td><td>the number grouped, with exactly so many decimals, the locale's way</td></tr>
  <tr><td><code>padNumberPercentage ( $number, $precision )</code></td><td>25 as 25%, 25.55 with a precision of 1 as 25.6%, the locale's way</td></tr>
  <tr><td><code>padNumberAbbreviate ( $number, $precision )</code></td><td>1500 as 2K, or 1.5K with a precision of 1 - K, M, B, T, Q</td></tr>
  <tr><td><code>padNumberForHumans ( $number, $precision )</code></td><td>1500000 as 2 million, or 1.5 million</td></tr>
  <tr><td><code>padNumberFileSize ( $bytes, $precision )</code></td><td>1536 as 2 KB, or 1.5 KB - what the <code>bytes</code> pipe answers</td></tr>
  <tr><td><code>padNumberOrdinal ( $number )</code></td><td>1st, 2nd, 3rd, 4th, 11th, 21st, 112th</td></tr>
  <tr><td><code>padNumberClamp ( $number, $min, $max )</code></td><td>the number, or the bound it went past</td></tr>
</table>

<h2>Formatting</h2>

<p><code>padNumberFormat</code> writes exactly <code>$decimals</code> decimals, with the
thousands grouped and the decimal mark of the locale: the request's
<code>$padLocale</code>, or the one given. <code>padNumberPercentage</code> takes a share
already counted in hundreds - 25 is 25% - and writes it the locale's way too. Half is
rounded up, so 2.5 is 3. PHP's intl extension does the writing when it is there; without
it the number is written the plain <code>number_format</code> way.</p>

{example 'fragments/numbers_1'}

<h2>Short and readable</h2>

<p><code>padNumberAbbreviate</code> and <code>padNumberForHumans</code> write a large number
in thousands, millions, billions, trillions or quadrillions, and
<code>padNumberFileSize</code> a byte count in units of 1024. The precision is the most
decimals written, the trailing zeros dropped: 1000 with a precision of 1 is 1K. The unit is
chosen on the number as it will be written, so 999999 is 1M, not 1000K. Below 1000 the
number has no unit, and a size below 1024 is in B. These write English, with a point before
the decimals.</p>

{example 'fragments/numbers_2'}

<h2>Places and bounds</h2>

<p><code>padNumberOrdinal</code> writes the English place of a whole number - 11th, 12th
and 13th take th, as do 111th to 113th. <code>padNumberClamp</code> keeps a number between a
minimum and a maximum: a page number from the address that has to stay within the pages
there are.</p>

{example 'fragments/numbers_3'}

<h2>In a template</h2>

<p>The <code>abbreviate</code> pipe is <code>padNumberAbbreviate</code> -
<code>{$views | abbreviate}</code>, <code>{$views | abbreviate(1)}</code> -
and the <code>ordinal</code> pipe is <code>padNumberOrdinal</code>. A value that is not a
number goes through them unchanged, as it does through <code>bytes</code>.</p>

{example 'fragments/numbers_4'}

<h2>Nothing and mistakes</h2>

<p>NULL, FALSE and empty text are nothing to write: every function answers an empty string
for them, <code>padNumberClamp</code> NULL. A value that is no number, a negative precision,
a fraction handed to <code>padNumberOrdinal</code>, a locale intl does not know and a
minimum above the maximum are reported as errors that name the function.</p>
