Tags/Charts and codes/pad:diagram

{pad:diagram}

Draws a diagram from Mermaid-style lines of text, laid out on the server as inline SVG - 9 kinds, from flowcharts and sequence diagrams to state machines, class and entity-relationship diagrams, mind maps, trees, user journeys and commit graphs.

Charts and codes Tag pairs

Syntax 

{diagram direction='LR', edges='curved', title='text'} A[Start] --> B{Ready?} {/diagram}
{diagram type='sequence', title='text'} Shop ->> Bank: Charge {/diagram}
{diagram:state} [*] --> Idle {/diagram:state}
{diagram:class} Animal <|-- Duck {/diagram:class}
{diagram:er} CUSTOMER ||--o{ ORDER : places {/diagram:er}
{mindmap} Root ... {/mindmap}
{diagram:tree direction='LR'} Root ... {/diagram:tree}
{journey} section Morning ... {/journey}
{gitgraph} commit ... {/gitgraph}

Options

type
The kind, a file of pad/diagrams/types/: class, er, flowchart, gitgraph, journey, mindmap, sequence, state, tree - flowchart unless it says otherwise. The diagram type names it as well, {diagram:state}, and so does the bare name, {state}, when nothing else has it; sequence and tree are tags of their own, so those are {diagram:sequence} and {diagram:tree}. A first line written the Mermaid way - sequenceDiagram, stateDiagram-v2, classDiagram, erDiagram, gitGraph - names the kind too.
direction
flowchart, state, class, er and tree: TB (default), BT, LR or RL - else a first line graph LR in a flowchart, or a line direction LR in a state, class or entity-relationship diagram.
edges
flowchart, state, class and er: how the edges run - orthogonal (default, rounded turns), straight or curved.
title
The accessible name, by default the kind's - Flowchart, Sequence diagram, State diagram ... - and for a journey its title line.

Description

{diagram} turns a few lines of text in its content into a picture, written the way Mermaid writes them, and lays it out on the server (pad/diagrams/) as inline SVG - no JavaScript in the browser, and the same lines always draw the same picture. The content is taken as it stands before the level walks it, so the braces of a decision like B{Paid?} or a class class A { need no ignore. Every kind is a file of pad/diagrams/types/; each is written three ways - {diagram type='state'}, {diagram:state} and the bare {state} when nothing else has the name.

Flowcharts

A line is a chain of nodes and edges. Nodes: A[Box], B(Rounded), C([Stadium]), D{Decision?}, E((Circle)), F[(Database)], G{{Hexagon}} - a node is named once with its text and later by its id alone. Edges: --> (arrow), --- (line), -.-> and -.- (dashed), ==> and === (thick), a label as -->|text| or -- text -->; & joins several nodes on one side (A & B --> C) and %% starts a comment. The layout is layered, with as few crossings as it can find; direction turns it, edges chooses how the lines run.

Sequence diagrams

With type='sequence' or {diagram:sequence} - bare, {sequence} is the sequence tag: participant A as Alice, actor U, messages ->> (arrow), -->> (dashed), -> and --> (no head), -x (cross), -) (open), Note left of A: text (also right of and over A,B), the frames loop, alt / else, opt, par / and, critical and break closed by end, and autonumber.

State, class and entity-relationship diagrams

Laid out in layers as a flowchart is. A state diagram: [*] --> A the start, A --> [*] the end, A --> B : label, state "Long name" as A, A : a line of description, state C <<choice>>, <<fork>> and <<join>>. A class diagram: class A { +field; +method() } a member a line ($ static, * abstract, List~int~ generic), A : +member, <<interface>> A, and A <|-- B (inherits), A <|.. B (implements), A *-- B (made of), A o-- B (holds), A --> B, A ..> B (depends on), with multiplicities A "1" --> "*" B. An entity-relationship diagram: A ||--o{ B : label - || exactly one, |o zero or one, }| one or more, }o zero or more, mirrored on the right, .. not identifying - and A { type name PK "comment" }.

Mind maps, trees, journeys and commit graphs

A mind map and a tree read their hierarchy from the indentation - the mind map's shapes by their brackets, [square], (rounded), ((circle)), {{hexagon}}, )cloud(, ))bang((; the tree is {diagram:tree}, as {tree} is the tree tag. A journey: title text, section text and a step a line, Make tea: 5: Me, Cat with its score from 1 to 5. A commit graph: commit id: "x" tag: "v1" type: HIGHLIGHT, branch name, checkout name, merge name and cherry-pick id: "x".

The SVG has role="img", a <title> and a <desc> that says every edge, message, relation or step. A diagram without nodes answers nothing, so its @else@ shows; a line it cannot read, or an unknown type, direction or edges, is an error under the strict check.

Examples

A flowchart

Nodes of several shapes, labelled edges and a dashed loop back.

Templateexamples/diagram/1-flowchart.pad 
{diagram title='Handling an order'}
  A([Order placed]) --> B{In stock?}
  B -->|no| C[Order from supplier]
  C -.->|delivered| B
  B -->|yes| D[Take payment] --> E[(Orders database)] --> F((Shipped))
{/diagram}
Resultopen alone

Left to right, curved

direction=LR and edges=curved; & fans one node out to several.

Templateexamples/diagram/2-lr.pad 
{diagram direction='LR', edges='curved', title='Deploy pipeline'}
  code([Commit]) --> build[Build]
  build --> unit[Tests] & lint[Lint]
  unit & lint --> gate{Green?}
  gate -->|yes| live((Live))
  gate -.->|no| code
{/diagram}
Resultopen alone

A sequence diagram

Participants, numbered messages, dashed replies, an alt frame and a note.

Templateexamples/diagram/3-sequence.pad 
{diagram type='sequence', title='Paying an order'}
  participant S as Shop
  participant B as Bank
  autonumber
  S ->> B: Charge 42.00
  alt Enough funds
    B -->> S: Approved
  else Declined
    B -->> S: Refused
  end
  Note over S,B: The card number never reaches the shop
{/diagram}
Resultopen alone

A state diagram

The start and the end, labelled transitions, a choice and a line of description.

Templateexamples/diagram/4-state.pad 
{diagram:state title='A ticket'}
  [*] --> Open
  Open --> Working : take
  Working : the clock runs
  state Done <<choice>>
  Working --> Done : finish
  Done --> Closed : accepted
  Done --> Working : rejected
  Closed --> [*]
{/diagram:state}
Resultopen alone

A class diagram

Classes with fields and methods, inheritance, composition and an association with its multiplicities.

Templateexamples/diagram/5-class.pad 
{diagram:class title='An order'}
  class Order {
    +Date placed
    +total() Money
  }
  class Line {
    +int quantity
  }
  Customer "1" --> "*" Order : places
  Order *-- "1..*" Line
  Line --> Product
{/diagram:class}
Resultopen alone

An entity-relationship diagram

Entities as tables of their attributes, the feet of a crow for how many.

Templateexamples/diagram/6-er.pad 
{diagram:er direction='LR', title='A shop'}
  CUSTOMER ||--o{ ORDER : places
  ORDER ||--|{ LINE-ITEM : contains
  PRODUCT ||--o{ LINE-ITEM : "is in"
  ORDER {
    int id PK
    int customer FK
    date placed
  }
{/diagram:er}
Resultopen alone

A mind map and a tree

Both read the hierarchy from the indentation; the tree tag keeps the bare name tree, so the tree diagram is diagram:tree.

Templateexamples/diagram/7-hierarchies.pad 
{diagram type='mindmap', title='A trip'}
  Trip((Trip))
    Packing
      Passport
      Charger
    Travel
      Train
      Ferry
    Plans
      Museum
      Beach
{/diagram}
{diagram:tree title='The company'}
  Board
    Sales
      North
      South
    Engineering
    Finance
{/diagram:tree}
Resultopen alone

A user journey

Steps in sections, a face at the height of each score and a dot for every person.

Templateexamples/diagram/8-journey.pad 
{journey}
  title A day at the office
  section Morning
    Make tea: 5: Me
    Read the mail: 2: Me, Cat
  section Afternoon
    Fix the build: 1: Me, Team
    Go home: 5: Me
{/journey}
Resultopen alone

A commit graph

Branches as lanes, a merge with its tag, a highlighted and a reverted commit.

Templateexamples/diagram/9-gitgraph.pad 
{gitgraph}
  commit id: "Init"
  branch develop
  commit id: "Parser" type: HIGHLIGHT
  checkout main
  commit id: "Oops" type: REVERSE
  merge develop tag: "v1.0"
{/gitgraph}
