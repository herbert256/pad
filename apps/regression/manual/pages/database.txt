<h1>Database</h1>

<p>PAD talks to the application's database - configured in
<code>_config/config.php</code> - in two places: a page's PHP half calls
<code>db()</code>, and the template side has tags that ask directly. The examples here read
the <code>staff</code> table of the demo database, the same people this manual's
<code>staff.xml</code> file holds.</p>

<h2>db() from the page's PHP</h2>

<p>The first word of the statement says what shape comes back:</p>

</table>

<h2>Asking from the template</h2>

<p>The same questions can be asked where the answer is used: a <code>{field}</code>
tag drops one value into the page, and an <code>{array}</code> pair iterates its
query on the spot. A comma inside a tag parameter would read as the next parameter, so a
column list is written with <code>&amp;comma;</code> - or the query keeps to
<code>*</code>:</p>

<h2>Declared tables - the select subsystem</h2>

<p>For an application built around its tables there is a third way: declare the tables once
in the configuration and every one of them is a tag, relations and automatic joins
included - the <code>select:</code> prefix. The
<a href="http://localhost/pad/classicModels/">classicModels application</a> is that subsystem
demonstrated over a whole database, and <code>docs/DATABASE.md</code> in the repository is
the reference.</p>
