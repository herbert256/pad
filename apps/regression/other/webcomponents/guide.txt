  <h1>Web components on a PAD page</h1>
  <p class="lede">
    Custom elements and shadow DOM are the browser's own components. PAD writes them with their
    shadow root already in place - declarative shadow DOM - and a small module adds behaviour.
  </p>
</header>

<h2>1. A PAD custom tag writes the element</h2>

   {shadow} writes its shadow root as a <code>&lt;template shadowrootmode="open"&gt;</code> - with the
   stylesheet inlined, since a shadow root takes no styles from the page and a <code>&lt;style&gt;</code> in a
   template would have its braces read as PAD tags:</p>

<h2>4. Data, posts and forms</h2>
<ul>
  <li>Attributes carry values (<code>value="{$mine}"</code>) and JSON (<code>items="{^items}"</code>);
      CSS can style by an attribute before any script runs: <code>:host([value="3"])</code>.</li>
  <li>A post sends the session's CSRF token in the <code>X-CSRF-Token</code> header, read from
      <code>&lt;meta name="csrf-token"&gt;</code>; the page answers the JSON of <code>$padExpose</code>.</li>
  <li>A form-associated element - <code>static formAssociated = true</code> and
      <code>ElementInternals.setFormValue</code> - posts its value with a {form} like an
      <code>&lt;input&gt;</code>, and <code>padValidate</code> checks it on the server.</li>
  <li>A library works the same: Lit reads PAD's JSON from an attribute into a property.</li>
</ul>
