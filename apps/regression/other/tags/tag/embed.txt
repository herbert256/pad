<p><code>{embed}</code> puts a video, a sound, a map, a pen or a document of another site in
the page without the page asking that site for anything before the visitor does. What is
written first is a facade: a poster drawn for the kind of thing it is - or a picture of the
application's own with <code>poster=</code> - the title, the name of the site it comes from and
a button. Pressing the button puts the provider's frame in its place, by a small script
written once per page with the CSP nonce, and moves the focus into it. Without script the
button is hidden and a link to the address on its own site stands in its place.</p>

<p>A provider is a file of <code>pad/subs/embeds/types/</code> - the files there are the providers
there are, and a provider is added by adding its file. It says the addresses it knows, the
site its frame comes from and what the frame is given. <code>{embed 'address'}</code> asks each
of them, the ones that know their host first; the embed type names one -
<code>{embed:vimeo '76979871'}</code>, or bare, <code>{vimeo '76979871'}</code>, when no tag,
store or field has the name - and then reads a bare id of that provider as well. A file of
the application - a video, a sound, a PDF - is an element of its own that loads nothing
before it is played, or a frame of the application loaded lazily; nothing about it is
another site's.</p>

<p>The frames need the providers' origins in a Content Security Policy's
<code>frame-src</code>: <code>padEmbedSources()</code> lists the ones the files name -
<code>https://www.youtube-nocookie.com https://player.vimeo.com ...</code> - and a PeerTube
instance is added by hand. <code>thumbnail</code> shows YouTube's own picture as the poster,
which asks Google's image server for it before the click, and needs <code>img-src
https://i.ytimg.com</code>. For the video sites alone, with the poster of the site,
<a href="?tag/video">{video}</a> is the older form.</p>
