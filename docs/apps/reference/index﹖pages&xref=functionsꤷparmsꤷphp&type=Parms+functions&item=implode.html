App: manual - Page: pages/forms

pages/forms.pad 		Result 
{pad:meta title='Forms'/}

<p>{app:tag 'form'/}, {app:tag 'input'/} and {app:tag 'textarea'/} write the fields of a form. When the
form comes back with mistakes in it, each field shows again what was typed - escaped - and
the message for its mistake beside it. <code>padValidate</code> in the page's PHP finds the
mistakes.</p>

{common:example 'fragments/forms_1'/}

<ul>
  <li>{app:tag 'form'/} posts back to the page and carries the session's CSRF token (see
  {app:manual 'csrf_protection'/}) and its name: <code>padPosted ( 'contact' )</code> is true when
  this form came back, so a page with two forms knows which one did.</li>
  <li>{app:tag 'input'/} and {app:tag 'textarea'/} take the field name first; <code>label=</code> writes a
  label tied to the field, <code>value=</code> the value before anything was posted, and every
  other item is an attribute of the field, as {app:tag 'attrs'/} writes it - <code>required</code>,
  <code>rows=6</code>, <code>placeholder='...'</code>.</li>
  <li>A checkbox or radio is checked when the posted value is its own value; a password or
  file field is never refilled.</li>
</ul>

<h2>Validation</h2>

<p><code>padValidate ( $rules )</code> checks the posted values and answers one message per
field that breaks a rule, keyed by the field - empty when all is well. A second argument
checks other data; a third replaces messages, per field (<code>'email'</code>) or per field
and rule (<code>'email.required'</code>):</p>

{common:example 'fragments/forms_2'/}

<p>A rule takes its argument after a colon: <code>min:n</code>, <code>max:n</code> and
<code>between:a,b</code> are a length, or a value with <code>numeric</code> or
<code>integer</code>; <code>in:a,b,c</code> a list, <code>regex:/.../</code> a pattern,
<code>same:other_field</code> another field, <code>digits:4</code> a number of digits. An empty
field is checked for <code>required</code> and <code>accepted</code> only. Every rule is a file of
<code>pad/subs/rules/types/</code> - its check in the browser beside it in <code>www/assets/rules/</code> -
and these are the {pad:echo php:count(padRuleTypes())/} there are:
{pad:echo php:implode(', ', padRuleTypes())/}. A rule name nothing knows is an error.</p>

<h2>After a failed post</h2>

<p>The fields of the form that came back show the message beside them, in the words of their
own label, tied to the field with <code>aria-invalid</code> and
<code>aria-describedby</code> so a screen reader reads them together. Here the post is
pretended in the PHP, the way a visitor's would arrive:</p>

{common:example 'fragments/forms_3'/}

<p>After a post that passes, store it and send the visitor on with <code>padRedirect ()</code>:
a refresh of the page they land on does not post a second time.</p>

<h2>Rules in the template</h2>

<p>The rules can stand on the fields themselves: <code>rules='required|email'</code> on an
{app:tag 'input'/} or a {app:tag 'textarea'/}. They are read from the page's template before its PHP
runs, and a post of the form is checked against them there - <code>padPosted ( 'contact' )</code>
is true only for a post that kept them, so the PHP acts on a good post alone. A post that broke
one renders the form again, refilled, with the messages beside the fields and the form's
<code>error=</code> above them (<code>error</code> alone says "Please correct the errors
below."):</p>

{common:example 'fragments/forms_4', skipResult/}

<ul>
  <li>Only what is written out counts: quoted rules, on a field with a quoted name, in a
  {app:tag 'form'/} with a name that posts back to its own page. Rules on a field in a snippet, a
  custom tag, a {app:tag 'page'/} or a layout, rules made from a variable, rules in a form with
  <code>action=</code> or <code>method='get'</code> and rules on a file field are errors -
  nothing would check them.</li>
  <li>Every field of the posted form that has rules is checked, also one in an {app:tag 'if'/}
  branch that did not render. A field that is there only sometimes keeps its check in the
  PHP: <code>padValidate</code> adds its messages to those of the template.</li>
  <li><code>padFormFailed ( 'contact' )</code> is true when the form came back and broke its
  rules.</li>
</ul>

<p>Beside <code>{pad:input}</code> and <code>{pad:textarea}</code> a form can hold
fields that do more: a slider, a row of stars, a switch, a month to choose a day from, a tag input,
a signature, a Markdown editor with its preview. There are {pad:echo php:count(padInputTypes())/} of
them - every kind is a file of <code>pad/subs/inputs/types/</code>, its script and style in

each in a form that posts back.</p>

{common:example 'fragments/inputs_1'/}

<h2>Writing a field</h2>

<p>The input: type names the kind, <code>{input:slider 'volume'/}</code>. The
first parameter is the field's name, <code>label=</code> its label, and every other item the kind
does not take is an attribute of its field, as with <code>{pad:input}</code>:
<code>required</code>, <code>placeholder=</code>, <code>autocomplete=</code>.</p>

<h2>A real value, with or without a script</h2>

<p>Every kind writes a native field that a form posts as it is - a range, a number, a date, a
time, a colour, a checkbox, radio buttons, a text field - and its script, written once a page with
the CSP nonce, makes more of it: a month over the date, the times to pick from, swatches beside the
colour. Without the script the form works all the same; only the signature needs it.</p>

{common:example 'fragments/inputs_2'/}

<p>Some fields post a text of their own making: a tag input the words joined with a comma, the boxes
of a one-time code the code, a signature a PNG as a data URL - each in a field with the name, which
a form without the script fills by hand. Choices come from a list - <code>options=</code>,
<code>suggestions=</code> - from a store named by <code>data=</code>, or a line each between the
tags.</p>

{common:example 'fragments/inputs_3'/}

<h2>Refilled, with the message beside it</h2>

<p>The fields are fields of the <a href="?pages/forms">{pad:form}</a> around them: after a
post of that form they show what was posted, and the message <code>padValidate</code> left for them
after their frame, in the words of their label. <code>rules=</code> on a field is read from the
template before the page's PHP runs, as on <code>{pad:input}</code>, and <code>client</code>
on the form checks the same rules in the browser. Here the post is pretended in the PHP:</p>

{common:example 'fragments/inputs_4'/}

<ul>
  <li>The kinds: {pad:echo php:implode(', ', padInputTypes())/}.</li>
  <li>The colours are custom properties on <code>.pad-input</code> - <code>--pad-input-accent</code>,
  <code>--pad-input-line</code>, <code>--pad-input-star</code> and their like - with light and dark
  defaults.</li>
  <li>A password is never refilled, a file field cannot be, and the rules of a drop zone are
  <code>padUpload</code>'s.</li>
</ul>

<p>{pad:ai} puts the answer of a language model in the page. What stands between the tags
renders first - fields, loops, anything - and what it rendered is the prompt; the answer comes back
as text. It is a value, never template code: markup in it is shown, not run, and so is a PAD tag:</p>

{common:example 'fragments/ai_1'/}

<p>The answer is kept: the same provider, model, system prompt and prompt on a later request is the
same answer, no request made - for an hour unless <code>ttl=</code> says otherwise, never with
<code>ttl=0</code>. A failed answer is never kept.</p>

<h2>From PHP</h2>

<p><code>padAi ( $prompt, $options )</code> asks the same from a page's PHP and answers the text - here
Ollama, which runs a model on this machine and needs no key:</p>

{common:example 'fragments/ai_2'/}

<h2>Providers and options</h2>

<p>Every provider is a file of <code>pad/subs/ai/types/</code> - {pad:echo php:implode(', ', padAiProviders())/} -
with its endpoint, its headers, the request it builds and how it reads the text and an error out of
the answer. A provider is added by adding its file.</p>

<ul>
  <li><code>provider=</code> names one - else <code>PAD_AI_PROVIDER</code> from <code>.env</code>, else
      anthropic. Its key is a <code>.env</code> value: <code>ANTHROPIC_API_KEY</code>,
      <code>OPENAI_API_KEY</code>, <code>MISTRAL_API_KEY</code>, <code>GEMINI_API_KEY</code>,
      <code>COHERE_API_KEY</code>, <code>CLOUDFLARE_API_TOKEN</code> (and the account in
      <code>CLOUDFLARE_ACCOUNT_ID</code>), <code>AWS_BEARER_TOKEN_BEDROCK</code> (and the region in
      <code>AWS_REGION</code>); Ollama's address <code>OLLAMA_HOST</code>, while LM Studio needs no key
      unless it is set up to, <code>LM_API_TOKEN</code> then.</li>
  <li><code>model=</code> the model - claude-opus-5-5 for Anthropic unless given; <code>system=</code> the
      system prompt; <code>tokens=</code> the most the answer may take - the handling option
      <code>max</code> is something else.</li>
  <li>A missing key, an unknown provider or an error of the API - a refused key, a limit, a refusal -
      is an error under the strict check, so it shows while the page is written. Without it the tag
      answers nothing, the page goes on, the error is logged and <code>padAiError ()</code> says it.</li>
  <li>A test answers the provider with <code>padCurlFake</code>, as the examples here do; while the
      fetches are faked no answer is kept.</li>
</ul>

{pad:meta title='Notifications'/}

<p>A notification is one message to one person - an order shipped, a comment answered - written
once and sent on the channels asked for. <code>padNotify</code> renders the template
<code>_notifications/order-shipped.pad</code> for each channel and hands it over:</p>

padNotify ( $user, 'order-shipped', [ 'order' => 42 ], [ 'mail', 'database', 'slack' ] );

<p>The template is a section per channel, or the plain text for every channel without one. A line
<code>&#64;slack&#64;</code> opens Slack's section, <code>&#64;title&#64;</code> the title - the mail's subject, the
push's heading; what stands before the first one is the plain text:</p>

{common:example 'fragments/notify_1', pad='_notifications/order-shipped.pad'/}

<p>The channels are the files of <code>pad/subs/channels/types/</code> - {pad:echo php:implode(', ', padNotifyChannels())/}.
A channel is added by adding its file: the settings it needs and a function that sends.</p>

<h2>Kept on the site</h2>

<p>The database channel keeps a notification for its recipient under <code>DATA/notifications/</code>.
{pad:notifications/} lists the unread ones of the user logged in, newest first, each with
a <em>Mark read</em> link - signed for that person, so it marks nothing of anyone else's. As a
pair the notifications are its rows:</p>

{common:example 'fragments/notify_2'/}

<h2>To a service of your own</h2>

<p>The webhook channel posts the notification as JSON to <code>WEBHOOK_URL</code> - Zapier, n8n,
a service of your own - signed as Standard Webhooks has it: the headers <code>webhook-id</code>,
<code>webhook-timestamp</code> and <code>webhook-signature</code>, the HMAC-SHA256 of the three
under <code>WEBHOOK_SECRET</code>. The receiver makes the signature again and compares; a queued
notification keeps its id for a retry, so the receiver can drop a second delivery:</p>

{common:example 'fragments/notify_3'/}

<h2>Who gets it, and where</h2>

<ul>
  <li>The recipient is a user row - <code>email</code>, <code>phone</code> (sms, twilio), and a field per channel
      naming the person there: <code>telegram</code> (a chat id), <code>ntfy</code> (a topic),
      <code>matrix</code> (a room id), <code>webpush</code>, <code>pushover</code> (a user key) - or
      an e-mail address alone.</li>
  <li>Every setting is looked for in the options (<code>[ 'slack' => [ 'url' => ... ] ]</code>), then
      in that row, then in <code>.env</code>: <code>SLACK_WEBHOOK_URL</code>,
      <code>DISCORD_WEBHOOK_URL</code>, <code>TEAMS_WEBHOOK_URL</code>, <code>TELEGRAM_BOT_TOKEN</code>,
      <code>NTFY_TOPIC</code>, <code>MATRIX_TOKEN</code>, <code>SMS_URL</code> ... One missing
      everywhere is an error under the strict check naming the variable.</li>
  <li>An address the server posts to - a webhook, a homeserver, a gateway - comes from the options
      or <code>.env</code> alone, never from the row, which a visitor may fill: the row only names
      the person within the channel, and what it says is checked first.</li>
  <li>webpush reaches the browsers the person allowed, the site closed: their
      <code>PushSubscription</code> in the row, the message encrypted for each as RFC 8291 has it
      and signed with the application's VAPID keys - <code>padWebPushKeys ()</code> makes the pair
      for <code>VAPID_PUBLIC_KEY</code> and <code>VAPID_PRIVATE_KEY</code>, and openssl does the rest.</li>
  <li><code>[ 'queue' => TRUE ]</code> sends later: every channel a job of its own for
      <code>pad work</code>, so a channel that fails is retried alone and the mail that went is not
      sent twice.</li>
  <li>A channel that does not deliver is no error of the page: <code>padNotify</code> answers FALSE,
      the failure is logged, and <code>padNotifyResults ()</code> says what each channel did - and
      which push subscriptions are gone.</li>
</ul>

{pad:meta title='Social login'/}

<p>"Log in with GitHub" is two calls on one page. <code>padOAuthStart ( 'github' )</code> sends the
visitor to GitHub - after keeping a random state, a PKCE verifier and, for an OpenID Connect
provider, a nonce in the session. GitHub sends the visitor back with a code;
<code>padOAuthUser ( 'github' )</code> checks the state, trades the code for a token, fetches the
user and answers a row for <code>padLogin</code>:</p>

// oauth/[provider].php - the start and the way back of every provider
if ( ! padRequestHas ( 'code' ) and ! padRequestHas ( 'error' ) )
  padOAuthStart ( $provider );
if ( $user = padOAuthUser ( $provider ) ) {
  padLogin ( $user );
  padRedirectIntended ();
}
$problem = padOAuthError ();

<p>The example does both halves in one request, GitHub answered by fakes:</p>

{common:example 'fragments/oauth_2'/}

<h2>The buttons</h2>

<p>{pad:oauth 'github'/} is the link that starts it, styled as a button - to
<code>oauth/github</code> of the application, the page above, unless <code>href=</code> names another;
<code>label=</code> changes its text. The provider's icon shows when the icon set has one of its
name.</p>

{common:example 'fragments/oauth_1'/}

<h2>The providers</h2>

<p>Every provider is a file of <code>pad/subs/oauth/types/</code> - {pad:echo php:implode(', ', padOAuthKinds())/} -
an array with its endpoints, its scopes, whether it takes PKCE, the settings it needs and how its
answer becomes the user: <code>provider</code>, <code>id</code> (<code>github:583231</code>, never the
same for two providers - nor for two instances of one: a GitLab of one's own has its address in
it, <code>gitlab@git.example.org:42</code>, and so has every OpenID issuer), <code>sub</code>, <code>name</code>, <code>email</code>, <code>email_verified</code>, <code>avatar</code>
and <code>username</code>. A provider is added by adding its file.</p>

<ul>
  <li>The settings are <code>.env</code> values: <code>GITHUB_CLIENT_ID</code> and
      <code>GITHUB_CLIENT_SECRET</code>, and so on per provider; <code>GITLAB_URL</code> and
      <code>FORGEJO_URL</code> for a forge of one's own, <code>MICROSOFT_TENANT</code>, <code>SLACK_TEAM</code>,
      <code>OIDC_ISSUER</code>. A missing one is an error under the strict check that names it.</li>
  <li>GitHub keeps an address private by answering null; it is then taken from
      <code>/user/emails</code> - the primary one, verified.</li>
  <li>Bitbucket's consumer has its permissions - Account and Email - set at Bitbucket, not asked
      for in the address, and its key and secret go to the token endpoint as HTTP Basic. Its
      <code>/2.0/user</code> holds no address: it comes from <code>/2.0/user/emails</code>, the
      primary one when it is confirmed, else another confirmed one.</li>
  <li>The <code>email</code> is a way to reach the person, not who they are: a provider may hold
      an address its user typed and never proved. <code>email_verified</code> is TRUE only when
      the provider vouches for it - Google's, Apple's, LinkedIn's, Slack's and an OpenID provider's
      <code>email_verified</code>, Discord's <code>verified</code>, GitLab's
      <code>confirmed_at</code>, GitHub's and Forgejo's verified addresses, Bitbucket's confirmed
      ones, X's <code>confirmed_email</code>, Microsoft's optional
      claim <code>xms_edov</code>. Link a login to an account that exists already by its address
      only when it is TRUE; else the address is anyone's to claim.</li>
  <li>Apple wants a client secret made for every exchange: an ES256 JWT signed with the key of
      the developer account (<code>APPLE_TEAM_ID</code>, <code>APPLE_KEY_ID</code>,
      <code>APPLE_PRIVATE_KEY</code>). It sends the name once, with the first login.</li>
  <li>LinkedIn speaks OpenID Connect without a nonce and, for a web application, without PKCE -
      neither is a parameter of its authorization - and its id_token names
      <code>https://www.linkedin.com</code> as its issuer where its discovery document says
      <code>https://www.linkedin.com/oauth</code>: <code>linkedin</code> takes either, which the
      generic <code>oidc</code> cannot.</li>
  <li><code>oidc</code> is any OpenID Connect provider - Keycloak, Authentik, Auth0 - its endpoints
      read from the issuer's <code>/.well-known/openid-configuration</code>.</li>
  <li>A Slack user's id is unique within its workspace alone, so Slack's <code>sub</code> is both,
      <code>T0R7GR/U0R7JM</code>. <code>team=</code> (or <code>SLACK_TEAM</code>) keeps the login to
      one workspace: Slack is asked for it, and a token of any other is refused.</li>
  <li>X requires PKCE and takes its client's id and secret as HTTP Basic. It gives an address
      only to an app allowed the scope <code>users.email</code> - ask for it with
      <code>scopes='tweet.read users.read users.email'</code> and the user's
      <code>confirmed_email</code> is fetched too.</li>
  <li>The id_token of OpenID Connect is checked for its issuer, audience, expiry and the nonce.
      Its signature is not: it comes straight from the token endpoint over TLS, which OpenID
      Connect Core 3.1.3.7 lets stand for the signature - so every address of a provider, its
      issuer, <code>base=</code> and the endpoints its document names, must be https (http on
      localhost alone).</li>
  <li>A state works once and for ten minutes. A no at the provider, a stale state or a refused
      code answers FALSE - <code>padOAuthError ()</code> says which - never an error of the page.</li>
</ul>
