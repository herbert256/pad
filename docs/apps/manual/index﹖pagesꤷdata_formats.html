Data formats

Besides JSON, XML, YAML and CSV, {format:auto} reads the formats of pad/subs/formats/: TOML, INI, TSV, NDJSON, Markdown pipe tables, iCalendar, vCard, GeoJSON, GPX, KML, WebVTT and SRT subtitles and Excel spreadsheets. Name the format with format= - or type=, the same option:

PHP
 HTML
fragments/data_formats_1.pad 		Result 
{format:auto 'trip', format='toml'}
  title = "Weekend in Ghent"
  start = 2026-11-06

  [[stops]]
  name = "Gravensteen"
  hours = 2

  [[stops]]
  name = "Graslei"
  hours = 1.5
{/format:auto}

{data:trip}
  <h3>{$title} - {$start}</h3>
  <ul>
    {array:stops}<li>{$name}: {$hours} h</li>{/array:stops}
  </ul>
{/data:trip}

Weekend in Ghent - 2026-11-06

  • Gravensteen: 2 h
  • Graslei: 1.5 h

An array of tables is a list of rows inside the row, so {array:stops} iterates it; a date is the text it is, 2026-11-06.

Known on sight

Some formats need no name: a text that opens with BEGIN:VCALENDAR is a calendar, BEGIN:VCARD a vCard, lines of JSON objects NDJSON, a Markdown pipe table a table and a header of tabs TSV. Each event is a row - summary, start, end, allday, location and the rest:

PHP
 HTML
fragments/data_formats_2.pad 		Result 
{format:auto 'agenda'}
  BEGIN:VCALENDAR
  VERSION:2.0
  BEGIN:VEVENT
  UID:talk@example.com
  DTSTART:20261106T090000Z
  DTEND:20261106T100000Z
  SUMMARY:Opening talk
  LOCATION:Hall A
  END:VEVENT
  BEGIN:VEVENT
  UID:dinner@example.com
  DTSTART;VALUE=DATE:20261107
  SUMMARY:Conference dinner\, all welcome
  END:VEVENT
  END:VCALENDAR
{/format:auto}

<ul>
  {data:agenda}
    <li>{$summary} - {$start}{pad:if $allday} (all day){/pad:if}{pad:if $location} - {$location}{/pad:if}</li>
  {/data:agenda}
</ul>
  • Opening talk - 2026-11-06T09:00:00Z - Hall A
  • Conference dinner, all welcome - 2026-11-07 (all day)

Captions and subtitles

A text that opens with WEBVTT is the captions of a video, an SRT file its subtitles: a cue is a row - start and end as 00:01:02.500 (startms and endms in milliseconds), text with its markup, plain without it and voice, who speaks:

PHP
 HTML
fragments/data_formats_4.pad 		Result 
{format:auto 'talk'}
  WEBVTT

  00:00.000 --> 00:04.000
  <v Ann>Welcome to the <i>formats</i> talk.

  00:04.000 --> 00:09.500
  <v Bob>Every cue is a row &amp; every row a cue.
{/format:auto}

<dl>
  {data:talk}<dt>{$start} {$voice}</dt><dd>{$plain}</dd>{/data:talk}
</dl>
00:00:00.000 Ann
Welcome to the formats talk.
00:00:04.000 Bob
Every cue is a row & every row a cue.

Places

A KML file of Google Earth is a placemark a row, with the folder it stands in, the fields of its ExtendedData and its geometry as GeoJSON has it - lat and lon of a point, coordinates of a line or a polygon - so the rows of one are written as the other:

PHP
 HTML
fragments/data_formats_5.pad 		Result 
{format:auto 'walk', format='kml'}
  <kml xmlns="http://www.opengis.net/kml/2.2">
    <Folder>
      <name>Ghent</name>
      <Placemark>
        <name>Gravensteen</name>
        <ExtendedData><Data name="hours"><value>2</value></Data></ExtendedData>
        <Point><coordinates>3.7206,51.0573</coordinates></Point>
      </Placemark>
      <Placemark>
        <name>Along the Leie</name>
        <LineString><coordinates>3.7206,51.0573 3.7189,51.0545</coordinates></LineString>
      </Placemark>
    </Folder>
  </kml>
{/format:auto}

<ul>
  {data:walk}<li>{$folder}: {$name} - {$geometry}{pad:if $lat} at {$lat}, {$lon}{/pad:if}</li>{/data:walk}
</ul>
  • Ghent: Gravensteen - Point at 51.0573, 3.7206
  • Ghent: Along the Leie - LineString

Files and PHP

A file in _data/ is read by its extension - _data/trip.toml is {data:trip} and {local:trip.toml}, _data/sales.xlsx the first sheet of the workbook ({local:sales.xlsx sheet='Notes'} another). In a page's PHP, padFormatRead reads a text and padFormatWrite writes rows:

PHP
fragments/data_formats_3.php 		HTML
fragments/data_formats_3.pad 		Result 
<?php

  $readme = "# Scores\n\nThe table is the data.\n\n| player | points |\n| ------ | -----: |\n| Ann    |     21 |\n| Bob    |     17 |\n";

  $scores = padFormatRead ( 'markdown', $readme );
  $tsv    = padFormatWrite ( 'tsv', $scores );

?>
 
<p>{array:scores}{$player} has {$points}. {/array:scores}</p>
{$tsv}

Ann has 21. Bob has 17. 

player points
Ann 21
Bob 17
  • The formats are the files of pad/subs/formats/types/ - toml, ini, tsv, ndjson, jsonseq (JSON text sequences), markdown, ics, vcf, geojson, gpx, kml, vtt, srt, xlsx and json, csv, yaml, xml; rss, atom and jsonfeed write only. An extension names its format too: md, jsonl, yml.
  • A text a format cannot read is an error naming the format and the line - TOML error on line 3: the key 'name' is defined twice; with the strict check off it gives no rows.
  • TOML, INI, GeoJSON, GPX and KML are never guessed - they read as CSV, JSON or XML before - so name them, or keep them in a file with their extension.
  • Writing data out - a calendar, a feed, a spreadsheet - is Feeds and exports.
