A page that exposes its data with $padExpose answers it as JSON and CSV (Data answers) - and in every other format of pad/subs/formats/ that writes: a calendar, a feed, a spreadsheet, a map. $padFormatOptions gives the writer what the rows do not say, here the name of the calendar:

PHP
fragments/feeds_and_exports_1.php 		HTML
fragments/feeds_and_exports_1.pad 		Result 
<?php

  $talks = [ [ 'title' => 'Opening talk', 'start' => '2026-11-06T09:00:00Z', 'end' => '2026-11-06T10:00:00Z',
               'location' => 'Hall A', 'link' => 'https://example.com/talks/opening' ],
             [ 'title' => 'Data in and out', 'start' => '2026-11-06T11:00:00Z', 'end' => '2026-11-06T12:00:00Z',
               'location' => 'Hall B', 'link' => 'https://example.com/talks/formats' ] ];

  $padExpose        = [ 'talks' ];
  $padFormatOptions = [ 'title' => 'Talks', 'name' => 'Talks' ];

?>
 
<ul>
  {array:talks}<li>{$title} - {$location}</li>{/array:talks}
</ul>
  • Opening talk - Hall A
  • Data in and out - Hall B

Asked with &padFormat=ics - or by a calendar application sending Accept: text/calendar - the page answers an iCalendar file, with &padFormat=md a Markdown table. The template does not run for either:

  $calendar = padCurl ( $padGoExt . 'fragments/feeds_and_exports_1&padFormat=ics' ) ['data'];

  • The formats that write: ics, vcf, xlsx, rss, atom, jsonfeed, geojson, gpx, kml, vtt, srt, markdown, tsv, ndjson, jsonseq, toml, yaml, ini, besides json and csv. A table format answers the first list the page exposes, toml, yaml and ini every exposed variable by name.
  • A page of chapters - a start and a title each, the end the next one's start - asked with &padFormat=vtt is the src of a video's <track kind="chapters">.
  • Each answers with its own content type, and a file with the page's name and the format's extension - talks.ics inline, talks.xlsx as an attachment.
  • The answer is the same bytes for the same rows: an event's UID is made of the row, its DTSTAMP is its start, a spreadsheet's parts carry a fixed date - never the clock.
  • A row a format has no place for - an order without a date in a calendar - is left out of the answer.

A feed of a collection

padFormatWrite writes rows in a format in a page's PHP. The rows of a Collections work as they are for the feeds - title, date, slug and body - the slug behind the feed's link is an entry's address:

PHP
fragments/feeds_and_exports_3.php 		HTML
fragments/feeds_and_exports_3.pad 		Result 
<?php

  $atom = padFormatWrite ( 'atom', padCollection ( 'news' ),
                           [ 'title' => 'PAD news', 'link' => 'https://example.com/news/', 'author' => 'The PAD team' ] );

?>
 
{$atom}
 
<?xml version="1.0" encoding="utf-8"?>

  • rss, atom and jsonfeed take title, link, self, description and author; the feed's updated is its newest entry's date.
  • ics takes name and stamp, xlsx sheet, gpx name and as='track', kml name.
