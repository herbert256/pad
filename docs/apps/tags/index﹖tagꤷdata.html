Tags/Variables and stores/data:*

{data:*}

Reads a supported data format, a list or a range into a named data set for a later tag to iterate.

Variables and stores Either form

Syntax 

{pad:data 'name'} ... {/pad:data}
{pad:data 'name', type='csv'} ... {/pad:data}
{pad:data 'name', format='toml'} ... {/pad:data}
{pad:data 'name', source/}
{pad:data} ... {/pad:data 'name'}

Parameters

name
The name the data is kept under; {data:name} ... {/data:name} (or {data:name}) iterates it. Not the name of a built-in or application tag.
source
Optional, when there is no content: the data as a value - '1..5', '["a","b"]' - or a field holding it.

Options

type
The reader to use explicitly: a data format, list or range.
format
The format to read, also accepted as type=: atom, csv, geojson, gpx, ics, ini, json, jsonfeed, jsonseq, kml, markdown, ndjson, rss, srt, toml, tsv, vcf, vtt, xlsx, xml, yaml.

Description

{pad:data 'name'} ... {/pad:data} reads its content as data and keeps it under that name; it prints nothing. A later {data:name} ... {/data:name} iterates it like any page array - fields, properties, the handling options (sort, where, first ...) - and so do data='name' on another tag, {data:name}, {pad:tree} and the lookup pipe.

Formats

The format is recognised from the content itself:

  • JSON - starts with [ or {. An array of objects gives rows with fields; a plain array gives values, read with {$name}.
  • XML - starts with <. The elements under the root are the rows, their attributes and child elements the fields.
  • YAML - starts with ---, or with a - item or key: value line. It needs PHP's yaml extension.
  • A list - ('a', 'b', 2 * 3) in parentheses: every element is evaluated as an expression.
  • A range - 1..10 or a..z.
  • CSV - anything else of several lines: the first line names the fields, each further line is a row.

When the start does not tell, format='toml' or type='csv' names the reader explicitly. A one-line name of a file in the application's _data/ directory reads that file.

Other forms

Without content, a second parameter is the source: {pad:data 'steps', '1..5'}. A value from a field there is data, never template: a field holding a parenthesised list is refused, since its elements would run as expressions. With the name on the closing tag - {pad:data} ... {/pad:data 'name'} - the content is rendered first and the result read as data, so fields and tags inside it are resolved.

Content with braces - JSON objects - is read as written: a JSON object in the content is not taken for a tag. Under the strict syntax check a {pad:data} without a name is an error, and so is a name that is already a built-in or application tag, since {data:name} would never reach the store.

All data formats

The format registry supplies this list. Choose a format for its record shape and helper examples.

Format File extensions Read Write Description
atom atom no yes Atom (RFC 4287), written: a feed with its id, title, updated and author, an entry per row - its id, title, updated, link, summary and content (title, link, date, summary, body and id of a row, or the front matter of a Markdown collection: subs/formats/_lib/feeds.php).
csv csv yes yes Comma separated values (RFC 4180), read and written: the reader is the engine's own, data/csv.php - a header line naming the fields, then a row per line - and the writer the one a CSV page answer is made with: a header row of every key the rows use, a cell holding a list as its JSON, and a text cell a spreadsheet would run as a formula (=, +, -, @ in front) with a ' before it.
geojson geojson yes yes GeoJSON (RFC 7946), read and written: a feature a row - its properties, its id, geometry (the type), lat and lon of a Point, coordinates of any other - and rows as a FeatureCollection, a Point for every row with lat and lon, the other fields its properties.
gpx gpx yes yes GPS Exchange Format 1.1, read and written: every point a row - the waypoints, the points of the routes, those of the track segments - with its type, track, segment, point, name, lat, lon, ele, time and desc; rows as waypoints, routes and tracks again, by their type (as='track' makes a list of positions one track).
ics ics, ical, ifb, icalendar yes yes ICalendar (RFC 5545), read and written: the VEVENTs of a calendar as rows - uid, summary, start, end, allday, timezone, location, description, url, status, categories, rrule - and rows as a calendar, folded at 75 octets with CRLF line ends, its UID and DTSTAMP made of the rows so the same rows give the same bytes.
ini ini yes yes INI files, read and written: [sections] of key = value lines, ; and # comments, quoted values, key[] lists and key[name] records.
json json yes yes JSON (RFC 8259), read and written: the reader is the engine's own, data/json.php, which takes the document out of the text around it; the writer writes any value as a JSON page answer has it - pretty, slashes and characters past ASCII as they are.
jsonfeed json no yes JSON Feed 1.1 (jsonfeed.org), written: the feed's title=, link=, self=, description=, author= and an item per row - its id, url, title, content_html or content_text, summary and date_published (title, link, date, summary, body and id of a row, or the front matter of a Markdown collection: subs/formats/_lib/feeds.php).
jsonseq yes yes JSON text sequences (RFC 7464), read and written: a record a row - an RS (0x1E), a JSON text, a line feed - as jq --seq writes them and a GeoJSON text sequence (RFC 8142) is made of; a record that is no JSON, or a number cut short, is the error under the strict check and passed over on the lenient walk, as the RFC has a parser recover (subs/formats/_lib/jsonseq.php).
kml kml yes yes KML (OGC KML 2.2), read and written: a Placemark a row - its ExtendedData, id, name, description, folder, address, style, time, and its geometry as GeoJSON's reader has it: geometry, lat and lon of a Point, coordinates of any other (subs/formats/_lib/kml.php) - and rows as a Document of placemarks, in folders by their folder, Points written from lat and lon.
markdown md, markdown yes yes Markdown pipe tables (GitHub Flavored Markdown), read and written: the first table of a text - a README, a page of notes - as rows, and rows as a table whose columns line up, numbers on the right.
ndjson ndjson, jsonl yes yes Newline delimited JSON (JSON Lines): a JSON value a line, a row each, read and written - what a log, a stream or a bulk export is made of.
rss rss no yes RSS 2.0, written: a channel of the feed's title=, link= and description=, an item per row - its title, link, date, summary and id (title, link, date, summary, body and id of a row, or the front matter of a Markdown collection: subs/formats/_lib/feeds.php).
srt srt yes yes SubRip subtitles (SRT, as the Library of Congress describes it, fdd000569), read and written: a subtitle a row, as WebVTT's cues are - id (its number), start, end, startms, endms, text, plain, voice and settings (subs/formats/_lib/cues.php) - and rows as subtitles numbered from 1 in the order of their start, 00:00:01,000 --> 00:00:04,000, with CRLF line ends.
toml toml yes yes TOML 1.0, read and written: tables, arrays of tables, inline tables, dotted keys, every kind of string, number and date.
tsv tsv, tab yes yes Tab separated values (IANA text/tab-separated-values), read and written: a header line of field names, then a row per line, the cells split at the tabs.
vcf vcf, vcard yes yes VCard 4.0 (RFC 6350), read and written - 3.0 cards are read as well: a card a row, name, the parts of the name, org, title, email and phone (the preferred one, and emails and phones all of them), url, the parts of the address, birthday, note and uid; rows as version 4.0 cards, folded at 75 octets with CRLF line ends, a UID made of the row when it has none.
vtt vtt yes yes WebVTT (W3C, WebVTT: The Web Video Text Tracks Format), read and written: a cue a row - id, start, end, startms, endms, text, plain, voice and settings (subs/formats/_lib/cues.php) - and rows as the cues of a <track>, sorted by their start: ?talk&padFormat=vtt is the src of a video's captions or chapters.
xlsx xlsx yes yes Excel spreadsheets (Office Open XML, SpreadsheetML), written and read with PHP's zip extension: rows as a workbook of one sheet - a bold header row frozen at the top, numbers as numbers, booleans as booleans, dates with a date format, every text a text and never a formula - the same bytes for the same rows; and the first sheet of a workbook as rows - shared and inline strings, numbers, booleans, dates (sheet= picks another, by name or number).
xml xml yes no XML, read only: the reader is the engine's own, data/xml.php - an element's attributes and children its fields, a repeated element a list, the names of every namespace taken.
yaml yaml, yml yes yes YAML 1.2, read and written with the PHP yaml extension: the reader is the engine's own, data/yaml.php - true and false the only booleans, 9:30 a text and not 570 - and the writer yaml_emit's document between --- and ..., a text that would read as another kind of value quoted.

A file of _data/ selects its reader by extension, for example {local:delivery.toml} or {local:sales.xlsx sheet='Notes'}. XLSX is binary: keep it in a file or pass the original bytes to padFormatRead; do not paste it into a template. JSON text sequences use the jsonseq format name explicitly because they have no registered file extension.

From PHP, padFormatRead ( 'toml', $contents ) reads a document and padFormatWrite ( 'toml', $data ) writes one. A page can return its exposed data with padFormat=toml. These helpers parse or serialize data; the separate list and range readers are template expressions, not interchange formats.

Examples

JSON rows

An array of objects becomes rows with fields, iterated by the name it was given.

Templateexamples/data/1-json.pad 
{pad:data 'dataPlanets'}
[
  { "name": "Mercury", "moons": 0 },
  { "name": "Earth",   "moons": 1 },
  { "name": "Mars",    "moons": 2 }
]
{/pad:data}
<ul>
{data:dataPlanets}
  <li>{$name}: {$moons} {pad:echo $moons eq 1 ? 'moon' : 'moons'/}</li>
{/data:dataPlanets}
</ul>
Resultopen alone
  • Mercury: 0 moons
  • Earth: 1 moon
  • Mars: 2 moons

CSV and XML

The first CSV line names the fields; XML elements under the root are the rows, attributes the fields.

Templateexamples/data/2-csv-xml.pad 
{pad:data 'dataPrices'}
fruit,price
Apple,0.40
Pear,0.55
{/pad:data}
{pad:data 'dataStock'}
<stock>
  <item fruit="Apple" boxes="12"/>
  <item fruit="Pear" boxes="3"/>
</stock>
{/pad:data}
<p>{data:dataPrices}{$fruit} costs {$price}. {/data:dataPrices}</p>
<p>{data:dataStock}{$fruit}: {$boxes} boxes. {/data:dataStock}</p>
Resultopen alone

Apple costs 0.40. Pear costs 0.55.

Apple: 12 boxes. Pear: 3 boxes.

Ranges, lists and a source parameter

A range, an evaluated list, and data given as the second parameter instead of content.

Templateexamples/data/3-list.pad 
{pad:data 'dataLetters'}a..f{/pad:data}
{pad:data 'dataSums'}(1 + 1, 2 * 3, 10 - 7){/pad:data}
{pad:data 'dataSteps', '1..4'/}
<p>{data:dataLetters}{$dataLetters} {/data:dataLetters}</p>
<p>{data:dataSums}{$dataSums} {/data:dataSums}</p>
<p>{data:dataSteps}step {$dataSteps}{property:notLast@dataSteps}, {/property:notLast@dataSteps}{/data:dataSteps}</p>
Resultopen alone

a b c d e f

2 6 3

step 1, step 2, step 3, step 4

A TOML document

format= selects TOML explicitly; its fields become the rows read by the following tag.

Templateexamples/data/7-toml.pad 
{pad:data 'delivery', format='toml'}
title = "Deliveries"
[[people]]
name = "Ann"
city = "Utrecht"
{/pad:data}
{data:delivery}<h3>{$title}</h3>{array:people}<p>{$name} — {$city}</p>{/array:people}{/data:delivery}
Resultopen alone

Deliveries

Ann — Utrecht

See also

  • {pad:content} Keeps a piece of template under a name instead of printing it, for a later {content:name} to render.
  • {pad:bool} Reduces its content or a value to TRUE or FALSE and keeps it under a name, for a later {bool:name} to test.
  • {pad:set} Assigns one or more variables, as globals that outlive the level the tag stands in.
  • {pad:tree} Renders a tree of rows: its body for every row, and {pad:recurse} renders it again for the row's children.
  • {pad:count} Renders its content only when a named data set or page array holds at least one element.
