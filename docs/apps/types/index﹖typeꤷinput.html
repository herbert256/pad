Types/Subsystems/input:

input:

A rich form field, a file of pad/inputs/types/, posted by any form.

Subsystems Tried 30 of 31 for a bare name

Syntax 

{input:slider 'volume', label='Volume'/}
{slider 'volume', label='Volume'/}

Description

A rich form field of the kind the tag names - a slider, a stepper, a date picker, stars, a signature ... - the inputs subsystem in PAD/inputs/ writes it, a field of its {form} as {input} is: a native field a form posts without any script, made more of by its script. 

{input:slider 'volume', label='Volume', unit='%', rules='integer|between:10,90'/}
{input:datepicker 'arrival', label='Arrival', min='2026-01-01'/}
{stars 'score', label='Score'/}

Resolution: a PHP file PAD/inputs/types/<name>.php, its script and style in PAD/inputs/assets/, the field written by PAD/inputs/input.php: the files of types/ are the kinds, and a kind is added by adding its file. Its items are read raw, as {input}'s are - label=, rules=, min= are the field's, never an option of the engine. Bare, an input kind comes last of the subsystems, so a store, a field, an array of the name - a page's $slider - or a kind of another subsystem wins; write input:slider there.

The handler

pad/types/input.php: Type handler for a rich form field: {input:slider 'volume', min=0, max=100/}, or a bare tag naming a file of inputs/types/ when nothing else has the name, {slider 'volume'/}. The kind is the tag's name, and the field is written by inputs/input.php - run as a built-in tag's PHP half is run, types/_go/tag.php. Its items are read raw, as {input}'s are (padParmsRaw, lib/attrs.php): label=, rules=, min= and every attribute are the field's, never an option of the engine - rows= of a markdown editor is no handling option.
