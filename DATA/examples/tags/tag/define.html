The body between {pad:define 'card'} and {/pad:define} becomes the template of a new tag, {define:card}, exactly as if it stood in _tags/card.pad. Defining prints nothing; every use of the tag renders the body, where the use stands and with the fields there.

Everything a file-based custom tag can do works in the body: {#name} reads a parameter of the use, {pad:parms} declares them (a bare name required, name=default filling in), @content@ takes the content of a pair use in, and {pad:slot}s take named fills. A define can use itself, for rows below the current one.

The body is kept as written and rendered at each use, so a field in it is read at the use, not at the definition. A define exists from the point it is walked - like a {pad:content} or {pad:data} store - so a use above the {pad:define} is an unknown tag. {define:card} asserts that the name is a define.

The define: prefix selects this namespace, so the name can also exist as a built-in, application tag or macro. Under the strict check a define needs a name and a body. Use a define for markup with a frame - content and slots; use a macro when the parameters should read as plain fields.
