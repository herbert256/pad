pages/comments.pad 		Result 
{meta title='Comments'}

<p>PAD has two comment forms. Both are taken out of the template before it is scanned, so a tag written inside one never runs and nothing of it reaches the output.</p>

<ul>
  <li><code>{# ... #}</code> - the original form</li>
  <li><code>{-- ... --}</code> - the form the editor kits highlight and toggle</li>
</ul>

{example 'fragments/comments_1'}

<h2>Rules</h2>

<ul>
  <li>A comment closes at the first <code>#}</code> or <code>--}</code> after it, and may span lines.</li>
  <li><code>{--</code> must be followed by whitespace: a CSS custom property inside an {tag 'ignore'} block, <code>:root{--gap:4px}</code>, is CSS and stays as it is.</li>
  <li><code>{#name}</code> is not a comment but the option sigil - the value of the tag option <code>name</code>.</li>
</ul>

<h2>See Also</h2>

<ul>
  <li>{manual 'ignore'} - keep PAD from parsing braces</li>
</ul>

{meta title='Field sigils'}

<p>The character in front of a name says which value is meant and how it is written into the page. None of these opens a level - the value is spliced in where the tag stood.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>Form</th><th>Writes</th></tr>
  <tr><td><code>{$name}</code></td><td>The field, through the sanitize chain</td></tr>
  <tr><td><code>{!name}</code></td><td>The same field raw - the sanitize chain is skipped</td></tr>
  <tr><td><code>{?name}</code></td><td>The field as a query fragment: <code>&amp;name=url+encoded</code></td></tr>
  <tr><td><code>{^name}</code></td><td>The field as JSON, escaped for a double-quoted HTML attribute; an array is encoded whole</td></tr>
  <tr><td><code>{&#35;name}</code></td><td>An option or parameter of the tag</td></tr>
  <tr><td><code>{&amp;name}</code></td><td>A property of the tag</td></tr>
</table>

{example 'fragments/sigils_1'}

<p>The JSON form is made for mount points of client-side components: <code>JSON.parse(elem.getAttribute('data-props'))</code> reads it back, with no custom tag and no {tag 'ignore'} pipe.</p>

<h2>See Also</h2>

<ul>
  <li>{manual 'php_and_html'}</li>
  <li>{manual 'escaping_special_PAD_chars'}</li>
</ul>

App: manual - Page: pages/forms
PHP
 HTML
pages/forms.pad 		Result 
{meta title='Forms'}

<p>{tag 'form'}, {tag 'input'} and {tag 'textarea'} write the fields of a form. When the
form comes back with mistakes in it, each field shows again what was typed - escaped - and
the message for its mistake beside it. <code>padValidate</code> in the page's PHP finds the
mistakes.</p>

{example 'fragments/forms_1'}

<ul>
  <li>{tag 'form'} posts back to the page and carries the session's CSRF token (see
  {manual 'csrf_protection'}) and its name: <code>padPosted ( 'contact' )</code> is true when
  this form came back, so a page with two forms knows which one did.</li>
  <li>{tag 'input'} and {tag 'textarea'} take the field name first; <code>label=</code> writes a
  label tied to the field, <code>value=</code> the value before anything was posted, and every
  other item is an attribute of the field, as {tag 'attrs'} writes it - <code>required</code>,
  <code>rows=6</code>, <code>placeholder='...'</code>.</li>
  <li>A checkbox or radio is checked when the posted value is its own value; a password or
  file field is never refilled.</li>
</ul>

<h2>Validation</h2>

<p><code>padValidate ( $rules )</code> checks the posted values and answers one message per
field that breaks a rule, keyed by the field - empty when all is well. A second argument
checks other data; a third replaces messages, per field (<code>'email'</code>) or per field
and rule (<code>'email.required'</code>):</p>

{example 'fragments/forms_2'}

<p>The rules: <code>required</code>, <code>email</code>, <code>url</code>, <code>numeric</code>,
<code>integer</code>, <code>min:n</code> and <code>max:n</code> (a length, or a value with
<code>numeric</code> or <code>integer</code>), <code>in:a,b,c</code>, <code>regex:/.../</code>,
<code>same:other_field</code>, <code>accepted</code> and <code>date</code>. An empty field is
checked for <code>required</code> only. A rule name nothing knows is an error.</p>

<h2>After a failed post</h2>

<p>The fields of the form that came back show the message beside them, in the words of their
own label, tied to the field with <code>aria-invalid</code> and
<code>aria-describedby</code> so a screen reader reads them together. Here the post is
pretended in the PHP, the way a visitor's would arrive:</p>

{example 'fragments/forms_3'}

<p>After a post that passes, store it and send the visitor on with <code>padRedirect ()</code>:
a refresh of the page they land on does not post a second time.</p>

<h2>Rules in the template</h2>

<p>The rules can stand on the fields themselves: <code>rules='required|email'</code> on an
{tag 'input'} or a {tag 'textarea'}. They are read from the page's template before its PHP
runs, and a post of the form is checked against them there - <code>padPosted ( 'contact' )</code>
is true only for a post that kept them, so the PHP acts on a good post alone. A post that broke
one renders the form again, refilled, with the messages beside the fields and the form's
<code>error=</code> above them (<code>error</code> alone says "Please correct the errors
below."):</p>

{example 'fragments/forms_4', skipResult}

<ul>
  <li>Only what is written out counts: quoted rules, on a field with a quoted name, in a
  {tag 'form'} with a name that posts back to its own page. Rules on a field in a snippet, a
  custom tag, a {tag 'page'} or a layout, rules made from a variable, rules in a form with
  <code>action=</code> or <code>method='get'</code> and rules on a file field are errors -
  nothing would check them.</li>
  <li>Every field of the posted form that has rules is checked, also one in an {tag 'if'}
  branch that did not render. A field that is there only sometimes keeps its check in the
  PHP: <code>padValidate</code> adds its messages to those of the template.</li>
  <li><code>padFormFailed ( 'contact' )</code> is true when the form came back and broke its
  rules.</li>
</ul>

App: manual - Page: pages/live_reload
PHP
 HTML
pages/live_reload.pad 		Result 
{meta title='Live reload'}

<p>With <code>$padReload = 'local'</code> in an application's <code>_config/config.php</code>,
every page of a local request carries a small script that asks the server once a second
whether a file behind the page has changed - and reloads the page when one has. Save a
template, a page's PHP or a stylesheet, and the browser shows it.</p>

{ignore}
<code><?php

  // _config/config.php
  $padReload = 'local';

?></code>
{/ignore}

<h2>What it watches</h2>

<ul>
  <li><code>'local'</code> (or <code>TRUE</code>) - the application's directory, its entry point directory in <code>www/</code> (stylesheets, scripts, images), and <code>_common</code> when the application uses it.</li>
  <li><code>'engine'</code> - <code>pad/</code> as well, for work on the engine itself.</li>
</ul>

<p>The script asks <code>?page&amp;padReload</code>, which the engine answers with the
newest file time before it runs any page. Together with <code>pad serve</code> (see
{manual 'pad_command'}) no other tool is needed.</p>

<h2>Where it never goes</h2>

<p>Only a local request gets it - the command line, or this machine asking itself with
nothing forwarded - whatever the setting. It is left out of a bare fragment
(<code>&amp;padInclude</code>), of anything that is not an HTML page answering 200, of the
page cache, which stores the page before the script is added, and of a <code>pad export</code>.
Set it in the configuration rather than in a page's PHP: the poll is answered before any
page runs.</p>

App: manual - Page: pages/pad_command
PHP
 HTML
pages/pad_command.pad 		Result 
{meta title='The pad command'}

<p><code>apps/cli/pad</code> is the command-line tool: a new application or page, a server
without Apache, a page rendered to the terminal, and a strict check of every page. Link it
into your PATH once as <code>pad</code>.</p>

{ignore}
<code>pad new shop                   # apps/shop/ and www/shop/index.php
pad new shop/orders/list       # list.php + list.pad in apps/shop/orders/
pad serve                      # http://127.0.0.1:8000/<app>/
pad render demo clock          # a page to stdout
pad render shop search q=shoes # with request values
pad lint shop                  # every page under the strict check
pad export demo out/           # a static copy (see the static export page)
pad help</code>
{/ignore}

<h2>A first application</h2>

{ignore}
<code>$ pad new shop
made apps/shop/index.php
made apps/shop/index.pad
made apps/shop/README.md
made www/shop/index.php

$ pad render shop
<h1>Hello from Shop!</h1></code>
{/ignore}

<p><code>pad new</code> never overwrites: an application or a page that exists is refused.
<code>pad serve</code> runs PHP's built-in server over <code>www/</code>, so every
application is at <code>http://127.0.0.1:8000/<app>/</code>; <code>--mount=pad</code>
serves them under <code>/pad/</code> instead, the way an Apache setup may mount them.</p>

<h2>Checking every page</h2>

<p><code>pad lint</code> renders each page of an application in a process of its own, with
the strict syntax check on, and lists what failed with its place in the template - the same
position an error page shows (see {manual 'template_errors'}):</p>

{ignore}
<code>$ pad lint shop
ok    index
FAIL  orders/list  Field '$totl' not found
      apps/shop/orders/list.pad:3:10  {$totl}  - did you mean $total?

2 pages, 1 failed</code>
{/ignore}

<p>Every command answers with its exit status - 0 when all is well, 1 when not - so a
script or a git hook can use it: <code>pad lint shop || exit 1</code>.</p>

App: manual - Page: pages/requests_and_sessions
PHP
 HTML
pages/requests_and_sessions.pad 		Result 
{meta title='Requests and sessions'}

<p>A page's PHP reads what the request brought, keeps what has to outlive it in the
session, and builds the address the visitor goes to next. The engine already turns request
values into variables - <code>$padRequestVars</code> - and keeps the
<code>$padSessionVars</code> names in the session; these helpers do the same by name, from
PHP, whatever those settings let through.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>function</th><th>what it does</th></tr>
  <tr><td><code>padRequest ( $key, $default )</code></td><td>one value of the input by name or dot path - a post over the query, the body of a JSON request - or all of it</td></tr>
  <tr><td><code>padRequestHas ( $keys )</code></td><td>whether every name was sent - an emptied field was</td></tr>
  <tr><td><code>padRequestFilled ( $key )</code></td><td>whether it was sent and is not blank</td></tr>
  <tr><td><code>padRequestOnly ( $keys )</code></td><td>the input with these names only</td></tr>
  <tr><td><code>padRequestExcept ( $keys )</code></td><td>the input without these names</td></tr>
  <tr><td><code>padRequestMethod ()</code></td><td>GET, POST, PUT ... - GET on the command line</td></tr>
  <tr><td><code>padRequestIs ( $method )</code></td><td>whether the method is this one, or one of a list</td></tr>
  <tr><td><code>padSession ( $key, $default )</code></td><td>one value of the session, or all of it - never starts a session</td></tr>
  <tr><td><code>padSessionPut ( $key, $value )</code></td><td>keeps a value in the session, which starts on demand</td></tr>
  <tr><td><code>padSessionHas ( $keys )</code></td><td>whether every name is in the session</td></tr>
  <tr><td><code>padSessionPull ( $key, $default )</code></td><td>a value of the session, taken out of it</td></tr>
  <tr><td><code>padSessionForget ( $keys )</code></td><td>removes names from the session</td></tr>
  <tr><td><code>padSessionRegenerate ()</code></td><td>a new session id, the data kept - after a login</td></tr>
  <tr><td><code>padFlashInput ( $except )</code></td><td>keeps this request's input for the next request only</td></tr>
  <tr><td><code>padOld ( $key, $default )</code></td><td>reads that input there</td></tr>
  <tr><td><code>padUrl ( $page, $vars, $absolute )</code></td><td>a link to a page of this application</td></tr>
  <tr><td><code>padBack ( $fallback )</code></td><td>redirects to the page the visitor came from - never off-site</td></tr>
  <tr><td><code>padAbort ( $status, $message )</code></td><td>ends the request with an error status</td></tr>
</table>

<h2>The input</h2>

<p><code>padRequest</code> reads a value by the name the form gave it, a dot path into an
array - <code>customer.name</code> for a field named <code>customer[name]</code> - and
answers the default when the request did not bring it. A posted value wins over a query value
of the same name, the body of a request sent as <code>application/json</code> is input too,
and every text is trimmed. The query key that names the page is no input.</p>

{example 'fragments/requests_and_sessions_1'}

<ul>
  <li>The names of <code>padRequestHas</code>, <code>padRequestOnly</code> and
  <code>padRequestExcept</code> are an array or one text with commas:
  <code>'customer.email, note'</code>.</li>
  <li>Blank is nothing, an empty or whitespace-only text, an empty array; a <code>'0'</code>
  is filled.</li>
  <li>A <code>*</code> in a dot path reads every item of a list:
  <code>padRequest ( 'items.*.id' )</code>.</li>
</ul>

<h2>The session</h2>

<p><code>padSessionPut</code> starts the session when there is none yet; reading never does
- a visitor without a session cookie gets the default, and no session is made to find that
out. Dot paths work here too:</p>

{example 'fragments/requests_and_sessions_2'}

<p>A name listed in <code>$padSessionVars</code> is a variable as well as a session value: the
helpers keep the two in step, so a value put in is the one the end of the request writes
back. After a login, <code>padSessionRegenerate ()</code> moves the session to a new id, so an
id someone learned before it is worth nothing.</p>

<h2>The form after a failed post</h2>

<p>The page a form posts to checks it; when something is wrong it keeps the input with
<code>padFlashInput ()</code> and sends the browser back to the form with
<code>padBack ()</code>. The form's page reads the input with <code>padOld</code> - on that
one next request only, like a {manual 'flash_messages'} message. Passwords and the CSRF token
are left out unless another list is given.</p>

{example 'fragments/requests_and_sessions_3'}

{ignore}
<code>// signup.php - the page the form posts to
$errors = padValidate ( [ 'email' => 'required|email' ] );

if ( $errors ) {
  padFlash ( 'Please check the form.', 'error' );
  padFlashInput ();
  padBack ( 'signup/form' );
}

// signup/form.php - the form, filled again
$email = padOld ( 'email' );        // {input 'email', value=$email}</code>
{/ignore}

<h2>Links</h2>

<p><code>padUrl</code> writes a link to a page of this application: the values as a query,
arrays too, in the clean form <code>/myapp/products/42</code> when
<code>$padCleanUrls</code> is on (see {manual 'clean_urls'}). Without a page it is the page
the visitor asked for; a third argument <code>TRUE</code> makes it absolute, on
<code>$padHost</code>, for a mail or a feed.</p>

{example 'fragments/requests_and_sessions_4'}

<h2>Going back, and stopping</h2>

<p>Both end the request, so they are shown here, not run. <code>padBack</code> follows the
browser's Referer only when it is a page of this application on this host, and goes to the
fallback page otherwise - the index when none is given. <code>padAbort</code> answers an error
status, 400 to 599, with the message as plain text - or the status's own words - through the
engine's exit, never PHP's (see {manual 'ending_the_request'}):</p>

{ignore}
<code>padBack ( 'orders' );                   // back where the visitor came from, else orders

if ( ! $order )
  padAbort ( 404 );                     // 404 Not Found

if ( padRequestIs ( 'delete' ) and ! $admin )
  padAbort ( 403, 'Only an administrator can delete an order.' );</code>
{/ignore}
