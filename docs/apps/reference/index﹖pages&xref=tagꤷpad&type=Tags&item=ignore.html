pages/app_tests.pad 		Result 
{meta title='Application tests'}

<p>An application keeps its own tests in <code>_tests/</code>. A test is a page there -
<code>cart.pad</code>, with <code>cart.php</code> when it needs data - next to its answer,
<code>cart.txt</code>. <code>pad test shop</code> renders every test page and compares:</p>

{ignore}
<code>$ pad test shop
shop
  ok    cart
  FAIL  checkout
        want: <p>Total 42</p>
        got:  HTTP 500 - assert failed: $total eq 42
              apps/shop/_tests/checkout.pad:1:1  {assert $total eq 42}
  2 tests, 1 failed</code>
{/ignore}

<h2>The answer</h2>

<ul>
  <li>the exact output of the page, trimmed;</li>
  <li><code>/a pattern/</code> matched over it - for output that changes, a date or a count;</li>
  <li><code>HTTP 500</code>, with an optional <code>/pattern/</code> on the next line, for a test that is meant to fail.</li>
</ul>

<p>A test without an answer counts against the run; <code>pad test shop --record</code> writes
the missing answers from what the pages render now, and never overwrites one.
<code>pad test --all</code> runs every application that has tests, and <code>./ci.sh</code>
does that as its <code>apptests</code> line.</p>

<h2>Asserts</h2>

<p>{tag 'assert'} holds a page to a condition during a test run: false, and the test fails
with the condition and the message as its report. Anywhere else it is silent - the
condition is not even evaluated - so it can stay in the application's own pages. The switch
is <code>$padAssert</code>, which <code>pad test</code> turns on; this example turns it on in
its PHP:</p>

{example 'fragments/app_tests_1'}

<h2>A test page</h2>

<p>It is a page like any other, rendered bare - without the application's wrappers - and no
URL reaches it. It can bring in a real page with <code>{page 'cart'}</code>, or
include the page's own PHP and check the data it sets:</p>

{ignore}
<code>_tests/cart.php    <?php include APP . 'cart.php'; ?>
_tests/cart.pad    {assert $total eq 42, 'the cart total'}
                   <p>Total {$total}</p>
_tests/cart.txt    <p>Total 42</p></code>
{/ignore}

{meta title='Options of your own'}

<p>A file in the application's <code>_options/</code> directory makes its name an option
of every tag - written bare, <code>{staff words}</code>, or with a value,
<code>{staff wrap='em'}</code>. Where the file stands decides when it runs:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>file</th><th>runs</th><th><code>$padContent</code> is</th></tr>
  <tr><td><code>_options/name.php</code></td><td>before the tag renders</td><td>the template between the tags</td></tr>
  <tr><td><code>_options/end/name.php</code></td><td>after the tag rendered</td><td>the result - every occurrence, joined</td></tr>
</table>

<p>&nbsp;</p>

<p>The handler changes <code>$padContent</code>, and the option's value is in
<code>$padGetName</code> - TRUE when the option is written bare. An end option sees the
fields filled in, so it can count, mark or tidy what the tag produced. Here
<code>fragments/options/_options/end/words.php</code> appends a word count:</p>

{ignore}
<code><?php                                   // _options/end/words.php

  $padContent .= '(' . str_word_count ( strip_tags ( $padContent ) ) . ' words)';

?></code>
{/ignore}

{example 'fragments/options/options_1'}

<p>With a value - <code>_options/end/wrap.php</code> puts the result in the element it is
given:</p>

{ignore}
<code><?php                                   // _options/end/wrap.php

  $padContent = "<$padGetName>" . trim ( $padContent ) . "</$padGetName>";

?></code>
{/ignore}

{example 'fragments/options/options_2'}

<p>An option may have both files: the first works on the template, the second on what it
became. The end options run before the built-in <code>toContent</code>, <code>toData</code>
and <code>tidy</code> - those store or tidy what the end option made - and before the closing
tag's pipe. Like tags and callbacks they are looked up from the page's directory up to the
application root.</p>

{meta title='Application Structure'}

<p>An application is a directory under <code>apps/</code>, and a page is a pair of files in
it: <code>name.php</code> gathers the data, <code>name.pad</code> renders it - the
<a href="?pages/php_and_html">php and html</a> page is about that pairing. No routing and no
controllers: creating the files creates the page, and subdirectories become url paths -
<code>?admin/users</code> is <code>admin/users.pad</code>.</p>

<h2>The wrappers</h2>

<p>A file <code>_inits.pad</code> wraps every page of its directory: the page's own output
lands where the wrapper writes <code>@page@</code>, and an <code>_exits.pad</code> closes
below it. This very page is inside one - the menu below and the centering around what you
are reading come from the wrapper of the <code>pages/</code> directory:</p>

{source 'pages/_inits.pad'}

<p>Wrappers nest: the application's own <code>_inits.pad</code> wraps the subdirectory's,
which wraps the page. The page never mentions any of them.</p>

<h2>The PHP runs first, in order</h2>

<p>All PHP has run before any template renders. Down the directory chain and back up:</p>

{ignore}
<code>/_inits.php
    /admin/_inits.php
        /admin/users.php
    /admin/_exits.php
/_exits.php</code>
{/ignore}

<h2>Subdirectories inherit, and may override</h2>

<p>The <a href="?pages/extending">extension directories</a> work at every level.
<code>_lib/</code> files accumulate down the chain, so a deeper page has every level's
functions; the lookup for a tag, function or snippet starts in the page's own directory and
walks up, so a subdirectory may bring its own words - or redefine an inherited name, and its
version wins for its pages.</p>

<p><b><a href="{$padHost}structure/">The structure application</a></b> is this page live: a
tree three levels deep, every level carrying the full set of special directories and
wrappers, with pages that show which level answered.</p>

PHP

pages/ending_the_request.pad 		Result 
{meta title='Ending the Request'}

<p>Some pages do not end by reaching their last line: a form handler redirects, a guard
refuses, an error stops everything. PAD has a tag or a function for each - and none of them
can be demonstrated live on this page, because each one would end the request this page is.
The examples are therefore shown, not run.</p>

<h2>Redirecting</h2>

<p>From a page's PHP, <code>padRedirect()</code> sends the browser to another page and ends
the request cleanly - session closed, buffers flushed, headers sent:</p>

{ignore}
<code>padRedirect ( 'tickets/index' );           // to a page of this application
padRedirect ( 'tickets/index', $vars );    // with variables carried along</code>
{/ignore}

<p><b>Never use PHP's <code>exit</code> or <code>die</code></b>, and not
<code>header()</code> either: they end PHP mid-request, skipping everything PAD still had to
do. The same goes for a restart - <code>padRestart('page')</code> renders another page in
place of this one without a round trip to the browser.</p>

<h2>The tags that end a request</h2>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>tag</th><th>what it does</th></tr>
  <tr><td><code>{exit}</code></td><td>ends the request where it stands - nothing is shipped, not even the output so far</td></tr>
  <tr><td><code>{error 'message'}</code></td><td>reports an error through the configured error action, which normally ends the request with a 500</td></tr>
  <tr><td><code>{exception 'message'}</code></td><td>throws a real PHP exception, for testing the nets that catch one</td></tr>
  <tr><td><code>{dump}</code></td><td>stops the request on a dump of the engine state, the heavy debugging tool</td></tr>
</table>

<h2>What happens on an error</h2>

<p>Any error - a tag that misses, a PHP warning, a thrown exception - ends the request
through the configured <code>$padErrorAction</code>: <code>pad</code> renders an error page,
<code>log</code> and <code>ignore</code> carry on, <code>dump</code> stops on the state
dump. The request answers with HTTP 500, and a command-line run exits with status 1, so a
script can test the outcome without reading the output.</p>

<p>A <code>demand</code> option turns an empty tag into an error: a page that is meaningless
without its data can say so - <code>{users demand}...{/users}</code> -
instead of rendering a hole.</p>

{meta title='Environment, cache and rate limits'}

<p>Some values differ per machine and must not stand in the code: the database password, an
API key, a debug switch. <code>padEnv</code> reads them from the server's environment or from
a <code>.env</code> file beside the code, so the same application runs unchanged on a laptop
and on the production server, and the secrets never reach git. The cache keeps what is slow
to make from one request to the next, and a rate limit counts how often a visitor tries.</p>

<h2>Environment values</h2>

<p><code>padEnv ( 'KEY', $default )</code> looks in three places and answers the first that
has the key: the real environment of the server (<code>getenv</code>, <code>$_ENV</code>,
<code>$_SERVER</code> - what Apache's <code>SetEnv</code> or PHP-FPM's <code>env[...]</code>
sets), then the application's <code>_config/.env</code>, then <code>.env</code> in the PAD
home. Without the key it answers the default - a closure as the default is called. This
manual has a <code>_config/.env</code> of its own:</p>

<code>MANUAL_SITE_NAME="PAD manual"
MANUAL_PAGE_SIZE=20
MANUAL_DEBUG=false</code>

{example 'fragments/environment_and_cache_1'}

<p>The engine loads its library before it reads any configuration, so the place a secret is
needed first can ask for it - <code>_config/config.php</code>:</p>

<code>$padSqlPassword = padEnv ( 'DB_PASSWORD' );
$padSqlUser     = padEnv ( 'DB_USER', 'shop' );</code>

<h2>The .env file</h2>

{ignore}
<code># a comment
APP_NAME=Shop                     a bare value, trimmed - # after a space starts a comment
export DB_HOST=localhost          export in front, as a shell script writes it
GREETING="Hello\nWorld"           double quotes: \n \r \t \" \\ \$ and ${OTHER}
PATTERN='${not} \n expanded'      single quotes: the text exactly as written
DEBUG=false                       true, false, null and empty are TRUE, FALSE, NULL and ''
NOTE="two
lines"                            a quoted value may run over several lines</code>
{/ignore}

<ul>
  <li>A quoted value is always text: <code>"false"</code> is the word, not FALSE.</li>
  <li><code>${OTHER}</code> is OTHER from the real environment, else as set
  earlier in the same file, else empty; it works in bare values too.</li>
  <li>A key written twice: the later line wins, as in a shell.</li>
  <li>A line that is none of these is an error naming the file and the line number - never
  the line itself, which may hold the secret.</li>
  <li>A key that starts with <code>HTTP_</code> is never read from the real environment:
  those are the headers of the request, which the client sends.</li>
  <li>No URL reaches <code>apps/</code> - the web server serves <code>www/</code> only - so an
  application's <code>_config/.env</code> is not served. The repository's
  <code>.gitignore</code> keeps the <code>.env</code> of the PAD home out of git; keep an
  application's out the same way when it holds a real secret.</li>
  <li>Each file is read once per request, the first time a key is asked for.</li>
</ul>

<h2>The cache</h2>

<p>A slow query, a remote service, a computed report: <code>padRemember ( $key, $ttl,
$callback )</code> answers what is kept under the key, or runs the callback, keeps its answer
for <code>$ttl</code> seconds and answers that. <code>padCachePut</code>,
<code>padCacheGet</code>, <code>padCacheHas</code> and <code>padCacheForget</code> do the same
by hand.</p>

{example 'fragments/environment_and_cache_2'}

<ul>
  <li>The ttl is a number of seconds - 3600 when <code>padCachePut</code> is not told - or
  <code>NULL</code> for ever, a <code>DateTimeInterface</code> (until then) or a
  <code>DateInterval</code>. A ttl of 0 or less keeps nothing.</li>
  <li>The cache keeps arrays and scalars - strings, numbers, TRUE, FALSE, NULL - nested as
  deep as they go. A value that holds an object is an error: it would not come back as
  it went in.</li>
  <li>A kept <code>NULL</code> counts: a callback that found nothing is not asked again until
  the entry expires. A closure as the default of <code>padCacheGet</code> is called.</li>
  <li>Each application has its own entries, files under
  <code>DATA/cache/app/<application>/</code>, one per key; <code>padCacheFlush ()</code>
  removes them all. A file is written beside its place and then renamed over it, so a
  request reads the old value or the new one, never half of one.</li>
  <li>When what a key holds changes - a product saved, a price updated - the page that
  changes it calls <code>padCacheForget</code>, and the next request makes it again.</li>
</ul>

<h2>Rate limits</h2>

<p><code>padRateLimit ( $key, $maxAttempts, $decaySeconds )</code> counts a hit and answers
TRUE while the key stays within the limit - five attempts a minute - and FALSE over it. The
first hit starts a window of <code>$decaySeconds</code>; when it ends, the key starts from
nothing again. A login form, a contact form, an expensive search: key it on the visitor, or
on the account that is tried.</p>

{example 'fragments/environment_and_cache_3'}

<ul>
  <li><code>padRateLimitRemaining ( $key, $maxAttempts )</code> - the hits left in the
  window; <code>padRateLimitAvailableIn ( $key )</code> - the seconds until it ends, 0 when no
  window runs; <code>padRateLimitClear ( $key )</code> - after a login that succeeded.</li>
  <li>A hit over the limit is not counted; the window ends when it would have anyway.</li>
  <li>Requests that come at once are each counted: they take turns on a lock while they
  count.</li>
  <li>Rate limits are kept with the cache - <code>padCacheFlush ()</code> clears them too -
  and a rate limit and a cache key of the same name are two entries.</li>
</ul>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>function</th><th>what it does</th></tr>
  <tr><td><code>padEnv ( $key, $default = NULL )</code></td><td>the value of an environment key - the real environment, then <code>_config/.env</code>, then the PAD home's <code>.env</code>, else the default</td></tr>
  <tr><td><code>padCacheGet ( $key, $default = NULL )</code></td><td>the value kept under the key, else the default</td></tr>
  <tr><td><code>padCachePut ( $key, $value, $ttl = 3600 )</code></td><td>keeps the value for <code>$ttl</code> seconds - <code>NULL</code> for ever; TRUE when it is kept</td></tr>
  <tr><td><code>padCacheHas ( $key )</code></td><td>whether the key holds a value that has not expired</td></tr>
  <tr><td><code>padCacheForget ( $key )</code></td><td>removes the key; TRUE when it held a value</td></tr>
  <tr><td><code>padCacheFlush ()</code></td><td>removes every entry of this application, rate limits included</td></tr>
  <tr><td><code>padRemember ( $key, $ttl, $callback )</code></td><td>the kept value, or the callback's answer - kept for <code>$ttl</code> seconds</td></tr>
  <tr><td><code>padRateLimit ( $key, $maxAttempts, $decaySeconds = 60 )</code></td><td>counts a hit: TRUE within the limit, FALSE over it</td></tr>
  <tr><td><code>padRateLimitRemaining ( $key, $maxAttempts )</code></td><td>the hits left in the current window</td></tr>
  <tr><td><code>padRateLimitAvailableIn ( $key )</code></td><td>the seconds until the current window ends</td></tr>
  <tr><td><code>padRateLimitClear ( $key )</code></td><td>ends the window - the key starts from nothing</td></tr>
</table>

{meta title='Event hooks'}

<p>A file in the application's <code>_events/</code> directory runs whenever the request
reaches that moment - on every request, without touching the engine. The place to report an
error to a tracker, log a slow query or an API that is down, or post-process the finished
page.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>file</th><th>runs when</th><th>its variables</th></tr>
  <tr><td><code>_events/error.php</code></td><td>an error is raised, whatever the error action does with it next</td><td><code>$error</code>, <code>$file</code>, <code>$line</code></td></tr>
  <tr><td><code>_events/sql.php</code></td><td><code>db()</code> ran a statement</td><td><code>$sql</code> as sent, <code>$input</code>, <code>$vars</code>, <code>$result</code>, <code>$rows</code>, <code>$ms</code></td></tr>
  <tr><td><code>_events/curl.php</code></td><td>a remote fetch finished, well or not</td><td><code>$url</code>, <code>$result</code> (the HTTP code, 999 on a failure), <code>$error</code>, <code>$ms</code></td></tr>
  <tr><td><code>_events/output.php</code></td><td>the page is about to be sent</td><td><code>$output</code> - change it to change the page</td></tr>
</table>

<p>&nbsp;</p>

<p>They are found the way <a href="?pages/callback">callbacks</a> are: the page's own
directory first, then up to the application root, so a subdirectory can hear an event its
own way. Here <code>fragments/events/_events/sql.php</code> keeps every statement in a list
the page shows:</p>

{ignore}
<code><?php                                   // fragments/events/_events/sql.php

  $GLOBALS ['heard'] [] = $sql;

?></code>
{/ignore}

{example 'fragments/events/events_1'}

<p>A hook runs in a scope of its own: the event's values are its variables, and the page's
are reached through <code>$GLOBALS</code>. What it echoes is dropped. An error inside the
error hook is logged and the original error goes its way; a query inside the sql hook does
not call the hook again.</p>

{ignore}
<code><?php                                   // _events/output.php

  $output = str_replace ( '</body>', '<!-- served by PAD --></body>', $output );

?></code>
{/ignore}

<p>The output hook runs after tidying and before the page
cache stores the page, so a cached page is served as the hook left it.</p>

pages/live_reload.pad 		Result 
{meta title='Live reload'}

<p>With <code>$padReload = 'local'</code> in an application's <code>_config/config.php</code>,
every page of a local request carries a small script that asks the server once a second
whether a file behind the page has changed - and reloads the page when one has. Save a
template, a page's PHP or a stylesheet, and the browser shows it.</p>

{ignore}
<code><?php

  // _config/config.php
  $padReload = 'local';

?></code>
{/ignore}

<h2>What it watches</h2>

<ul>
  <li><code>'local'</code> (or <code>TRUE</code>) - the application's directory, its entry point directory in <code>www/</code> (stylesheets, scripts, images), and <code>_common</code> when the application uses it.</li>
  <li><code>'engine'</code> - <code>pad/</code> as well, for work on the engine itself.</li>
</ul>

<p>The script asks <code>?page&amp;padReload</code>, which the engine answers with the
newest file time before it runs any page. Together with <code>pad serve</code> (see
{manual 'pad_command'}) no other tool is needed.</p>

<h2>Where it never goes</h2>

<p>Only a local request gets it - the command line, or this machine asking itself with
nothing forwarded - whatever the setting. It is left out of a bare fragment
(<code>&amp;padInclude</code>), of anything that is not an HTML page answering 200, of the
page cache, which stores the page before the script is added, and of a <code>pad export</code>.
Set it in the configuration rather than in a page's PHP: the poll is answered before any
page runs.</p>

{meta title='The pad command'}

<p><code>apps/cli/pad</code> is the command-line tool: a new application or page, a server
without Apache, a page rendered to the terminal, and a strict check of every page. Link it
into your PATH once as <code>pad</code>.</p>

{ignore}
<code>pad new shop                   # apps/shop/ and www/shop/index.php
pad new shop/orders/list       # list.php + list.pad in apps/shop/orders/
pad serve                      # http://127.0.0.1:8000/<app>/
pad render demo clock          # a page to stdout
pad render shop search q=shoes # with request values
pad lint shop                  # every page under the strict check
pad export demo out/           # a static copy (see the static export page)
pad help</code>
{/ignore}

<h2>A first application</h2>

{ignore}
<code>$ pad new shop
made apps/shop/index.php
made apps/shop/index.pad
made apps/shop/README.md
made www/shop/index.php

$ pad render shop
<h1>Hello from Shop!</h1></code>
{/ignore}

<p><code>pad new</code> never overwrites: an application or a page that exists is refused.
<code>pad serve</code> runs PHP's built-in server over <code>www/</code>, so every
application is at <code>http://127.0.0.1:8000/<app>/</code>; <code>--mount=pad</code>
serves them under <code>/pad/</code> instead, the way an Apache setup may mount them.</p>

<h2>Checking every page</h2>

<p><code>pad lint</code> renders each page of an application in a process of its own, with
the strict syntax check on, and lists what failed with its place in the template - the same
position an error page shows (see {manual 'template_errors'}):</p>

{ignore}
<code>$ pad lint shop
ok    index
FAIL  orders/list  Field '$totl' not found
      apps/shop/orders/list.pad:3:10  {$totl}  - did you mean $total?

2 pages, 1 failed</code>
{/ignore}

<p>Every command answers with its exit status - 0 when all is well, 1 when not - so a
script or a git hook can use it: <code>pad lint shop || exit 1</code>.</p>

{meta title='Remote data with a cache'}

<p>Data can come from another server: a URL as the data of a tag, a <code>.curl</code> file
in <code>_data/</code>, or the {tag 'curl'} tag for the raw answer. Each of them takes a
<code>ttl</code> - the seconds to keep the answer - and within that time the page is served
from the copy instead of asking the source again. A dashboard on an external API then costs
one call per ttl, not one per visitor.</p>

<p>A <code>.curl</code> file names the URL and the ttl. Here <code>_data/rates.curl</code>
reads the rates from a page of this manual standing in for an API:</p>

{ignore}
<code><curl>
  <url>SELF://manual/?fragments/rates&amp;amp;padInclude</url>
  <ttl>600</ttl>
</curl></code>
{/ignore}

<p>Its name is a tag, like any data file:</p>

{example 'fragments/remote_1'}

<p>The same with the URL in the template - the ttl is an option of the tag the data is
for, <code>{pad data='https://...', ttl=600}</code> - or the answer as it came,
with {tag 'curl'}:</p>

{example 'fragments/remote_2'}

<p>When the source fails after the ttl - it is down, or answers with an error - the last good
copy is served and the failure is written to the error log, where an
<a href="?pages/events">event hook</a> on <code>curl</code> hears it too. Only a good answer
is kept, and a copy stays a day beyond its ttl for that purpose
(<code>$padCurlStale</code>). <code>$padCurlCache</code> chooses where the copies live:
<code>'file'</code>, <code>'apcu'</code>, <code>'redis'</code>, <code>'memcached'</code>,
or <code>FALSE</code> to fetch every time.</p>
