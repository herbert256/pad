Rich form fields

Beside {input:field} and {input:textarea} a form can hold fields that do more: a slider, a row of stars, a switch, a month to choose a day from, a tag input, a signature, a Markdown editor with its preview. The subsystem has 27 types, including the native field, textarea, form container and standalone validator. Every kind is a file of pad/subs/inputs/types/, with rich fields' scripts and styles in www/assets/inputs/, and the inputs application shows them all, each in a form that posts back.

PHP
 HTML
fragments/inputs_1.pad 		Result 
{input:slider 'volume', label='Volume', unit='%'/}
{input:stars 'score', label='Your rating'/}
{input:toggle 'news', label='Send me the newsletter', checked/}

Writing a field

The input: type names the kind, {input:slider 'volume'/}. The first parameter is the field's name, label= its label, and every other item the kind does not take is an attribute of its field, as with {input:field}: required, placeholder=, autocomplete=.

A real value, with or without a script

Every kind writes a native field that a form posts as it is - a range, a number, a date, a time, a colour, a checkbox, radio buttons, a text field - and its script, written once a page with the CSP nonce, makes more of it: a month over the date, the times to pick from, swatches beside the colour. Without the script the form works all the same; only the signature needs it.

PHP
 HTML
fragments/inputs_2.pad 		Result 
{input:datepicker 'arrival', label='Arrival'/}
{input:timepicker 'pickup', label='Time', every=15/}
{input:colorpicker 'tint', label='Colour'/}

Some fields post a text of their own making: a tag input the words joined with a comma, the boxes of a one-time code the code, a signature a PNG as a data URL - each in a field with the name, which a form without the script fills by hand. Choices come from a list - options=, suggestions= - from a store named by data=, or a line each between the tags.

PHP
 HTML
fragments/inputs_3.pad 		Result 
{input:taginput 'topics', label='Topics', value='pad, forms'/}
{input:combobox 'city', label='City'}
  Amsterdam
  Berlin
  Paris
{/input:combobox}
{input:otp 'code', label='Code', length=4/}

Refilled, with the message beside it

The fields are fields of the {input:form} around them: after a post of that form they show what was posted, and the message padValidate left for them after their frame, in the words of their label. rules= on a field is read from the template before the page's PHP runs, as on {input:field}, and client on the form checks the same rules in the browser. Here the post is pretended in the PHP:

PHP
fragments/inputs_4.php 		HTML
fragments/inputs_4.pad 		Result 
<?php

  // As if the form had been posted.

  $_SERVER ['REQUEST_METHOD'] = 'POST';
  $_POST = [ 'guests' => '12' ];

  $errors = padValidate ( [
    'guests' => 'integer|between:1,8',
    'score'  => 'required' ] );

?>
 
{input:stepper 'guests', label='Guests'/}
{input:stars 'score', label='Rating'/}

  • The kinds: colorpicker, combobox, currency, datepicker, daterange, dropzone, durationpicker, field, form, mdeditor, multiselect, newpassword, otp, rangeslider, repeatable, segmented, signature, slider, stars, stepper, taginput, textarea, timepicker, toggle, treepicker, unitpicker, validator.
  • The colours are custom properties on .pad-input - --pad-input-accent, --pad-input-line, --pad-input-star and their like - with light and dark defaults.
  • A password is never refilled, a file field cannot be, and the rules of a drop zone are padUpload's.
