Tags/Debugging and errors/dump

{dump}

Stops the request and shows the debug dump of the engine's state at that point.

Debugging and errors Single tags

Syntax 

{dump}

Description

{dump} ends the request right where it stands and answers with the debug dump of the engine: the message {dump} tag used, the stack, every level of the tag stack with its tag, type, parameters, content and flags, the application's variables, the stores, the request, the headers and the SQL and remote calls made so far. Nothing after the tag is processed - the output rendered so far is thrown away and the status is 500.

Who sees what depends on where the request comes from. A local request - the command line, or a loopback request with nothing forwarded - gets the full report inline - under the console output type the message, the template position and the directory the full report was written to. Any other visitor gets only the request id, or the application's _errors/500.pad when it has one, while the full report is written under DATA/dumps/, so a forgotten {dump} leaks nothing.

Use it to look at everything at one moment. To look at one value while the page goes on rendering, use {debug}; to follow the execution of a part of the page, {trace}. Like {exit} it never returns, so it has no content and no else branch.

Examples

Look at the state mid-page

The request stops at the dump; the rows above it were processed, the paragraph below never is.

Templateexamples/dump/1-stop-here.src 
{orders}
  <p>{$number}: {$total}</p>
  {if $total gt 1000}{dump}{/if}
{/orders}
<p>This paragraph is never rendered when an order above 1000 is there.</p>

Check a computed value

The dump lists the application variables, so a value set just before it can be inspected.

Templateexamples/dump/2-after-set.src 
{set $subtotal = $price * $quantity}
{set $vat      = $subtotal * 0.21}
{dump}
<p>Never reached: {$vat}</p>

See also

  • {debug} Shows values as a collapsible tree in the page, for a local request only, while rendering goes on.
  • {trace} Switches the execution trace on for just the part of the page it wraps.
  • {error} Raises a PAD error from the template, handled as the configured error action says.
  • {exit} Ends the request at once, with an empty body - the PAD way to stop instead of PHP's exit.
