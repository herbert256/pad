App: manual - Page: pages/app_tests
PHP
 HTML
pages/app_tests.pad 		Result 
{meta title='Application tests'}

<p>An application keeps its own tests in <code>_tests/</code>. A test is a page there -
<code>cart.pad</code>, with <code>cart.php</code> when it needs data - next to its answer,
<code>cart.txt</code>. <code>pad test shop</code> renders every test page and compares:</p>

{ignore}
<code>$ pad test shop
shop
  ok    cart
  FAIL  checkout
        want: <p>Total 42</p>
        got:  HTTP 500 - assert failed: $total eq 42
              apps/shop/_tests/checkout.pad:1:1  {assert $total eq 42}
  2 tests, 1 failed</code>
{/ignore}

<h2>The answer</h2>

<ul>
  <li>the exact output of the page, trimmed;</li>
  <li><code>/a pattern/</code> matched over it - for output that changes, a date or a count;</li>
  <li><code>HTTP 500</code>, with an optional <code>/pattern/</code> on the next line, for a test that is meant to fail.</li>
</ul>

<p>A test without an answer counts against the run; <code>pad test shop --record</code> writes
the missing answers from what the pages render now, and never overwrites one.
<code>pad test --all</code> runs every application that has tests, and <code>./ci.sh</code>
does that as its <code>apptests</code> line.</p>

<h2>Asserts</h2>

<p>{tag 'assert'} holds a page to a condition during a test run: false, and the test fails
with the condition and the message as its report. Anywhere else it is silent - the
condition is not even evaluated - so it can stay in the application's own pages. The switch
is <code>$padAssert</code>, which <code>pad test</code> turns on; this example turns it on in
its PHP:</p>

{example 'fragments/app_tests_1'}

<h2>A test page</h2>

<p>It is a page like any other, rendered bare - without the application's wrappers - and no
URL reaches it. It can bring in a real page with <code>{page 'cart'}</code>, or
include the page's own PHP and check the data it sets:</p>

{ignore}
<code>_tests/cart.php    <?php include APP . 'cart.php'; ?>
_tests/cart.pad    {assert $total eq 42, 'the cart total'}
                   <p>Total {$total}</p>
_tests/cart.txt    <p>Total 42</p></code>
{/ignore}

pages/charts.pad 		Result 
{meta title='Charts'}

<p>{tag 'chart'} draws a chart as inline SVG on the server. There is no JavaScript, so the
chart prints, works where scripts do not run, and caches like any other output. A
<code>bar</code> chart puts columns on a zero baseline; a <code>line</code> chart draws a line
over a light wash with the last point marked.</p>

{example 'fragments/charts_1'}

<p>The first word picks the kind of chart, after the job the data has to do:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>Kind</th><th>Shows</th><th>Options</th></tr>
  <tr><td><code>line</code></td><td>change over time</td><td><code>label</code>, <code>value</code></td></tr>
  <tr><td><code>bar</code> (or <code>column</code>), <code>hbar</code></td><td>categories compared</td><td><code>label</code>, <code>value</code>, <code>stacked</code></td></tr>
  <tr><td><code>pie</code>, <code>donut</code></td><td>parts of a whole</td><td><code>label</code>, <code>value</code></td></tr>
  <tr><td><code>scatter</code>, <code>bubble</code></td><td>how two numbers relate</td><td><code>x</code>, <code>y</code>, <code>size</code>, <code>label</code>, <code>color</code>, <code>trend</code></td></tr>
  <tr><td><code>heatmap</code></td><td>patterns in a grid of two categories</td><td><code>x</code>, <code>y</code>, <code>value</code></td></tr>
  <tr><td><code>sankey</code></td><td>flows from one stage to the next</td><td><code>source</code>, <code>target</code>, <code>value</code></td></tr>
  <tr><td><code>network</code></td><td>connections</td><td><code>source</code>, <code>target</code>, <code>value</code>, <code>layout</code>, <code>arrows</code></td></tr>
  <tr><td><code>treemap</code>, <code>sunburst</code></td><td>a hierarchy, each part's share</td><td><code>label</code>, <code>value</code>, <code>levels</code></td></tr>
  <tr><td><code>sparkline</code></td><td>a shape the size of a word</td><td><code>label</code>, <code>value</code></td></tr>
</table>

<p>An option left out takes the first field that fits: a numeric one for a number, another one
for a name.</p>

<h2>Where the numbers come from</h2>

<ul>
  <li><code>data='sales'</code> - a {tag 'data'} store, a sequence store, an array of the page's PHP, or a <code>_data</code> file of that name.</li>
  <li><code>value=</code> names the field with the number, <code>label=</code> the field for the axis. Without them the first numeric field is the value and the first other field the label.</li>
  <li><code>sequence='fibonacci', rows=12</code> - the first terms of a sequence, for demo data straight away.</li>
</ul>

<h2>Several series</h2>

<p>A list of fields in <code>value=</code> draws a series each - bars side by side, or on top of
each other with <code>stacked</code>, or a line each, named at its end. A legend above the plot
names them in the fixed order of the colours; eight series at most.</p>

{example 'fragments/charts_3'}

<h2>Horizontal bars</h2>

<p><code>hbar</code> lays the bars down, the names on the left - for long names or many
categories.</p>

{example 'fragments/charts_4'}

<h2>Pie and donut</h2>

<p>Parts of a whole: only positive values count, clockwise from twelve o'clock, a legend with
each value and its share. Past eight parts the smallest are folded into one grey
<em>Other</em>. A donut shows the total in its middle.</p>

{example 'fragments/charts_5'}

<h2>Scatter and bubble</h2>

<p>A dot per row on two numeric axes, <code>x=</code> and <code>y=</code>. <code>color=</code>
colours the dots by a field, <code>trend</code> draws the least-squares line. A bubble's
<code>size=</code> sets its area.</p>

{example 'fragments/charts_6'}

<h2>Heatmap</h2>

<p>Two categories as columns (<code>x=</code>) and rows (<code>y=</code>), each cell coloured by
its value in seven steps of one hue, with the scale underneath.</p>

{example 'fragments/charts_7'}

<h2>Sankey</h2>

<p>A row is a flow from <code>source=</code> to <code>target=</code>, as wide as its
<code>value=</code>. The columns follow the flows; flows that go round in a circle are an
error.</p>

{example 'fragments/charts_8'}

<h2>Network</h2>

<p>A row is a link between two nodes. The default <code>layout='force'</code> pulls linked nodes
together - the same data always draws the same picture - and <code>layout='radial'</code> sets
them on a circle; <code>arrows</code> shows the direction.</p>

{example 'fragments/charts_9'}

<h2>Treemap and sunburst</h2>

<p><code>levels=</code> lists the fields above the parts, the outermost first. A treemap nests
rectangles, a sunburst rings; the colour is that of the outermost level.</p>

{example 'fragments/charts_10'}

<h2>Sparklines</h2>

<p>{tag 'sparkline'} is a line chart the size of a word, without axes, to stand in a sentence
or a table cell.</p>

{example 'fragments/charts_2'}

<h2>Accessible and themeable</h2>

<p>Every chart is an image to a screen reader (<code>role="img"</code>), named by its
<code>title=</code> and described by a list of its values. Every bar, point, slice, cell, flow
and node carries its own tooltip; a sparkline has none. The colours are CSS custom properties - <code>--pad-chart-series</code>,
<code>--pad-chart-text</code>, <code>--pad-chart-grid</code>, <code>--pad-chart-surface</code>,
the categorical <code>--pad-chart-1</code> to <code>--pad-chart-8</code>,
<code>--pad-chart-other</code> and the heatmap's <code>--pad-chart-heat-0</code> to
<code>--pad-chart-heat-6</code> - set on <code>.pad-chart</code>, and their defaults follow the
page's <code>color-scheme</code>, light or dark.</p>

{meta title='Validation in the browser'}

<p>The rules a form's fields carry are checked on the server, after the post. With
<code>client</code> on the {tag 'form'} the browser checks them too, as the visitor types and
before the form leaves - with the same rules and the same messages, so the two never
disagree. The server still checks every post: the browser's check only saves a round trip.</p>

{example 'fragments/client_validation_1', skipResult}

<ul>
  <li>The form gets its rules in a <code>data-pad-rules</code> attribute, and the first such form
      of the page brings a small script along. A field is checked when it is left, again
      while it is typed in once it showed a message, and every field when the form is sent - a
      form that fails is not sent, and the first field with a message gets the focus.</li>
  <li>The messages stand where {tag 'input'} puts the server's - a
      <code><span class="error"></code> after the field, tied to it with
      <code>aria-invalid</code> and <code>aria-describedby</code> - in the words of the field's
      label; the form's <code>error=</code> shows above the fields.</li>
  <li>A form with <code>client</code> needs a name and fields with <code>rules=</code>. A
      <code>regex:</code> rule JavaScript cannot read as PCRE does is left to the server.</li>
</ul>

<h2>Forms a component draws</h2>

<p>A React, Vue or Alpine form is no {tag 'form'} of the template. Keep the rules in the page's
PHP instead - one list for both sides: <code>padValidate ( $rules )</code> checks the post, and
<code>padValidateClient ( $rules )</code> exports the same list for the browser, every rule
with the message padValidate would give:</p>

{example 'fragments/client_validation_2'}

<p>{tag 'validator'} in the template brings the checker without a form, and the component asks
it:</p>

{ignore}
<code><div x-data="{ rules: {^rules}, form: {}, errors: {} }">
  <input x-model="form.email" @blur="errors = padValidate.check(rules, form)">
  <span class="error" x-text="errors.email"></span>
</div>
{validator}</code>
{/ignore}

<p><code>padValidate.check ( rules, values )</code> answers the message of every field that broke
a rule; <code>padValidate.field ( rules.email, value, values )</code> one field's, empty when it
holds. A field named <code>tags[]</code> takes a list.</p>

<p>A list links to the page of a post with its slug - <code>?news/post&amp;slug={$slug}</code> -
and that page names it with the <code>slug</code> option. A slug that names no file gives no
rows, so the {construct 'else'} part answers.</p>

{example 'fragments/collections_2'}

{meta title='Comments'}

<p>PAD has two comment forms. Both are taken out of the template before it is scanned, so a tag written inside one never runs and nothing of it reaches the output.</p>

<ul>
  <li><code>{# ... #}</code> - the original form</li>
  <li><code>{-- ... --}</code> - the form the editor kits highlight and toggle</li>
</ul>

{example 'fragments/comments_1'}

<h2>Rules</h2>

<ul>
  <li>A comment closes at the first <code>#}</code> or <code>--}</code> after it, and may span lines.</li>
  <li><code>{--</code> must be followed by whitespace: a CSS custom property inside an {tag 'ignore'} block, <code>:root{--gap:4px}</code>, is CSS and stays as it is.</li>
  <li><code>{#name}</code> is not a comment but the option sigil - the value of the tag option <code>name</code>.</li>
</ul>

{meta title='Template coverage'}

<p>A test suite says what it checks; coverage says what it reaches. With coverage on, every
local request notes which templates it read, which of their tags ran, and which branch each
{tag 'if'} and {tag 'case'} took. The report then shows each template with the parts that
never ran marked.</p>

{example 'fragments/coverage_1'}

<ul>
  <li><code>$padCoverage = TRUE</code> in <code>_config/config.php</code> records into the run
      <code>default</code>; a name instead of TRUE records into a run of that name, and
      <code>?page&amp;padCoverage=name</code> records one request.</li>
  <li><code>develop/?coverage&amp;start=suites</code> records every local request of every
      application until <code>develop/?coverage&amp;stop</code> - start it, run the suites,
      stop it, and <code>develop/?coverage&amp;run=suites</code> lists every template with the
      share of its tags and branches that ran, and the files no request read at all.</li>
  <li>A run is a file of JSON lines, <code>DATA/coverage/<run>.jsonl</code>, one line per
      request. Only local requests are recorded.</li>
  <li>An {if} without an {else} has one branch more: the run in which
      its condition was false. It is marked on the {/if}.</li>
</ul>

pages/csrf_protection.pad 		Result 
{meta title='CSRF protection'}

<p>Another site can make a visitor's browser post to your application - a hidden form that
submits itself - and the browser sends your session cookie along. A CSRF token tells those
posts apart from the ones your own forms send: a random value kept in the visitor's session
and written into your form, which another site can make the browser send but cannot read.</p>

<h2>One setting</h2>

<p>With <code>$padCsrf = TRUE</code> in <code>_config/config.php</code> every
<code><form method="post"></code> of a page gets a hidden <code>padCsrfToken</code> field
holding the token, and every POST - and PUT, PATCH and DELETE - that does not bring the token
back is answered <code>403</code> before any of the application runs. The forms an
application already has are protected without a change to them. A form that posts to another
site gets no token, and neither does a GET form, whose fields end up in the url.</p>

<h2>The {csrf} tag</h2>

<p>{tag 'csrf'} writes the field itself, for a form the page builds some other way, or for
an application that leaves <code>$padCsrf</code> off and checks a post by hand with
<code>padCsrfValid ()</code>. <code>{csrf token}</code> is the bare token, for a
script that sends it in an <code>X-CSRF-Token</code> header:</p>

{example 'fragments/csrf_protection_1'}

<ul>
  <li>The token is one per session, so two open tabs and the back button keep working. The
  session starts the first time a token is needed.</li>
  <li>A page carrying a token is never stored in the page cache - it would hand one visitor's
  token to the next.</li>
  <li>An application that accepts posts from elsewhere on some pages - a webhook - switches
  <code>$padCsrf</code> off for those pages in its <code>_config/config.php</code>, which
  knows <code>$padPage</code>.</li>
</ul>

{meta title='Directory guards'}

<p>A <code>_guard.php</code> in a directory decides, for every page below it, whether the
request may see the page - before any <code>_inits.php</code> or page PHP runs. Access
control follows the file tree: put one in <code>admin/</code> and every page there is
protected, with no list of routes to keep in step.</p>

<p>The guard of this manual's <code>guarded/</code> directory:</p>

{source 'guarded/_guard.php'}

<ul>
  <li>Returning <code>FALSE</code> - or anything that is not true: <code>NULL</code>,
  <code>0</code>, <code>''</code> - refuses the page with <code>403 Forbidden</code>. Returning
  <code>TRUE</code>, or no return at all, lets the request through to the next guard down.</li>
  <li>The guards run from the application root down, each directory's in turn, after the
  <code>_lib</code> files, so a guard can call the application's functions and read the session
  and request variables - and <code>$padPage</code>, to decide per page.</li>
  <li>A guard can send the visitor elsewhere itself: <code>padRedirect ( 'login' )</code>.</li>
  <li>A page a {tag 'page'} tag includes is guarded too: when its guard says no, it renders as
  nothing, and the page that includes it carries on.</li>
  <li>A guarded page is never served from the page cache, nor stored in it.</li>
</ul>

pages/expressions.pad 		Result 
{meta title='Expressions'}

<p>An expression is the part of a tag that works out a value: <code>1 + 2</code>,
<code>$price * $qty</code>, <code>$name | upper</code>, <code>$state in ('open',
'pending')</code>. PAD's evaluator reads it - numbers, strings, fields, lists, operators,
functions and pipes - and answers one value. This page goes through all of it; every example
is live, its template beside what PAD made of it.</p>

<h2>Where expressions stand</h2>

<p>An expression is read wherever a tag takes a value: the parameter of {tag 'echo'} and of
<code>{if}</code> and <code>{elseif}</code>, the right side of
<code>{set $x = ...}</code>, the value of <code>{case}</code> and its
<code>{when}</code>s, the condition of <code>{while}</code> and
<code>{until}</code>, a quoted option such as <code>where='...'</code>, and an
occurrence assignment <code>%name = ...</code> on a tag that loops:</p>

{example 'fragments/expressions_1'}

{example 'fragments/expressions_2'}

{example 'fragments/expressions_3'}

<p>A field tag takes a pipe as it stands - <code>{$name | trim}</code> - and so
does the closing tag of a pair, over everything the pair rendered. The
<a href="?pages/pipes">pipes</a> page has the opening and closing tag pipes in full:</p>

{example 'fragments/expressions_4'}

<h2>Values</h2>

<h3>Numbers</h3>

<p>Whole numbers, decimals, a decimal that starts with its point (<code>.5</code>) and
exponents (<code>1e3</code>, <code>2.5E-1</code>). A minus before a number belongs to it.
<code>0x</code> followed by hexadecimal digits is not a number but a string of bytes:
<code>0x41</code> is the letter A.</p>

{example 'fragments/expressions_5'}

<h3>Strings</h3>

<p>Text stands between single or double quotes, which mean the same: a <code>$name</code>
inside double quotes stays text, it is not filled in as PHP would. A backslash starts an
escape - <code>\n</code>, <code>\r</code>, <code>\t</code>, <code>\\</code>,
<code>\'</code> and <code>\"</code>; any other letter after it is an error. The dot joins
strings, and numbers with them:</p>

{example 'fragments/expressions_6'}

<h3>Bare words</h3>

<p>A word without quotes and without a sigil is looked up. An operator word -
<code>eq</code>, <code>and</code>, <code>not</code> ... - is the operator; a PHP constant -
<code>TRUE</code>, <code>FALSE</code>, <code>NULL</code>, <code>PHP_EOL</code>,
<code>M_PI</code> - is its value; a word that names nothing stands for its own text.</p>

{example 'fragments/expressions_7'}

<p><b>Quote text.</b> A bare word that names something PAD knows - a function, a tag, a
property, a data set, a field - is that thing: <code>count</code>, <code>name</code> and
<code>first</code> are <a href="?pages/properties">properties</a>, so
<code>{echo count}</code> does not write the word count. Text in quotes is always
text.</p>

<h3>Fields, paths and indirection</h3>

<p><code>$name</code> reads a field: a variable the page's PHP set, one a
<code>{set}</code> made, a field of the row a loop stands on. A dot walks into an
array - <code>$user.address.city</code>, and <code>$items.0</code> by position.</p>

{example 'fragments/expressions_8'}

<p><code>$$name</code> reads the field whose name another field holds - a path as well - the
way <code>{$$name}</code> does as a tag. The name must be one of the application's
fields; the engine's own <code>pad...</code> variables are never read this way.</p>

{example 'fragments/expressions_9'}

<p>A field that holds a list is not a value: <code>$items + 1</code> is an error. Walk the
list with a loop, or hand it to a function with the <code>array:</code> prefix, below.</p>

<h3>Options, properties and the placeholder</h3>

<ul>
  <li><code>&#35;name</code> - a parameter or option of the tag; in a
  <code>{define}</code> or a custom tag, the ones the tag was called with</li>
  <li><code>&amp;name</code> - a property of the tag, <code>name@tag</code> a property of the
  tag named - <code>first@items</code>, <code>current@items</code>, <code>count@items</code>
  (see <a href="?pages/properties">properties</a>)</li>
  <li><code>@</code> - the value piped into this part of the expression (see
  <a href="#pipes">pipes</a> below)</li>
</ul>

{example 'fragments/expressions_10'}

<h3>Lists</h3>

<p><code>[ ]</code> makes a list, its items separated by commas, with keys written
<code>key => value</code> where wanted, mixed with plain items as PHP mixes them. A list is
what <code>{set}</code> stores, what a loop walks and what a PHP function

<h2>Operators</h2>

<p>The operators bind in this order, strongest first. Those of one row bind equally and are
applied left to right - <code>10 - 2 + 3</code> is 11 - except <code>**</code>, which binds
right to left. Round brackets group as usual.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>operators</th><th>what they do</th></tr>
  <tr><td><code>**</code></td><td>power, right to left: <code>2 ** 3 ** 2</code> is <code>2 ** 9</code></td></tr>
  <tr><td><code>!</code>, a sign <code>-</code> <code>+</code> before a value</td><td>not, and the signs - weaker than <code>**</code>: <code>-3 ** 2</code> is -9</td></tr>
  <tr><td><code>*</code> <code>/</code> <code>%</code></td><td>multiply, divide, remainder</td></tr>
  <tr><td><code>+</code> <code>-</code></td><td>add, subtract</td></tr>
  <tr><td><code>.</code></td><td>join as text</td></tr>
  <tr><td><code>lt</code> <code>le</code> <code>gt</code> <code>ge</code> - <code><</code> <code><=</code> <code>></code> <code>>=</code></td><td>order</td></tr>
  <tr><td><code>eq</code> <code>ne</code> - <code>==</code> <code>=</code> <code>!=</code> <code><></code></td><td>equal, not equal</td></tr>
  <tr><td><code>not</code></td><td>denies what follows, a comparison included</td></tr>
  <tr><td><code>and</code> - <code>&amp;&amp;</code></td><td>both hold</td></tr>
  <tr><td><code>xor</code></td><td>exactly one holds</td></tr>
  <tr><td><code>or</code> - <code>||</code></td><td>either holds</td></tr>
  <tr><td><code>??</code></td><td>the left side, or the right one when the left is empty or missing</td></tr>
  <tr><td><code>? :</code> and <code>?:</code></td><td>the inline ternary, weakest of all</td></tr>
</table>

<p>The tests <code>in</code>, <code>like</code>, <code>matches</code>, <code>range</code>,
<code>between</code> and <code>contains</code> read infix as well; they have
<a href="#tests">a section of their own</a>.</p>

<h3>Arithmetic</h3>

<p>As in PHP: <code>/</code> answers a decimal when it does not divide evenly, <code>%</code>
works on whole numbers. A text that is a number counts as one - <code>'5' + '5'</code> is 10 -
a text that is not, <code>'a' + 1</code>, is an error, and so is a division by zero.</p>

{example 'fragments/expressions_13'}

<h3>Joining text</h3>

<p>The dot binds weaker than <code>+</code> and <code>-</code>: in <code>1 + 2 . 3</code> the
sum comes first and is then joined with the 3, and in <code>1 . 5 + 5</code> the 1 is joined
with 10. After a value a dot is the join, also right against it - <code>'a'.1</code> - and
only where no value stands before it does a dot start a number.</p>

{example 'fragments/expressions_15'}

<h3>Comparing</h3>

<p>Each comparison has a word and a symbol: <code>eq</code> or <code>==</code> (a single
<code>=</code> too), <code>ne</code>, <code>!=</code> or <code><></code>, and
<code>lt le gt ge</code> or <code>< <= > >=</code>. The words read better in a
template full of HTML. Numbers, and texts that are numbers, compare as numbers -
<code>'2' lt '10'</code> holds; other texts compare character by character, case counting.
PHP's <code>===</code> and <code>!==</code> are not there. A comparison answers
<code>1</code> or nothing:</p>

{example 'fragments/expressions_16'}

<h3>Logic</h3>

<p><code>and</code>, <code>or</code>, <code>xor</code> and <code>not</code>, with
<code>&amp;&amp;</code>, <code>||</code> and <code>!</code> as their symbols. The word
<code>not</code> binds weaker than the comparisons, so <code>not $a eq $b</code> denies the
comparison; <code>!</code> binds as tightly as a sign, so <code>!$a eq $b</code> compares
<code>!$a</code> with <code>$b</code>. <code>and</code> and <code>or</code> stop at a left
side that decides: <code>$n gt 0 and 10 / $n gt 1</code> never divides by zero.</p>

{example 'fragments/expressions_17'}

<h3>A default: ??</h3>

<p><code>a ?? b</code> answers <code>a</code> unless it is empty - <code>''</code>, NULL, FALSE,
an empty list - or a field that does not exist; then it answers <code>b</code>. A 0 is a value
and stays. A field in front of <code>??</code> may be missing, also under the strict check:
giving it a default is what the operator is for. The right side is worked out only when it
is wanted. In a pipe it takes the piped value, and the <code>default</code> function does
the same:</p>

{example 'fragments/expressions_18'}

<h3>The inline ternary</h3>

<p><code>cond ? then : else</code> binds weakest of all: everything before the
<code>?</code> is the condition, and each branch runs to its <code>:</code> or to the end -
<code>0 ? 'yes' : 'no' . '!'</code> joins the <code>'!'</code> to the no. Only the branch
chosen is worked out. Ternaries in a row read from the right, <code>a ? b : c ? d : e</code>
being <code>a ? b : (c ? d : e)</code>. The short form <code>a ?: b</code> answers
<code>a</code> itself when it holds, and with nothing before the <code>?</code> the piped
value is the condition:</p>

{example 'fragments/expressions_19'}

<h2>Truth</h2>

<p>Where a condition is wanted - <code>{if}</code>, <code>where=</code>, the
ternary, <code>and</code> and <code>or</code> - a value is tested as PHP tests it:
<code>''</code>, <code>'0'</code>, 0, NULL, FALSE and an empty list are false, every other
value is true - the texts <code>'0.0'</code>, <code>'false'</code> and a space among
them.</p>

{example 'fragments/expressions_21'}

<p>The comparisons, the tests and the logic operators answer <code>1</code> for true and
<code>''</code> for false: written by {tag 'echo'} a truth is a 1 or nothing at all, and truths
add up as numbers.</p>

{example 'fragments/expressions_22'}

<h2>Functions</h2>

<p>The built-in pipe functions - <code>upper</code>, <code>left</code>, <code>replace</code>,
<code>date</code> and the rest of the {tag 'functions'} list - are used two ways. After a pipe
they take the value on its left: <code>$s | left(2)</code>. Written as a call with nothing
piped in they take it as their first argument: <code>left($s, 2)</code>, as PHP's own
functions do - so they nest, and stand wherever a value can. The number of parameters is
checked.</p>

goes in as the only argument - <code>'abc' | php:strrev</code> - and into a call with

<h2>When an expression is wrong</h2>

<p>Under the strict syntax check - <code>$padCheckSyntax</code>, on by default - a mistake in
an expression is an error that names the fault and its place, and the page answers with the
error report instead of guessing. The report shows the template's file, line and column with
the lines around it (see <a href="?pages/template_errors">errors in the template</a>). What
some mistakes are told:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>written</th><th>the error says</th></tr>
  <tr><td><code>{echo (1 + 2}</code></td><td>the ( opened at position 1 is never closed</td></tr>
  <tr><td><code>{echo 'abc}</code></td><td>the string opened with ' at position 1 is never closed</td></tr>
  <tr><td><code>{echo $name | uppr}</code></td><td>there is no pipe function named 'uppr'</td></tr>
  <tr><td><code>{echo nofunc(1)}</code></td><td>there is no function named 'nofunc'</td></tr>
  <tr><td><code>{if $typo eq 1}</code></td><td>there is no field named '$typo'</td></tr>
  <tr><td><code>{echo $items + 1}</code></td><td>the field '$items' is a list, not a value</td></tr>
  <tr><td><code>{if $n eq}</code></td><td>the operator 'eq' has nothing on its right</td></tr>
  <tr><td><code>{echo $n + * 3}</code></td><td>the operators '+' and '*' stand side by side - a value is missing between them</td></tr>
  <tr><td><code>{if $n === 5}</code></td><td>'===' is no operator - eq (==) compares two values</td></tr>
  <tr><td><code>{echo $n | +1}</code></td><td>a pipe operator needs a space before its operand - write '| + 1', not '| +1'</td></tr>
  <tr><td><code>{echo 5 &amp; 3}</code></td><td>'&amp;' is no operator or value</td></tr>
  <tr><td><code>{if $n not 5}</code></td><td>a 'not' after a value denies a test - write $a not in (...), not like, not matches or not range, or put it in front: not $a eq $b</td></tr>
  <tr><td><code>{echo 7 / 0}</code></td><td>a division by zero in /</td></tr>
  <tr><td><code>{echo 'a' * 2}</code></td><td>'a' is not a number for *</td></tr>
  <tr><td><code>{echo $n ? 'a'}</code></td><td>the ? of an inline ternary has no : - write cond ? then : else</td></tr>
  <tr><td><code>{echo [ 'a' => ]}</code></td><td>the key 'a' of a list has no value after its =></td></tr>
  <tr><td><code>{echo replace('abc')}</code></td><td>the function 'replace' wants 2 parameters after the value it works on - written as a call its first argument is that value: replace($value, ...)</td></tr>
  <tr><td><code>{echo php:str_repeat('x', -1)}</code></td><td>the PHP function 'str_repeat' refused its arguments: str_repeat(): Argument #2 ($times) must be greater than or equal to 0</td></tr>
  <tr><td><code>{echo 'a\qb'}</code></td><td>Unsupported \ char</td></tr>
</table>

<h2>The lenient walk</h2>

<p>With <code>$padCheckSyntax = FALSE</code> in <code>_config/config.php</code> nothing is
reported and the evaluator answers what it can: a text that is no number counts as 0
(<code>'a' + 1</code> is 1), a missing field is empty (<code>$nope + 1</code> is 1), an
unknown escape loses its backslash, and an expression that cannot be worked out at all - a
bracket never closed, a division by zero, a PHP function refusing its arguments - answers
nothing. That suits old templates; a new one is better off with the check, which finds the
typo the lenient walk hides.</p>

{meta title='File uploads'}

<p><code>padUpload</code> takes the file of one form field and stores it safely:</p>

<ul>
  <li>its real type comes from its content - not from the type the browser claims, and not
  from its name - and is held against the types you allow, <code>image/*</code> for any image;</li>
  <li>a file over the size you allow, <code>'2M'</code>, <code>'500K'</code> or bytes, is refused;</li>
  <li>it is stored under a random name in <code>DATA/uploads/</code>, with the extension of
  what it really is, never under the name the visitor's file had.</li>
</ul>

{example 'fragments/file_uploads_1'}

<p>The answer is the record of the stored file - <code>name</code> (the visitor's own file
name, for showing only), <code>file</code> (the path under <code>DATA</code>, for
<code>padFileGet</code>), <code>path</code>, <code>size</code>, <code>type</code> and
<code>extension</code> - or <code>NULL</code> when the field brought no file, or
<code>FALSE</code> when the file was refused. <code>padUploadError ( 'avatar' )</code> says
why, and the {tag 'input'} file field of the form shows it beside itself, in the words of its
label.</p>

<p>A {tag 'form'} holding a file field posts as <code>multipart/form-data</code> by itself;
without that the browser sends only the file's name.</p>

<p>What is stored under <code>DATA</code> no address reaches. A page sends it back with
<code>padUploadSend ( $record ['file'], $record ['name'] )</code>, which answers the file as the
whole page and ends the request: its type read from its content again, a picture, a PDF or
plain text shown, anything else - HTML, SVG, a script, which shown on the site's own address
would run with its rights - downloaded; <code>TRUE</code> as its third argument downloads it in any
case. A path out of <code>DATA</code>, or to no file, answers 404.</p>

{meta title='Flash messages'}

<p>A page that takes a post redirects the browser to a plain page, so a refresh cannot post
twice - and then the page the browser lands on has to say what happened. A flash message
carries that: <code>padFlash ( 'Thanks, your message was sent.' )</code> before the
<code>padRedirect ()</code>, and {tag 'flash'} on the page it leads to.</p>

{example 'fragments/flash_messages_1'}

<ul>
  <li>{tag 'flash'} renders its content once per message, with <code>{$message}</code>
  and <code>{$type}</code>; without a message the {construct 'else'} half renders.
  <code>{flash 'error'}</code> shows the messages of that type only.</li>
  <li>The type is the second argument of <code>padFlash</code>, <code>info</code> when it is
  left out.</li>
  <li>A message lives exactly one request after the one that flashed it - the redirect's
  destination - and is gone after that, shown or not. A page that flashes and renders itself
  shows it at once, as here.</li>
  <li>The message is kept in the session, which starts on demand. A small
  <code>padFlash</code> cookie tells the next request that there is something to take, so the
  pages that never flash do not open the session at all.</li>
</ul>
