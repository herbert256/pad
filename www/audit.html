A broad, fast and currently green behavioral suite with strong baseline hygiene—but not yet an exhaustive or self-proving gate.

Audited 11 August 2026 · commit 582d3b6a0 · PHP 8.5.9 · Apache 2.4.68

Pass with reservations

Current framework behavior is well protected for server-rendered GET paths and template semantics. Do not claim “every page exactly once” yet: one live framework page has no owner, state-changing/request-mode paths sit outside the gate, and the harness itself has false-green states that its self-tests do not exercise.

What is strong

Real HTTP isolation

Cases are fetched as the browser-facing framework sees them rather than evaluated only as in-process helpers. Missing multi-fetch responses are converted to HTTP 999 failures instead of disappearing from totals.

Oracle hygiene

All 1,792 selected rows have exactly one baseline. There are no missing or orphan answer files and no duplicate fetched URLs across suites. The Errors suite pairs expected failures with status and message shape.

Fail-closed command gate

ci.sh rejects missing/unreadable results, non-zero failure counts, new tests and old timestamps. Exact and regex expectations also require a healthy 2xx response.

Useful breadth

Template parsing, expressions, tags, variables, data, sequence behavior, strict/lenient errors, output modes, databases and five cache backends all receive live coverage in this environment.

Findings

P1 · High

The “every page exactly once” invariant is already false

Coverage completeness · confirmed against live HTTP and all result files

http://localhost/pad/regression/framework/?index returns HTTP 200 but appears in no suite result. The Framework enumerator only reads .pad files one directory below its root (regression.php:604–614), while the Regression family deliberately excludes the entire framework application (regression.php:69–83).

The missed page is not benign noise: it still says cases live under _suites/ and are driven through ?run, both stale concepts. A suite ownership check would have caught that drift.

Remedy: explicitly own the root index (add it to Framework, move it to a covered app, or delete it) and add an independent parity assertion from all public renderable endpoints to exactly one direct or declared parent test.

P1 · High

The harness is much less tested than the framework it judges

False-green risk · 737-line runner, six narrow harness cases

Only six Framework cases target the regression harness, and they cover URL/want-file/count helpers. There are no focused negative tests for comparison modes, dropped fetches, discovery, result aggregation, corrupt files, write failure, new/stale states or the shell gate.

The Regression suite’s overview baselines are permissive: suite pages may match never run or any numeric failed count. The main overview pattern does not specifically require the new Errors row. These tests prove that a page has roughly the expected shape, not that the harness verdict is right.

Remedy: add a small pure-PHP harness suite with synthetic work lists and responses, plus black-box command tests that inject one failure, one new page, one missing response, one corrupt result and one stale run.

P1 · High

Stateful request paths sit outside the gate

Coverage boundary · source inventory and request-shape search

An independent page-shaped source scan found 1,922 candidates. The shared walker excludes 24: all 21 Develop endpoints plus demo/todoPost, regression/main/record and structure/index. Some are deliberately excluded because a GET would mutate or redirect, but they remain public behavior without explicit scenarios.

Every suite fetch issued by the runner is a GET. No regression fixture sends POST data, cookies, sessions, file uploads or raw request bodies, despite dedicated framework code for those paths. Client-side React/Ajax behavior is compared as emitted markup; it is not executed.

The action exclusion is also lexical: any PHP-only page containing padRedirect, padRestart, padFilePut or padDeleteDataDir anywhere in its source is silently skipped (apps.php:33–42).

Remedy: replace source-string discovery with an explicit endpoint manifest and add isolated POST/session/cookie/upload/action scenarios with disposable data directories.

P2 · Medium

Human-facing verdicts report false success

Reporting · reproduced with isolated runner probes

getSuitePage() sets the detail verdict from failures only (regression.php:726–731). A result of “1 new” displays all ok; a suite that has never run also displays all ok. The main overview similarly labels “never run” as ok because it checks only failed/new.

1 pages, 1 tests, 0 failed, 1 new  →  all ok
never run                           →  all ok

Remedy: use a single verdict function everywhere: NEVER RUN, FAILURES, NEW, then OK. Unit-test every state.

P2 · Medium

Ordinary CI runs leak generated files

Operational reliability · measured before and after one green run

One ./ci.sh run added 255 files and 1,552 KiB under DATA/dumps (1,276 → 1,531 files; 7,776 → 9,328 KiB). Forty generated files were also standing under DATA/temp. The interactive Fresh build wipes dumps/temp/suites, but CI calls ?index&test and performs no cleanup.

Remedy: give each run an isolated data root and delete it on success, or run bounded pre/post cleanup while retaining only failed-run artifacts. Add a retention cap as a backstop.

P2 · Medium

The HTTP “record” link mutates the test oracle with a GET

Oracle integrity · record.php:11–47

A failure-row link can overwrite an exact baseline in the source tree. The action uses GET, has no confirmation/CSRF token, does not require that the named row is part of the current failing result, and fetches the page again—so a volatile response may differ from the one the reviewer saw.

Remedy: make recording development-only, POST-only and CSRF-protected; show the exact pending diff; bind it to the current result/run ID; validate membership and failure state; then require explicit confirmation.

P2 · Medium

CI results have no run identity and the checkout path is fixed

Reproducibility and concurrency · ci.sh:13–47, home/home.sh:3–7

ci.sh accepts a host but reads results from OS-specific hard-coded paths. Freshness is a seconds-resolution timestamp and accepts equality, so concurrent runs can mix files and a same-second stale result can pass the freshness test. Result writes are not associated with a commit, host or unique run token.

Remedy: derive the repository root from ci.sh, lock one run or use per-run directories, pass a random run ID to the trigger, store it in every result, and verify the ID plus commit after the request.

P2 · Medium

Framework comparisons erase meaningful internal whitespace

Oracle sensitivity · reproduced from regression.php:658–674

The Framework suite removes every newline and all following whitespace from actual output before comparison. The distinct output "a\n b" normalizes to "ab" and passes an ab baseline. This is convenient for one-line engine assertions, but it can conceal newline/spacing regressions.

Remedy: make normalization an explicit per-case mode, default new cases to raw exact comparison, and keep dedicated whitespace-sensitive fixtures in Pages.

P3 · Low

Expectation grammar and documentation need maintenance guards

Maintainability · no current malformed baselines found

For an HTTP expectation, only line two is treated as a pattern; later lines are silently ignored. The audit proved that HTTP 500\n/error/\nunchecked passes. The runner has no schema/lint command for this, although today’s stored expectations are valid.

Documentation has already drifted: the README and Build page still say CI runs seven suites, the overview prose describes a retired scan, and some comments omit Errors. Counts also mix logical catalogue assertions with failed pages, which can understate a catalogue failure.

Remedy: validate each oracle as exactly one supported form; fail invalid regexes/extra lines; derive suite counts/names in UI copy where possible; label failure metrics as pages or assertions consistently.

Recommended order of work

  1. Restore the ownership invariant. Cover or remove regression/framework/?index, then add an independent endpoint-to-suite parity test.
  2. Test the test system. Add deterministic harness and command-gate fault injection before expanding case count further.
  3. Make verdicts impossible to misread. Unify NEVER RUN / FAILURES / NEW / OK across the index, detail pages, JSON and CLI.
  4. Isolate runs. Add run IDs, a repository-relative data path, locking/per-run result directories and cleanup/retention.
  5. Cover request lifecycle and actions. Add explicit POST, cookie, session, raw-body, upload, redirect and source-writing scenarios using disposable fixtures.
  6. Harden oracles. Protect recording, validate expectation files, opt in to whitespace normalization, and record timing/commit metadata.
Release decision: suitable as a local behavioral regression gate today. For shared/concurrent CI or an “exhaustive coverage” claim, close P1 findings first and the run-isolation/artifact-leak findings next.

Method and evidence

Dynamic checks

  • Five complete ./ci.sh executions against local Apache.
  • Direct request to the uncovered Framework root page.
  • Synthetic probes for new/never-run verdicts, discovery false positives, newline normalization and extra HTTP expectation lines.
  • Before/after measurement of dump growth for one passing run.

Static checks

  • Runner, CI, registry, discovery, record and overview code review.
  • Independent inventory of page-shaped sources and suite ownership.
  • Baseline pairing, orphan, duplicate URL, mode and regex validation.
  • PHP syntax check of 287 regression/entry-point files; Bash syntax and ShellCheck review.

Scope: the repository state at commit 582d3b6a02058051882e9cd4be82274c84e9b9d0. This was a regression-system audit, not a proof of line/branch coverage for all 1,014 core PHP files. The repository does not wire source coverage or mutation testing into its gate.
