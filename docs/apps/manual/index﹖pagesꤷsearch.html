Site search

A search box without a search server: {pad:search} finds the rows of a source that match a query and ranks them, the best first. This manual has a little collection of recipes, _content/recipes/ - six Markdown files - and the examples search it live.

PHP
 HTML
fragments/search_1.pad 		Result 
{pad:search 'recipes', q='baking'}
  <p><b>{$title}</b> <small>({$score})</small><br>{!excerpt}</p>
@else@
  <p>Nothing found.</p>
{/pad:search}

Apple pie (0.9)
A classic apple pie: a buttery crust baked golden, filled with sliced apples, sugar and cinnamon. Bake it on the lowest shelf so the bottom crust browns, and let the …

Country bread (0.9)
Flour, water, salt and yeast, kneaded and left to rise twice. The loaf is baked in a very hot oven with steam, so the crust becomes crisp and dark; baking …

Crème brûlée (0.746)
Vanilla custard baked slowly in a water bath, chilled, then topped with sugar that is caramelised under a hot grill until it cracks like glass.

  • The source is a Markdown collection, as {pad:collection} reads it, else a {pad:data} store, a page's array - a db() result - or a _data file of the name.
  • A row found is the source's own row with two fields added: score and excerpt - the words around the first match, every matched word marked. The excerpt is HTML, so it is printed raw, {!excerpt}.
  • baking found baked and Bake as well: every word is reduced to its stem before it is compared.

The query

Words find a row with any of them; the more and the rarer, the higher it ranks. A "phrase" must be there, its words in that order; pre* stands for every word that begins so; -word and -"a phrase" leave a row out. Accents do not count: creme finds the Crème brûlée.

PHP
 HTML
fragments/search_2.pad 		Result 
<ul>
  <li>creme: {pad:search 'recipes', q='creme'}{$title} {/pad:search}</li>
  <li>"hot pan": {pad:search 'recipes', q='"hot pan"'}{$title} {/pad:search}</li>
  <li>lem*: {pad:search 'recipes', q='lem*'}{$title} {/pad:search}</li>
  <li>sugar -apples: {pad:search 'recipes', q='sugar -apples'}{$title} {/pad:search}</li>
  <li>zebra: {pad:search 'recipes', q='zebra'}{$title} @else@nothing{/pad:search}</li>
</ul>
  • creme: Crème brûlée
  • "hot pan": Pancakes
  • lem*: Lemonade Pancakes
  • sugar -apples: Crème brûlée Lemonade
  • zebra: nothing

Fields, languages and PHP

fields='title^2, body' names the fields searched and what each weighs - a collection is searched that way by default. lang is the language: its stop words are skipped and its stemmer makes wandelingen and wandelen one word in Dutch. There are eleven, a file each in pad/subs/search/types/: en, nl, de, fr, es, it, pt, sv, da, no (nb and nn are Norwegian too) and ru, the stemmers of the Snowball project. padSearch does the same for a page's PHP, here over rows of its own:

PHP
fragments/search_3.php 		HTML
fragments/search_3.pad 		Result 
<?php

  $walks = [
    [ 'naam' => 'Langs de dijken', 'over' => 'Fietsen langs de rivier en door de polders.' ],
    [ 'naam' => 'Door de bossen',  'over' => 'Wandelingen en fietstochten door de bossen.' ],
    [ 'naam' => 'Aan zee',         'over' => 'Wandelen over het strand, de wind in de rug.' ]
  ];

  $found = padSearch ( $walks, 'wandeling', [ 'name' => 'walks', 'lang' => 'nl', 'fields' => 'naam^2, over' ] );

?>
 
<ul>
  {array:found}
    <li>{$naam} ({$score}): {!excerpt}</li>
  {/array:found}
</ul>
  • Door de bossen (0.508):Wandelingen en fietstochten door de bossen.
  • Aan zee (0.453):Wandelen over het strand, de wind in de rug.

A list without a template

Written as a single tag the hits are a numbered list: the first field searched as the title, a link when link= names a field with one, and the excerpt - words= sets its length.

PHP
 HTML
fragments/search_4.pad 		Result 
{pad:search 'recipes', q='bread soup', words=12/}
  1. Tomato soup
    … them in stock and blend the soup until smooth. A spoon of …
  2. Country bread
    … crust becomes crisp and dark; baking bread takes patience more than skill.
  • The ranking is BM25: a word found often in a short field counts more than once in a long one, a rare word more than a common one.
  • The index is made the first time a source is searched and kept in DATA/cache/search/; it is made again when a file of the collection changes, or the rows do.
