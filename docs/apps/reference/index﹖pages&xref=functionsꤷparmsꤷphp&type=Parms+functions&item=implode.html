 HTML
pages/forms.pad 		Result 
{meta title='Forms'/}

<p>{tag 'form'/}, {tag 'input'/} and {tag 'textarea'/} write the fields of a form. When the
form comes back with mistakes in it, each field shows again what was typed - escaped - and
the message for its mistake beside it. <code>padValidate</code> in the page's PHP finds the
mistakes.</p>

{example 'fragments/forms_1'/}

<ul>
  <li>{tag 'form'/} posts back to the page and carries the session's CSRF token (see
  {manual 'csrf_protection'/}) and its name: <code>padPosted ( 'contact' )</code> is true when
  this form came back, so a page with two forms knows which one did.</li>
  <li>{tag 'input'/} and {tag 'textarea'/} take the field name first; <code>label=</code> writes a
  label tied to the field, <code>value=</code> the value before anything was posted, and every
  other item is an attribute of the field, as {tag 'attrs'/} writes it - <code>required</code>,
  <code>rows=6</code>, <code>placeholder='...'</code>.</li>
  <li>A checkbox or radio is checked when the posted value is its own value; a password or
  file field is never refilled.</li>
</ul>

<h2>Validation</h2>

<p><code>padValidate ( $rules )</code> checks the posted values and answers one message per
field that breaks a rule, keyed by the field - empty when all is well. A second argument
checks other data; a third replaces messages, per field (<code>'email'</code>) or per field
and rule (<code>'email.required'</code>):</p>

{example 'fragments/forms_2'/}

<p>A rule takes its argument after a colon: <code>min:n</code>, <code>max:n</code> and
<code>between:a,b</code> are a length, or a value with <code>numeric</code> or
<code>integer</code>; <code>in:a,b,c</code> a list, <code>regex:/.../</code> a pattern,
<code>same:other_field</code> another field, <code>digits:4</code> a number of digits. An empty
field is checked for <code>required</code> and <code>accepted</code> only. Every rule is a file of
<code>pad/rules/types/</code> - its check in the browser beside it in <code>pad/rules/assets/</code> -
and these are the {echo php:count(padRuleTypes())/} there are:
{echo php:implode(', ', padRuleTypes())/}. A rule name nothing knows is an error.</p>

<h2>After a failed post</h2>

<p>The fields of the form that came back show the message beside them, in the words of their
own label, tied to the field with <code>aria-invalid</code> and
<code>aria-describedby</code> so a screen reader reads them together. Here the post is
pretended in the PHP, the way a visitor's would arrive:</p>

{example 'fragments/forms_3'/}

<p>After a post that passes, store it and send the visitor on with <code>padRedirect ()</code>:
a refresh of the page they land on does not post a second time.</p>

<h2>Rules in the template</h2>

<p>The rules can stand on the fields themselves: <code>rules='required|email'</code> on an
{tag 'input'/} or a {tag 'textarea'/}. They are read from the page's template before its PHP
runs, and a post of the form is checked against them there - <code>padPosted ( 'contact' )</code>
is true only for a post that kept them, so the PHP acts on a good post alone. A post that broke
one renders the form again, refilled, with the messages beside the fields and the form's
<code>error=</code> above them (<code>error</code> alone says "Please correct the errors
below."):</p>

{example 'fragments/forms_4', skipResult/}

<ul>
  <li>Only what is written out counts: quoted rules, on a field with a quoted name, in a
  {tag 'form'/} with a name that posts back to its own page. Rules on a field in a snippet, a
  custom tag, a {tag 'page'/} or a layout, rules made from a variable, rules in a form with
  <code>action=</code> or <code>method='get'</code> and rules on a file field are errors -
  nothing would check them.</li>
  <li>Every field of the posted form that has rules is checked, also one in an {tag 'if'/}
  branch that did not render. A field that is there only sometimes keeps its check in the
  PHP: <code>padValidate</code> adds its messages to those of the template.</li>
  <li><code>padFormFailed ( 'contact' )</code> is true when the form came back and broke its
  rules.</li>
</ul>

{meta title='Rich form fields'/}

<p>Beside <code>{input}</code> and <code>{textarea}</code> a form can hold
fields that do more: a slider, a row of stars, a switch, a month to choose a day from, a tag input,
a signature, a Markdown editor with its preview. There are {echo php:count(padInputTypes())/} of
them - every kind is a file of <code>pad/inputs/types/</code>, its script and style in
<code>pad/inputs/assets/</code>, and the <a href="../inputs/">inputs</a> application shows them all,
each in a form that posts back.</p>

{example 'fragments/inputs_1'/}

<h2>Two ways to write one</h2>

<p>The input: type names the kind, <code>{input:slider 'volume'/}</code>, and so does
the bare name, <code>{slider 'volume'/}</code>, as long as no tag, store, field or
sequence has that name - an array of the page with a key <code>slider</code> is read first. The
first parameter is the field's name, <code>label=</code> its label, and every other item the kind
does not take is an attribute of its field, as with <code>{input}</code>:
<code>required</code>, <code>placeholder=</code>, <code>autocomplete=</code>.</p>

<h2>A real value, with or without a script</h2>

<p>Every kind writes a native field that a form posts as it is - a range, a number, a date, a
time, a colour, a checkbox, radio buttons, a text field - and its script, written once a page with
the CSP nonce, makes more of it: a month over the date, the times to pick from, swatches beside the
colour. Without the script the form works all the same; only the signature needs it.</p>

{example 'fragments/inputs_2'/}

<p>Some fields post a text of their own making: a tag input the words joined with a comma, the boxes
of a one-time code the code, a signature a PNG as a data URL - each in a field with the name, which
a form without the script fills by hand. Choices come from a list - <code>options=</code>,
<code>suggestions=</code> - from a store named by <code>data=</code>, or a line each between the
tags.</p>

{example 'fragments/inputs_3'/}

<h2>Refilled, with the message beside it</h2>

<p>The fields are fields of the <a href="?pages/forms">{form}</a> around them: after a
post of that form they show what was posted, and the message <code>padValidate</code> left for them
after their frame, in the words of their label. <code>rules=</code> on a field is read from the
template before the page's PHP runs, as on <code>{input}</code>, and <code>client</code>
on the form checks the same rules in the browser. Here the post is pretended in the PHP:</p>

{example 'fragments/inputs_4'/}

<ul>
  <li>The kinds: {echo php:implode(', ', padInputTypes())/}.</li>
  <li>The colours are custom properties on <code>.pad-input</code> - <code>--pad-input-accent</code>,
  <code>--pad-input-line</code>, <code>--pad-input-star</code> and their like - with light and dark
  defaults.</li>
  <li>A password is never refilled, a file field cannot be, and the rules of a drop zone are
  <code>padUpload</code>'s.</li>
</ul>
