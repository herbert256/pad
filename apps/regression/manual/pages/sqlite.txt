<p>The application database is MySQL by default. One setting makes it SQLite: a single file,
no server to install, which is all a small application or a test needs.</p>


<pre><code># apps/myapp/.env - read with padEnv, as every database setting is

padSqlDriver=sqlite
padSqlDatabase=myapp/myapp.sqlite          # under DATA/
padSqlSetup=_install/schema.sql            # builds it the first time</code></pre>


<p><code>$padSqlDatabase</code> is the file - a relative name lives under <code>DATA/</code>.
<code>$padSqlSetup</code> is optional: a <code>.sql</code> file in the application that is run
once, when the database file does not exist yet, so the first request builds the database
from text kept with the application.</p>

<p>Nothing else changes. The page below is one of the <a href="?pages/database">database</a>
examples, which this manual runs on MySQL - with the settings above it runs unchanged on
SQLite:</p>

<ul>
  <li>The <code>db()</code> verbs answer in the same shapes - <code>field</code>, <code>record</code>,
      <code>array</code>, <code>check</code>, <code>insert</code> with the new id,
      <code>update</code> and <code>delete</code> with the rows they touched.</li>
  <li>The <code>{0}</code> placeholders escape the way SQLite needs: a quote is doubled,
      so a value never ends its literal early.</li>
  <li>The database tags, named <code>_data/*.sql</code> queries and the Select subsystem work as
      they do on MySQL.</li>
  <li>The SQL is SQLite's own: <code>||</code> joins strings, a key is
      <code>integer PRIMARY KEY AUTOINCREMENT</code>.</li>
</ul>
