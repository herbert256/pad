Games

{game} puts a little game on the page that is played in the browser. The server checks what the game is given and writes its board; the game's script, written once per page, plays it. There are 18 of them - every game is a file of pad/games/types/, and the games application plays them all.

PHP
 HTML
fragments/games_1.pad 		Result 
{game 'memory', pairs=6/}
Memory

Three ways to write one

The tag names the game: {game 'tictactoe'/}. The game: type does the same, {game:tictactoe/}, and so does the bare name, {tictactoe/}, as long as no tag, store, field or sequence has that name. opens='computer' lets the computer open, two makes it a game of two players at one screen.

Words, questions and pictures

The games that play with words, questions or a picture take them between their tags, a line each, as they are written - braces and all. A quiz line is the question with its answers after a bar, the right one first; they are shuffled when shown.

PHP
 HTML
fragments/games_2.pad 		Result 
{quiz}
  Which tag repeats its content? | {while} | {if} | {set}
  How is a single tag written? | with a slash | with a colon | with a hash
  Where do an application's own tags go? | _tags | _lib | _data
{/quiz}
Quiz

The same list can come from the page: data= names a store, an array of the page or a _data file, as a chart's data does.

fragments/games_3.php 		HTML
fragments/games_3.pad 		Result 
<?php

  $words = [ 'template', 'pipe', 'field', 'option', 'level' ];

?>
 
{scramble data='words', rounds=3/}
Word scramble

The same game every time

seed= makes a game's shuffles, boards and puzzles the same on every load - a page can say which sudoku it hands out. Without a puzzle the sudoku makes a new one with one solution; givens= says how many squares it shows. paper draws a sudoku or a crossword to print instead, with no script, and solve - solution for a crossword - fills in the answers.

PHP
 HTML
fragments/games_4.pad 		Result 
{sudoku givens=34, seed=2026/}
Sudoku
  • When a game ends its board carries data-result="won" or "lost", and a pad-game-end event goes up from it - a page can count the games won.
  • The colours are custom properties on .pad-game - --pad-game-accent, --pad-game-good, --pad-game-bad and their like - with light and dark defaults.
  • The script carries the CSP nonce, as the interactive tags' scripts do, and a game a fragment or a live region brings later starts as well.
