{pad:ai} puts the answer of a language model in the page. What stands between the tags renders first - fields, loops, anything - and what it rendered is the prompt; the answer comes back as text. It is a value, never template code: markup in it is shown, not run, and so is a PAD tag:

PHP
fragments/ai_1.php 		HTML
fragments/ai_1.pad 		Result 
<?php

  // Anthropic is not asked here: a fake answers in the shape of its Messages API, as a test
  // answers it. In an application the key stands in .env as ANTHROPIC_API_KEY; here it is
  // put where padEnv finds it first.

  $_ENV ['ANTHROPIC_API_KEY'] = 'sk-example';

  padCurlFake ( [ 'https://api.anthropic.com/v1/messages' => [ 'data' => [
    'stop_reason' => 'end_turn',
    'content'     => [ [ 'type' => 'text', 'text' => 'Two friends trade pots of <b>jam</b> & {stories} across one long winter.' ] ] ] ] ] );

  $body = 'All winter long Ann and Bo swapped jars of jam over the fence, and with every jar a story.';

?>
 
<p>{pad:ai provider='anthropic', ttl=86400}Summarise in one sentence: {$body}{/pad:ai}</p>
{php:padCurlFakeStop/}

Two friends trade pots of <b>jam</b> & {stories} across one long winter.

The answer is kept: the same provider, model, system prompt and prompt on a later request is the same answer, no request made - for an hour unless ttl= says otherwise, never with ttl=0. A failed answer is never kept.

From PHP

padAi ( $prompt, $options ) asks the same from a page's PHP and answers the text - here Ollama, which runs a model on this machine and needs no key:

PHP
fragments/ai_2.php 		HTML
fragments/ai_2.pad 		Result 
<?php

  // Ollama runs a model on this machine and needs no key - here a fake answers in its shape,
  // and padCurlRecorded shows what was sent.

  padCurlFake ( [ 'http://127.0.0.1:11434/api/chat' => [ 'data' => [ 'message' => [ 'role' => 'assistant', 'content' => 'Loire, Seine, Rhone.' ] ] ] ] );

  $rivers = padAi ( 'Name three rivers of France.', [ 'provider' => 'ollama', 'system' => 'Answer in one line.', 'tokens' => 40 ] );

  $sent     = json_decode ( padCurlRecorded () [0] ['post'], TRUE );
  $messages = $sent ['messages'];

  padCurlFakeStop ();

?>
 
<p>{$rivers}</p>
<p>Sent to {$sent.model}: {array:messages}<i>{$role}</i>: {$content} {/array:messages}</p>

Loire, Seine, Rhone.

Sent to llama3.2: system: Answer in one line. user: Name three rivers of France.

Providers and options

Every provider is a file of pad/subs/ai/types/ - anthropic, bedrock, cloudflare, cohere, gemini, lmstudio, mistral, ollama, openai - with its endpoint, its headers, the request it builds and how it reads the text and an error out of the answer. A provider is added by adding its file.

  • provider= names one - else PAD_AI_PROVIDER from .env, else anthropic. Its key is a .env value: ANTHROPIC_API_KEY, OPENAI_API_KEY, MISTRAL_API_KEY, GEMINI_API_KEY, COHERE_API_KEY, CLOUDFLARE_API_TOKEN (and the account in CLOUDFLARE_ACCOUNT_ID), AWS_BEARER_TOKEN_BEDROCK (and the region in AWS_REGION); Ollama's address OLLAMA_HOST, while LM Studio needs no key unless it is set up to, LM_API_TOKEN then.
  • model= the model - claude-opus-5-5 for Anthropic unless given; system= the system prompt; tokens= the most the answer may take - the handling option max is something else.
  • A missing key, an unknown provider or an error of the API - a refused key, a limit, a refusal - is an error under the strict check, so it shows while the page is written. Without it the tag answers nothing, the page goes on, the error is logged and padAiError () says it.
  • A test answers the provider with padCurlFake, as the examples here do; while the fetches are faked no answer is kept.
