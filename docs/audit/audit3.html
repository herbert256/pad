PAD, audited and fixed

Two audits and a bug hunt had already closed most of what was wrong. This third pass split the repository into twelve areas and hunted each one in parallel, each in its own worktree against its own server, reading every line. Every bug became a commit of its own, with a regression case that fails on the code before it. Two review rounds then went over the merged fixes, and a final one over the last of them. Each review found fixes that broke something or left a sibling path open, and those came back as further commits.

Each promise the second audit found broken is now kept on every path the hunts and three review rounds could find:

  • A value stays text, through tags, pipes, parameters, stores, splices, markdown and the attribute helpers.
  • The engine's own globals and secrets cannot be read from a template, by name, by indirection, by position or by wildcard.
  • A data name stays in _data/.
  • The engine's requests to itself go to this server and carry no local trust.
  • The developer applications answer this machine only.

What is left is listed under Found and not fixed, each with its reason. Most are deliberate design (an author's own SQL, an author's own data=$url), environment limits, or edges no visitor reaches.

What was found

The hunts found the same kinds of fault the earlier audits did, at edges those fixes had not reached:

  • Values running as code: custom-tag parameters, glued and bare splices, opening pipes, print options, {content}, {bool} and {data} stores, {meta layout=}.
  • Reading what a template should not: engine globals through $$x, the @ path, dotted paths, positions and *; superglobals; the configuration source in error reports.
  • Escaping: the stand-in quote characters a request can send, markdown links (javascript: behind entities and control characters), {attrs} arrays, {trans} substitutions.
  • Trust: self-fetches addressed by the visitor's Host; forwarded or rebound requests taken for local; developer tools and the regression runner acting on any GET.
  • CSRF: token handed to off-site actions through attribute parsing, entities, formaction, <base> and forms hidden in scripts or comments.
  • Performance: quadratic markdown, Tidy and placeholder paths; sequences that recursed or regenerated per candidate.
  • Correctness: the sign's precedence, sort stability, MySQL numeric text, date modifiers, locale negotiation, the sequence types at the integer and float edges.
  • Documentation: about a hundred claims in CLAUDE.md, docs/ and the manual that the engine contradicted.

Method

Hunting

  • Twelve areas split by directory, never by concept: an earlier fan-out had two hunters fix the same bug in different places. Each hunter owned an explicit list of files; anything outside went to its owner as a note.
  • Each hunter had its own git worktree, branch audit3-<area>, and its own php -S server (PAD_HOME pointed at the worktree), so twelve sets of edits never met until the merge.
  • Each bug went case-first: the regression case was written and seen to fail on the unfixed code, then the fix, then the whole gate (./ci.sh: eight suites, the editor lists, the LSP, MCP and Tree-sitter checks and the application tests), then one commit.
  • Findings outside an area were sent to its owner. When an owner had finished, it was resumed with the item.

Merging and reviewing

  • Each finished branch was cherry-picked onto master and the full gate run on Apache, the canonical setup. A red gate stopped the merge until it was understood. Where two parallel fixes collided, a reconciliation commit was made (the coordinator rows).
  • Review round 1 read the 287 commits merged first, in three groups. Round 2 read the 157 that followed, mostly the round-1 fixes. A final round read the last 55. Every reviewer reproduced each finding against the commit's parent on its own server, and every finding went back to its area's hunter as a further wave.
  • Severity in the tags is the hunter's, checked at merge.

Two review rounds

A green gate says a fix broke none of the cases that exist. The reviews looked for what no case covers. Each reviewer read its commits, reproduced every finding on its own server against the commit's parent, and classified it as a regression, an incomplete fix (a sibling path left open), a collision between two fixes, or a case that cannot fail.

What the reviews caught

  • Regressions: protected parameters that made htmlspecialchars miss quotes, which turned the documented button tag into an XSS; an indirection check that reopened engine names; an opening-pipe fix that killed the author's own tags; the CSRF attribute parser handing the token to an off-site action; a localDate that moved dates by a day; a minus space added inside quoted SQL literals; a quadratic placeholder fill.
  • Incomplete fixes: the same sink reached by another spelling, such as a BOM before a PAD list, a wildcard or ordinal first step, a control-character entity in a markdown link, or another attribute.
  • Collisions: two hunters fixing H2 in two places, {?$x} encoding against the indirection refusal, the @-path hardening against multibyte keys. Each was reconciled in one commit.
  • Weak cases: a restart case that passed by a 74-byte accident, a recaman case that only timed out, and a track case that raced its recorder.

Found and not fixed

Each item was reproduced, or is marked suspected. It was left either because it is the documented design, because a fix would be a redesign rather than a bug fix, or because nothing a visitor can send reaches it.

Request, session and security helpers

  • A POST naming a live region the page lacks (padLive=x) is an error: the code intends it, as for a missing fragment.
  • A regex: rule whose pattern does not compile rejects every value. It fails closed.
  • A template rule cannot hold | inside a regex. It is reported as an unknown rule.
  • The live-region script carries no CSP nonce: the engine adds no nonce to its own inline scripts, by design.
  • padBack follows a Referer holding ... Browsers normalise it before sending.
  • Suspected: a race creating the crypt key file on a filesystem without hard links. The cache sweep's inode check could be fooled by inode reuse on ext4 or tmpfs; the lock covers the case seen here.

Request lifecycle: bootstrap, routing, assembly, output, page cache

  • A case variant of the application name (/pad/TEST/) is taken as is on case-insensitive filesystems. It points at the same files, and no access check depends on it (audit2 L9).
  • The session id rides the PAD header and is accepted from the query. It is a tracking id and authorises nothing.
  • An Apache site on a port other than 80/443 without a proxy must now list name:port in $padHosts (or set $padHostBase) for its self-fetches. This is the price of the Host-port fix, and CLAUDE.md says so.
  • A stop= a sequence never reaches still renders up to a million rows (about 20 s). The run itself is bounded by $padSeqMaxSeconds.

Database, Select, data readers, remote fetches, handling options

  • Suspected: data/html.php and data/_lib/xml.php call new tidy without a class_exists check. Tidy is built into this PHP, so this could not be tested.
  • Replay does not count SQLite PRAGMA/VACUUM/ATTACH or SELECT … INTO OUTFILE as writes: rare, and PRAGMA also reads.
  • A value starting with http: given to data= is fetched. That is the documented feature, and a template that passes request input there owns the URL.
  • The {xN} placeholder keys are raw by design. A three-part select name a.b.c keeps only a. A repeated CSV header name: the later column wins.
  • On MySQL, numeric text in an ORDER BY/GROUP BY item is a column position, so a request value there must name a selected column. This is now documented in DATABASE.md.

Built-in tags, options, markup libraries

  • An unquoted field spliced into the SQL of {field}/{record}/{array}/{check} can be injected. The author writes that SQL and the tags cannot bind, so DATABASE.md tells authors to quote.
  • A value holding a {stack} marker is filled with that stack's text. It only duplicates the author's own pushes.
  • Two fills for one slot: the second wins silently. A _content folder whose path holds [ ] finds no files (glob).
  • Markdown pairs emphasis left-first rather than by CommonMark's rules: a subset renderer, safe. {case} compares loosely, as eq does.

PHP helper library

  • NAN as a key prefix, sort direction or flatten depth warns or does nothing, and sorting rows that mix objects and numbers warns. These are PHP's own comparison rules.
  • number_format with a precision near 100 allocates that much (capped at 100). Plural nouns outside the irregular list follow the general rules.

Error handling, info modes, events, developer aids

  • The toolbar's SQL lines are not redacted. They are shown to this machine only.
  • The trace flags for eval, var and parse name hooks nothing calls.
  • track_session keeps the raw session id, because it is that table's key.
  • padNoCurl, used without ext-curl, sends no headers, so it carries no non-local marker either.

Expression evaluator, fields and pipe functions

  • escape('js'|'attr'|'css') on invalid UTF-8 drops the character after the broken byte. The output stays safe.
  • An expression of about 3000 operators takes 14 s. Only a template author can write one, and the cure is a refactor.
  • A page value of INF reads as not found, because INF is the resolver's own not-found marker.

Sequence subsystem and the sequence application

  • Recurrence types ignore increment=, as build/types/order.php documents. Honouring it would mean redesigning how skip and try count.
  • The substract.pad pages keep the old type name: renaming them would move 44 tracked harvest files.
  • Membership far past the ceiling, for types with no closed form, is still decided by generating, so it can take until the time limit. recaman membership past its table cannot be bounded, because recaman is not monotonic.

Developer applications

  • The Host checks of develop, the builds and the playground take localhost, 127.0.0.1 and [::1] only. A checkout served under an /etc/hosts alias gets 403. This was a deliberate trade against DNS rebinding.
  • examples/?show serves the harvested HTML raw, which is the applications' own rendered output. The playground may use {curl}, {page} and {files} locally.

Editor tooling, CI, the regression runner, small applications

  • The suites need a server with more than twelve workers: the runner fetches twelve pages at once, and many of them fetch the server again. pad serve's default 4 workers, or php -S with 8, deadlock under ./ci.sh.
  • The lint accepts a pattern answer that matches anything, and nothing detects an answer file with no page. Neither exists in the stores today.
  • ci.sh lists the eight suites by hand, and its commit stamp ignores uncommitted changes.
  • The Tree-sitter scanner's saved state holds as many open tag names as fit in 1,024 bytes.
