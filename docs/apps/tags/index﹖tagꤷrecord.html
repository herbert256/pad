Tags/Database/record

{record}

Runs a SQL query on the application database and renders its content with the first row's columns as fields.

Database Tag pairs

Syntax 

{record "* from table where ..."} ... {/record}
{record "* from users where id=5", name='user'} ... @else@ ... {/record}

Parameters

sql
The query after the word SELECT - "* from users where id=5".

Options

name
In the designer preview (&padSample) the sample's row of that name answers instead of the database; a capture records the database's answer under it.

Description

{record "..."} runs its parameter as a query and renders its content once, with the columns of the first row as fields - the template form of db ( "RECORD ..." ). The tag name is the command word, so the parameter starts after the SELECT: {record "* from users where id=5"}.

When the query finds no row the content does not render; an @else@ in it gives the text for that case - "no such customer". Inside, {fields@record} iterates the columns as $name / $value pairs, for a generic detail view.

{record} shares its implementation with {field} and {array}. A value from the request belongs in a placeholder of the page's PHP - $user = db ( "RECORD * FROM users WHERE id={0}", [ $id ] ); - and then {user}...{/user} renders the same way.

Examples

One row

The content renders once, with the columns of the first row as fields; @else@ when there is none.

Templateexamples/record/1-one.src 
{record "name, email, city from customers where id=103"}
  <h3>{$name}</h3>
  <p>{$email}, {$city}</p>
@else@
  <p>No such customer.</p>
{/record}

Every column

fields@record walks the columns of the row as name and value.

Templateexamples/record/2-fields.src 
{record "* from products where code='S10_1678'"}
  <dl>
    {fields@record}<dt>{$name}</dt><dd>{$value}</dd>{/fields@record}
  </dl>
{/record}

See also

  • {array} Runs a SQL query on the application database and repeats its content once per row.
  • {field} Runs a SQL query on the application database and prints the single value it answers.
  • {check} Asks the application database whether a row exists, and renders its content only when one does.
