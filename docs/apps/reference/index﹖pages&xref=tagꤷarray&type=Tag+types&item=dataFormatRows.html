Reference - Tag types - dataFormatRows

App: tags - Page: tag/data
PHP
tag/data.php 		HTML
tag/data.pad 		Result 
<?php

  $tagAbout   = 'Reads a supported data format, a list or a range into a named data set for a later tag to iterate.';
  $tagGroup   = 'values';
  $tagForm    = 'both';

  $tagSyntax  = <<<'PAD'
{pad:data 'name'} ... {/pad:data}
{pad:data 'name', type='csv'} ... {/pad:data}
{pad:data 'name', format='toml'} ... {/pad:data}
{pad:data 'name', source/}
{pad:data} ... {/pad:data 'name'}
PAD;

  $tagParms   = [
    'name'   => 'The name the data is kept under; <code>{data:name}</code> ... <code>{/data:name}</code> (or <code>{data:name}</code>) iterates it. Not the name of a built-in or application tag.',
    'source' => 'Optional, when there is no content: the data as a value - <code>\'1..5\'</code>, <code>\'["a","b"]\'</code> - or a field holding it.' ];

  $tagOptions = [
    'type' => 'The reader to use explicitly: a data format, <code>list</code> or <code>range</code>.',
    'format' => 'The format to read, also accepted as <code>type=</code>: ' . appSubsystemLinks ( 'format' ) . '.' ];

  $tagSee     = [ 'content', 'bool', 'set', 'tree', 'count' ];

  $dataFormatRows = [];
  foreach ( padKinds ( 'formats' ) as $kind ) {
    $definition = padFormatDef ( $kind );
    $dataFormatRows [] = [ 'name' => $kind, 'link' => "kind/format/$kind",
                           'extensions' => implode ( ', ', $definition ['extension'] ?? [] ),
                           'reads' => isset ( $definition ['read'] ) ? 'yes' : 'no',
                           'writes' => isset ( $definition ['write'] ) ? 'yes' : 'no',
                           'about' => appSubsystemCatalog () ["format:$kind"] ['about'] ];
  }

?>
 
{pad:ignore}
<p><code>{pad:data 'name'}</code> ... <code>{/pad:data}</code> reads its content as data and keeps it
under that name; it prints nothing. A later <code>{data:name}</code> ... <code>{/data:name}</code>
iterates it like any page array - fields, properties, the handling options
(<code>sort</code>, <code>where</code>, <code>first</code> ...) - and so do
<code>data='name'</code> on another tag, <code>{data:name}</code>, <a href="?tag/tree">{pad:tree}</a>
and the <code>lookup</code> pipe.</p>

<h3>Formats</h3>
<p>The format is recognised from the content itself:</p>
<ul>
  <li><strong>JSON</strong> - starts with <code>[</code> or <code>{</code>. An array of objects
  gives rows with fields; a plain array gives values, read with <code>{$name}</code>.</li>
  <li><strong>XML</strong> - starts with <code><</code>. The elements under the root are the
  rows, their attributes and child elements the fields.</li>
  <li><strong>YAML</strong> - starts with <code>---</code>, or with a <code>- item</code> or
  <code>key: value</code> line. It needs PHP's yaml extension.</li>
  <li><strong>A list</strong> - <code>('a', 'b', 2 * 3)</code> in parentheses: every element is
  evaluated as an expression.</li>
  <li><strong>A range</strong> - <code>1..10</code> or <code>a..z</code>.</li>
  <li><strong>CSV</strong> - anything else of several lines: the first line names the fields,
  each further line is a row.</li>
</ul>
<p>When the start does not tell, <code>format='toml'</code> or <code>type='csv'</code> names the reader explicitly. A one-line
name of a file in the application's <code>_data/</code> directory reads that file.</p>

<h3>Other forms</h3>
<p>Without content, a second parameter is the source: <code>{pad:data 'steps', '1..5'}</code>. A
value from a field there is data, never template: a field holding a parenthesised list is
refused, since its elements would run as expressions. With the name on the closing tag -
<code>{pad:data}</code> ... <code>{/pad:data 'name'}</code> - the content is rendered first and the
result read as data, so fields and tags inside it are resolved.</p>

<p>Content with braces - JSON objects - is read as written: a JSON object in the content is
not taken for a tag. Under the strict syntax check a <code>{pad:data}</code> without a name is an
error, and so is a name that is already a built-in or application tag, since
<code>{data:name}</code> would never reach the store.</p>
{/pad:ignore}

<p>A file of <code>_data/</code> selects its reader by extension, for example
<code>{local:delivery.toml}</code> or <code>{local:sales.xlsx sheet='Notes'}</code>.
XLSX is binary: keep it in a file or pass the original bytes to <code>padFormatRead</code>;
do not paste it into a template. JSON text sequences use the <code>jsonseq</code> format
name explicitly because they have no registered file extension.</p>
<p>From PHP, <code>padFormatRead ( 'toml', $contents )</code> reads a document and
<code>padFormatWrite ( 'toml', $data )</code> writes one. A page can return its exposed data
with <code>padFormat=toml</code>. These helpers parse or serialize data; the separate
list and range readers are template expressions, not interchange formats.</p>
{/pad:ignore}
