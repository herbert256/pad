Diagrams

{diagram} draws a diagram from a few lines of text between its tags, written the way Mermaid writes them, and lays it out on the server as inline SVG. There is no JavaScript, so a diagram prints, works in an e-mail and caches like any other output, and the same lines always draw the same picture. There are 9 kinds - every kind is a file of pad/diagrams/types/, and a flowchart is the one drawn when the tag names none.

PHP
 HTML
fragments/diagrams_1.pad 		Result 
{diagram title='Handling an order'}
  A([Order placed]) --> B{In stock?}
  B -->|yes| C[Take payment] --> D((Shipped))
  B -.->|no| E[(Supplier)] -.-> B
{/diagram}

A line of a flowchart is a chain of nodes and edges. The brackets give a node its shape - [box], (rounded), {decision}, ((circle)), [(database)] - and the arrow its line: -->, -.-> dashed, ==> thick, --- without a head, a label between bars. The lines are taken as they stand, so their braces need no {ignore}.

Three ways to write one

type= names the kind: {diagram type='state'}. The diagram type does the same, {diagram:state}, and so does the bare name, {state}, as long as no tag, store, field or sequence has that name. sequence and tree are tags of their own, so those two kinds are written {diagram:sequence} and {diagram:tree}. A first line written the Mermaid way - sequenceDiagram, stateDiagram-v2, classDiagram, erDiagram, gitGraph - names the kind as well, so a diagram copied from Mermaid draws as it is.

Messages and states

A sequence diagram puts the participants side by side and the messages between them from top to bottom, with notes and frames for loops and alternatives. A state diagram draws a machine: [*] is its start on the left of an arrow and its end on the right, a label follows the colon, and a state can be a choice or a fork.

PHP
 HTML
fragments/diagrams_2.pad 		Result 
{diagram:sequence title='Paying an order'}
  participant S as Shop
  participant B as Bank
  S ->> B: Charge 42.00
  alt Enough funds
    B -->> S: Approved
  else Declined
    B -->> S: Refused
  end
{/diagram:sequence}
PHP
 HTML
fragments/diagrams_3.pad 		Result 
{diagram:state title='A ticket'}
  [*] --> Open
  Open --> Working : take
  Working --> Open : give back
  state Done <<choice>>
  Working --> Done : finish
  Done --> Closed : accepted
  Done --> Working : rejected
  Closed --> [*]
{/diagram:state}

Classes and tables

A class diagram draws a box of three parts for every class - its name, its fields, its methods - and the relations between them: <|-- inherits, *-- is made of, o-- holds, ..> depends on, with the multiplicities in quotes. The parent and the whole are laid out above. An entity-relationship diagram draws every entity as a table of its attributes and the relations with the feet of a crow: || exactly one, o{ zero or more, |{ one or more.

PHP
 HTML
fragments/diagrams_4.pad 		Result 
{diagram:class title='Shapes'}
  class Shape {
    <<abstract>>
    +area()* double
  }
  class Circle {
    +double radius
  }
  class Square {
    +double side
  }
  Shape <|-- Circle
  Shape <|-- Square
  Drawing o-- "*" Shape : holds
{/diagram:class}
PHP
 HTML
fragments/diagrams_5.pad 		Result 
{diagram:er title='Orders'}
  CUSTOMER ||--o{ ORDER : places
  ORDER ||--|{ LINE : contains
  CUSTOMER {
    int id PK
    string name
  }
  ORDER {
    int id PK
    int customer FK
  }
{/diagram:er}

Hierarchies

A mind map and a tree read their hierarchy from the indentation: a line is a node, and a line indented under another is its child. The mind map shares the branches of its root over two sides, each in a colour its twigs keep; the tree stands top down, every box centred over its children - direction='LR' lays it on its side.

PHP
 HTML
fragments/diagrams_6.pad 		Result 
{mindmap title='PAD'}
  PAD
    Templates
      Tags
      Pipes
    Data
      Database
      Sequences
    Output
      Charts
      Diagrams
{/mindmap}
PHP
 HTML
fragments/diagrams_7.pad 		Result 
{diagram:tree title='The company'}
  Board
    Sales
      North
      South
    Engineering
    Finance
{/diagram:tree}

Journeys and commits

A user journey puts the steps of a day in a row, a face under each at the height of its score from 1 to 5, and a dot for everybody who takes the step. A commit graph draws the commits of a repository on the lanes of their branches, with the branches leaving and the merges joining.

PHP
 HTML
fragments/diagrams_8.pad 		Result 
{journey}
  title Ordering online
  section Choose
    Find the product: 4: Customer
  section Buy
    Pay: 3: Customer, Bank
    Get the parcel: 5: Customer, Courier
{/journey}
PHP
 HTML
fragments/diagrams_9.pad 		Result 
{gitgraph title='A release'}
  commit id: "Start"
  branch develop
  commit id: "Feature"
  checkout main
  commit id: "Hotfix"
  merge develop tag: "v1.0"
{/gitgraph}
  • The SVG has role="img", a <title> - title=, else the name of the kind - and a <desc> that says every edge, message, relation or step in words, so a screen reader hears the whole diagram.
  • The colours are custom properties on .pad-chart-diagram - --pad-diagram-node, --pad-diagram-border, --pad-diagram-edge and their like - with light and dark defaults; the mind map, the journey and the commit graph take the colours of the charts.
  • A kind reads only the options it draws with: direction on a sequence diagram is an option nothing reads, and a line a kind cannot read is an error that names the line.
  • A diagram without nodes answers nothing, so its @else@ shows.
