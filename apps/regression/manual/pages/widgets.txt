<p><b>{widget}</b> puts an interactive part on the page - tabs, an accordion, a carousel, a modal,
a dropdown, a toast and more, 17 of them. Every one is built on

and it is written once per page with the CSP nonce. Every widget is a file of
<code>pad/subs/widgets/types/</code>, and the files there are the widgets there are.</p>

<h2>Three ways to write one</h2>

<p>The tag names the widget, and its second parameter is the widget's own first:
<code>{widget 'toast', 'Saved'/}</code>. The widget: type does the same,
<code>{widget:toast 'Saved'/}</code>, and so does the bare name,
<code>{toast 'Saved'/}</code>. The bare name comes after every other kind of tag:
a store, a field or an array of the name wins, so a page's <code>$tabs</code> array is the data
of <code>{tabs}</code>.</p>

<h2>What the browser does itself</h2>

<p>Each widget stands on what HTML and CSS can do: radio buttons and CSS for tabs and the wizard,
<code>&lt;details&gt;</code> for the accordion, a <code>&lt;dialog&gt;</code> for the modal, the
drawer and the toast, the <code>popover</code> attribute for the dropdown, <code>:hover</code>
and <code>:focus-within</code> for the tooltip, <code>:target</code> for the carousel's links and
the lightbox, the CSS resize grip for a split pane. The keyboard works because the browser's own controls are underneath; the scripts
add the arrow keys of a menu, Escape on a tooltip, the focus of a lightbox, the bar of a split
pane.</p>
