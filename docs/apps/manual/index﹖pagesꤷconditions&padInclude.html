The {pad:if} pair renders its content when its expression holds, with as many {pad:elseif} branches as needed and an {pad:else} for when none did:

PHP
HTML
fragments/conditions_1.pad 		Result 
{format:auto 'nums'}[3, 7, 12]{/format:auto}
{data:nums}
  <p>{$nums} is
  {pad:if $nums lt 5}
    small
  {pad:elseif $nums lt 10}
    medium
  {pad:else}
    large
  {/pad:if}
  </p>
{/data:nums}

3 is small

7 is medium

12 is large

A bare value is tested for its truth. {pad:if $flag} holds unless the value is empty, 0, '0' or FALSE - the truth PHP gives it; write a comparison when a particular value is meant: {pad:if $count eq 0}.

Case and when

When one value decides between several branches, {pad:case} reads better than a chain of elseifs. Each {pad:when} names a value, and {pad:else} catches the rest:

PHP
HTML
fragments/conditions_3.pad 		Result 
{pad:set $light = 'green'/}
{pad:case $light}
  {pad:when 'red'}Stop
  {pad:when 'yellow'}Caution
  {pad:when 'green'}Go
  {pad:else}Unknown
{/pad:case}
 Go

A {pad:when} may list several values, separated by commas; it answers when any of them matches:

PHP
HTML
fragments/conditions_7.pad 		Result 
{format:auto 'days'}["Saturday","Monday","Sunday"]{/format:auto}
{data:days}
  <p>{$days}: {pad:case $days}{pad:when 'Saturday', 'Sunday'}weekend{pad:else}a working day{/pad:case}</p>
{/data:days}

Saturday: weekend

Monday: a working day

Sunday: weekend

The ternary

Inside an expression tag, ? and : pick one of two values - the usual way to give alternating rows their class, together with the iteration properties:

PHP
HTML
fragments/conditions_4.pad 		Result 
{format:auto 'fruit'}["apple","pear","plum"]{/format:auto}
{data:fruit}
  <p class="{property:odd@fruit ? odd : even/}">{$fruit}</p>
{/data:fruit}

apple

pear

plum

Inside an expression

An expression has a ternary of its own, cond ? then : else, the weakest binding there is. a ?? b answers a unless it is empty or a field that is not there - so it gives a field its default - and the tests in, like, matches and range read infix:

PHP
fragments/conditions_6.php 		HTML
fragments/conditions_6.pad 		Result 
<?php

  $count   = 3;
  $heading = '';
  $code    = 'NL1234';
  $state   = 'pending';

?>
 
<p>{$count} {pad:echo $count eq 1 ? 'item' : 'items'/}</p>
<p>Title: {$heading | ?? 'Untitled'} - subtitle: {pad:echo $subtitle ?? 'none'/}</p>
<p>Code {$code} {pad:if $code matches '/^[A-Z][A-Z][0-9]+$/'}is{pad:else}is not{/pad:if} well formed</p>
<p>State {$state} {pad:if $state in ('active', 'pending')}is open{pad:else}is closed{/pad:if}</p>

3 items

Title: Untitled - subtitle: none

Code NL1234 is well formed

State pending is open

Properties in conditions

The iteration properties read as values inside an expression, so they stand in conditions - alone for the boolean ones, with an operator for the counting ones:

PHP
HTML
fragments/conditions_5.pad 		Result 
{format:auto 'crew'}["Kirk","Spock","McCoy"]{/format:auto}
{data:crew}
  {pad:if first@crew}<ul>{/pad:if}
  <li>{$crew}{pad:if notLast@crew} and counting{/pad:if}</li>
  {pad:if last@crew}</ul>{/pad:if}
{/data:crew}
  • Kirk and counting
  • Spock and counting
  • McCoy

Every tag also carries the else construct: the part after the divider renders when the tag itself produced nothing.
