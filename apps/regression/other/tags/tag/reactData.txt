<p><code>{reactData id='products'}</code> runs the provider <code>_providers/products.php</code>
and writes <code>&lt;div id="products" data="..."&gt;&lt;/div&gt;</code>, the provider's result
as JSON, HTML-escaped for the attribute. A React component mounted on the div reads it with
<code>JSON.parse ( el.getAttribute ( 'data' ) )</code> - <code>getAttribute</code>, not
<code>dataset.data</code>, which reads <code>data-data</code>.</p>

<p><code>provider=</code> names another file than the id; it must be a plain name, so no path
outside <code>_providers/</code> can be run. The result keeps the types the provider gave it -
numbers stay numbers, a text like <code>"007"</code> stays a text. It is also kept in
<code>$padProviders</code> under the id, for a later provider. <code>type='check'</code>
collapses it to 1 or 0.</p>

<p>The tag writes an empty element whose meaning only a script brings out, so the examples are
shown rather than run. For new work the islands pattern of the react application is the more
general route: <code>&lt;div data-island="Name" data-props="{^field}"&gt;</code> with the
props from the page's own PHP. See <code>docs/REACT.md</code>.</p>
