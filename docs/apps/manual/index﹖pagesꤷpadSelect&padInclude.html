The Select subsystem makes the tables of the application database tags. A table is declared once in PHP - in $padSelect, with its key and the order of its rows - and from then on its name is a tag that walks its rows, every column a field. The relations between the tables are declared in $padRelations, and a table nested in another reads only the rows related to the row around it: the template walks the database without a join written anywhere. The examples read the Classic Models tables of the demo database; the padSelect application shows every option over a music catalogue, each with the SQL PAD sent for it.

An application declares its tables in _lib/select.php, so every page has them; the examples here declare them in their own PHP half.

PHP
fragments/padSelect_1.php 		HTML
fragments/padSelect_1.pad 		Result 
<?php

  $padSelect ['offices'] = [ 'key' => 'officeCode', 'order' => 'city' ];

?>
 
<ul>
  {select:offices}<li>{$city}, {$country}</li>{/select:offices}
</ul>
  • Boston, USA
  • London, UK
  • NYC, USA
  • Paris, France
  • San Francisco, USA
  • Sydney, Australia
  • Tokyo, Japan

{select:offices} names the type, for a table whose name is something else as well - a tag of the application, a content block.

Options on the tag

where=, order=, having= and group= are SQL the template writes, so each is a quoted string. A value goes into them as $name: in where= and having= it is bound as an escaped literal of that variable, never as SQL; in order= and group= it must hold column names. rows= and page= are the SQL limit, and $field=value picks rows by a field of the declared key.

PHP
fragments/padSelect_2.php 		HTML
fragments/padSelect_2.pad 		Result 
<?php

  $padSelect ['customers'] = [ 'key' => 'customerNumber', 'order' => 'customerName' ];

  $country = 'France';
  $minimum = 100000;

?>
 
{select:customers where="country = $country and creditLimit > $minimum",
           order="creditLimit desc", rows=3, fields="customerName, creditLimit"}
  <p>{$customerName}: {$creditLimit}</p>
{/select:customers}

Relations

A relation is declared from the table that holds the reference - $padRelations ['employees'] ['offices'] - and is followed both ways: nested in an office, {select:employees} is the people of that office, and nested in an employee, {select:offices} would be the office they work in. Every enclosing table counts, not only the nearest. A nested table with fields="count(*) as n" counts the related rows in the SQL.

PHP
fragments/padSelect_3.php 		HTML
fragments/padSelect_3.pad 		Result 
<?php

  $padSelect ['offices']   = [ 'key' => 'officeCode',     'order' => 'city'     ];
  $padSelect ['employees'] = [ 'key' => 'employeeNumber', 'order' => 'lastName' ];

  $padRelations ['employees'] ['offices'] = 'officeCode';

?>
 
{select:offices where="country = 'USA'"}
  <p><b>{$city}</b>, {select:employees fields="count(*) as n"}{$n}{/select:employees} people:
    {select:employees}{$firstName} {$lastName}{property:notLast@employees}, {/property:notLast@employees}{/select:employees}</p>
{/select:offices}

Boston, 2 people: Julie Firrelli, Steve Patterson

NYC, 2 people: Foon Yue Tseng, George Vanauf

San Francisco, 6 people: Anthony Bow, Jeff Firrelli, Leslie Jennings, Diane Murphy, Mary Patterson, Leslie Thompson
the relation writtenmeans
'officeCode'a field both tables have
[ 'reportsTo' => 'employeeNumber' ]field of the first table => field of the second, a pair per field
[ 'key' => 'salesRepEmployeeNumber' ]the field of the first table that holds the declared key of the second

Views - a table that stands on another

base= makes a virtual table: it takes what it does not declare - the table, the key, the order - from its base, a where of its own adds to the base's, and it follows the relations of its base. Two names for one table relate it to itself: an employee and the manager they report to.

PHP
fragments/padSelect_4.php 		HTML
fragments/padSelect_4.pad 		Result 
<?php

  $padSelect ['employees'] = [ 'key' => 'employeeNumber', 'order' => 'lastName' ];
  $padSelect ['managers']  = [ 'base' => 'employees' ];

  $padRelations ['employees'] ['managers'] = [ 'reportsTo' => 'employeeNumber' ];

?>
 
{select:employees where="officeCode = 4"}
  <p>{$firstName} {$lastName} reports to
    {select:managers}{$firstName} {$lastName}@else@nobody{/select:managers}</p>
{/select:employees}

Joins

join= in the declaration joins another declared table: the kind - inner, left, right, natural, cross - names the table, key holds the fields its declared key is met by, and the columns it adds are its declared fields, column => alias. A list of joins joins them all.

PHP
fragments/padSelect_5.php 		HTML
fragments/padSelect_5.pad 		Result 
<?php

  $padSelect ['customers'] = [ 'key' => 'customerNumber', 'order' => 'customerName' ];
  $padSelect ['repName']   = [ 'db' => 'employees', 'key' => 'employeeNumber', 'fields' => [ 'lastName' => 'rep' ] ];

  $padSelect ['japan'] = [ 'base'   => 'customers',
                           'fields' => 'customers.customerName',
                           'join'   => [ 'left' => 'repName', 'key' => 'customers.salesRepEmployeeNumber' ],
                           'where'  => "customers.country = 'Japan'",
                           'order'  => 'customers.customerName' ];

?>
 
{select:japan}
  <p>{$customerName}: {$rep}</p>
{/select:japan}

Osaka Souveniers Co.: Nishi

Tokyo Collectables, Ltd: Nishi

Groups and totals

group=, having= and rollup make a row per group, and a total row with rollup. The order a table declares sorts the table's rows - a select that groups, is distinct or totals in its fields is sorted only by the order= written with it.

PHP
fragments/padSelect_6.php 		HTML
fragments/padSelect_6.pad 		Result 
<?php

  $padSelect ['customers'] = [ 'key' => 'customerNumber', 'order' => 'customerName' ];
  $padSelect ['payments']  = [ 'key' => 'customerNumber,checkNumber' ];

?>
 
{select:customers fields="country, count(*) as n", group="country", having="count(*) >= 10", order="n desc"}
  <p>{$country}: {$n} customers</p>
{/select:customers}

{select:payments fields="year(paymentDate) as year, sum(amount) as total", group="year", rollup}
  <p>{pad:if $year}{$year}{pad:else}All years{/pad:if}: {$total}</p>
{/select:payments}

USA: 36 customers

Germany: 13 customers

France: 12 customers

2003: 3250217.70

2004: 4313328.25

2005: 1290293.28

All years: 8853839.23

Unions

union= adds the rows of another declared table - or of a list of them - built from its declaration alone, with as many columns. The tag's order= sorts the whole union.

PHP
fragments/padSelect_8.php 		HTML
fragments/padSelect_8.pad 		Result 
<?php

  $padSelect ['places']    = [ 'db' => 'offices',   'fields' => "city, 'office' as what",
                               'where' => "country = 'Australia'", 'union' => 'customerAt' ];
  $padSelect ['customerAt'] = [ 'db' => 'customers', 'fields' => "city, 'customer' as what",
                               'where' => "country = 'Australia'" ];

?>
 
{select:places order="city, what"}
  <p>{$city} - {$what}</p>
{/select:places}

Chatswood - customer

Glen Waverly - customer

Melbourne - customer

North Sydney - customer

South Brisbane - customer

Sydney - office

The options

Each can stand in the declaration or on the tag; the tag's wins.

optionwhat it is
keythe field, or the fields, that name one row
dbthe table read, when it is not the tag's name
basethe table a view stands on - in the declaration only
fieldsthe column list; declared as an array, column => alias
where, orderthe SQL condition and sort
group, having, rollupa row per group, a condition on the groups, the total row
distinct, distinctrow, allthe word after select
join, unionmore tables in the row, more rows in the list
rows, pagethe SQL limit
typearray (every row), record (one row) or field (one value)
htmlAttrJsonthe rows as JSON, escaped for an HTML attribute

The rows a select answers go through the handling options of every tag after the SQL - sort=, first= - and the properties of a loop work on them. The full reference is docs/DATABASE.md in the repository; the classicModels application walks these tables a level further.
