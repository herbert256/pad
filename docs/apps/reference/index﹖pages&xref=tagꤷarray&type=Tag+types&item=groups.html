    ♥ <span x-text="likes"></span>
  </button>
</div>
{/highlight}
    <p class="small muted">The template holds no brace of Alpine's: the state is the JSON of a PHP array.</p>

    <h1>The server renders.<br><span class="grad">htmx swaps it in.</span></h1>
    <p class="lede">
      htmx asks the server for a part of the page and puts the answer where it belongs. PAD
      already speaks that language: every {fragment} of a template can be asked for
      alone - by its name, or by the element htmx swaps - so one template serves the whole page
      and every piece of it.
    </p>
    <div class="hero-actions">
      <a class="btn" href="?examples/search">Start with active search</a>
      <a class="btn btn-ghost" href="?guide">How PAD answers htmx</a>
    </div>
  </div>

  <div class="hero-code">
{highlight 'pad'}
<input name="q" hx-get="?products"
       hx-trigger="input changed delay:300ms"
       hx-target="#results">

<ul id="results">
  {fragment 'results'}
    {products}<li>{$name}</li>{/products}
  {/fragment}
</ul>
{/highlight}
    <p class="small muted">The request carries <code>HX-Target: results</code>; PAD answers that fragment alone.</p>
  </div>

</section>

index.php 		HTML
index.pad 		Result 
<?php

  // The home page: the examples in their groups for the cards, and what the server says to
  // the island at the top - asked again by its button as JSON, the same page with
  // padFormat=json, which answers only what $padExpose names.

  $groups = reactGroups ();

  $hello = [ 'message'  => 'Hello from PAD',
             'php'      => PHP_VERSION,
             'time'     => date ( 'H:i:s' ),
             'patterns' => count ( reactData ( 'examples' ) ['examples'] ) ];

  $padExpose = [ 'hello' ];

?>
 
{# The island carries the server time, so the page differs on every request: the stored
   answer is a pattern. #}
<section class="hero">

  <div>
    <span class="eyebrow"><b>●</b> PHP renders &middot; React reacts</span>
    <h1>Server pages,<br><span class="grad">living islands.</span></h1>
    <p class="lede">
      PAD builds the page on the server - the data, the HTML, the routing by file name. React
      takes over the parts that move: an island here, a widget there, each handed its data by
      PAD and talking back to PAD while it runs.
    </p>
    <div class="hero-actions">
      <a class="btn" href="?patterns">See the patterns</a>
      <a class="btn btn-ghost" href="?guide">Build your own</a>
    </div>
  </div>

  <div data-island="HelloServer" data-props="{^hello}">
    <div class="island-fallback">PAD says: <strong>{$hello.message}</strong> at {$hello.time} - React takes this box over in a moment.</div>
  </div>

</section>

<div class="flow">
  <div class="flow-step">
    <h3>PHP gathers</h3>
    <p>The page's <code>.php</code> reads the database, a <code>_data/</code> file, the session.</p>
  </div>
  <div class="flow-step">
    <h3>PAD writes</h3>
    <p>The template places the islands and hands each its props: <code>data-props="{^field}"</code>.</p>
  </div>
  <div class="flow-step is-client">
    <h3>React mounts</h3>
    <p><code>PadReact.island()</code> finds the islands and renders a component on each.</p>
  </div>
  <div class="flow-step is-client">
    <h3>React asks back</h3>
    <p>The same pages answer JSON, one fragment, or a post - <code>padFormat=json</code>, <code>padFragment</code>.</p>
