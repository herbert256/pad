pages/islands.pad 

{meta title='Islands of any framework'}

<p>An island is a place in a PAD page where a component takes over: an element naming the
component, its props as JSON in <code>data-props</code>, and HTML of PAD's own inside that
shows until the component runs. Which framework the component is written in does not matter to
the page:</p>

{ignore}
<code><div data-island="VueCounter" data-props="{^counter}">{$counter.start}</div>
<div data-island="Shelf" data-load="visible" data-props="{^shelf}"></div>

{vite 'src/main.js'}</code>
{/ignore}

<p>A small runtime in the build pairs each name with a component and its framework, and mounts
it - fetching the component, and its framework with it, only when an island of that name is on
the page and due:</p>

{ignore}
<code>islands({
  VueCounter: vue(() => import('./islands/Counter.vue')),
  Shelf:      react(() => import('./islands/Shelf.react.jsx'))
});</code>
{/ignore}

<ul>
  <li><code>data-load</code> says when: <code>eager</code> (at once), <code>idle</code> (when the
      browser has nothing else to do) or <code>visible</code> (when the island scrolls into
      view).</li>
  <li>An adapter per framework mounts a component with props and answers how to unmount it -
      React, Vue, Svelte, Preact and Solid each take a dozen lines.</li>
  <li>Islands of different frameworks share state through a store, and talk to PAD through the
      page's JSON (<code>$padExpose</code>) and posts with the CSRF token.</li>
  <li>{manual 'vite'} builds the components; {tag 'vite'} links the build, or the dev server while
      it runs.</li>
</ul>

<p>The islands application has all of it, with the runtime, the adapters and the components
beside each example: <a href="{$padHost}islands/">islands</a>. The react application does the
same without a build step, with Babel in the browser.</p>
