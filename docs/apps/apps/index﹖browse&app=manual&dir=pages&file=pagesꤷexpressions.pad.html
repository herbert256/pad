pages/expressions.pad 

{meta title='Expressions'}

<p>An expression is the part of a tag that works out a value: <code>1 + 2</code>,
<code>$price * $qty</code>, <code>$name | upper</code>, <code>$state in ('open',
'pending')</code>. PAD's evaluator reads it - numbers, strings, fields, lists, operators,
functions and pipes - and answers one value. This page goes through all of it; every example
is live, its template beside what PAD made of it.</p>

<h2>Where expressions stand</h2>

<p>An expression is read wherever a tag takes a value: the parameter of {tag 'echo'} and of
<code>{if}</code> and <code>{elseif}</code>, the right side of
<code>{set $x = ...}</code>, the value of <code>{case}</code> and its
<code>{when}</code>s, the condition of <code>{while}</code> and
<code>{until}</code>, a quoted option such as <code>where='...'</code>, and an
occurrence assignment <code>%name = ...</code> on a tag that loops:</p>

{example 'fragments/expressions_1'}

{example 'fragments/expressions_2'}

{example 'fragments/expressions_3'}

<p>A field tag takes a pipe as it stands - <code>{$name | trim}</code> - and so
does the closing tag of a pair, over everything the pair rendered. The
<a href="?pages/pipes">pipes</a> page has the opening and closing tag pipes in full:</p>

{example 'fragments/expressions_4'}

<h2>Values</h2>

<h3>Numbers</h3>

<p>Whole numbers, decimals, a decimal that starts with its point (<code>.5</code>) and
exponents (<code>1e3</code>, <code>2.5E-1</code>). A minus before a number belongs to it.
<code>0x</code> followed by hexadecimal digits is not a number but a string of bytes:
<code>0x41</code> is the letter A.</p>

{example 'fragments/expressions_5'}

<h3>Strings</h3>

<p>Text stands between single or double quotes, which mean the same: a <code>$name</code>
inside double quotes stays text, it is not filled in as PHP would. A backslash starts an
escape - <code>\n</code>, <code>\r</code>, <code>\t</code>, <code>\\</code>,
<code>\'</code> and <code>\"</code>; any other letter after it is an error. The dot joins
strings, and numbers with them:</p>

{example 'fragments/expressions_6'}

<h3>Bare words</h3>

<p>A word without quotes and without a sigil is looked up. An operator word -
<code>eq</code>, <code>and</code>, <code>not</code> ... - is the operator; a PHP constant -
<code>TRUE</code>, <code>FALSE</code>, <code>NULL</code>, <code>PHP_EOL</code>,
<code>M_PI</code> - is its value; a word that names nothing stands for its own text.</p>

{example 'fragments/expressions_7'}

<p><b>Quote text.</b> A bare word that names something PAD knows - a function, a tag, a
property, a data set, a field - is that thing: <code>count</code>, <code>name</code> and
<code>first</code> are <a href="?pages/properties">properties</a>, so
<code>{echo count}</code> does not write the word count. Text in quotes is always
text.</p>

<h3>Fields, paths and indirection</h3>

<p><code>$name</code> reads a field: a variable the page's PHP set, one a
<code>{set}</code> made, a field of the row a loop stands on. A dot walks into an
array - <code>$user.address.city</code>, and <code>$items.0</code> by position.</p>

{example 'fragments/expressions_8'}

<p><code>$$name</code> reads the field whose name another field holds - a path as well - the
way <code>{$$name}</code> does as a tag. The name must be one of the application's
fields; the engine's own <code>pad...</code> variables are never read this way.</p>

{example 'fragments/expressions_9'}

<p>A field that holds a list is not a value: <code>$items + 1</code> is an error. Walk the
list with a loop, or hand it to a function with the <code>array:</code> prefix, below.</p>

<h3>Options, properties and the placeholder</h3>

<ul>
  <li><code>&#35;name</code> - a parameter or option of the tag; in a
  <code>{define}</code> or a custom tag, the ones the tag was called with</li>
  <li><code>&amp;name</code> - a property of the tag, <code>name@tag</code> a property of the
  tag named - <code>first@items</code>, <code>current@items</code>, <code>count@items</code>
  (see <a href="?pages/properties">properties</a>)</li>
  <li><code>@</code> - the value piped into this part of the expression (see
  <a href="#pipes">pipes</a> below)</li>
</ul>

{example 'fragments/expressions_10'}

<h3>Lists</h3>

<p><code>[ ]</code> makes a list, its items separated by commas, with keys written
<code>key => value</code> where wanted, mixed with plain items as PHP mixes them. A list is
what <code>{set}</code> stores, what a loop walks and what a PHP function
takes:</p>

{example 'fragments/expressions_11'}

<h3>Type prefixes</h3>

<p>A prefix says what a name is, so nothing else of that name can be meant:
<code>field:</code>, <code>array:</code> (a list as a value), <code>data:</code> (a
<code>{data}</code> set), <code>constant:</code>, <code>php:</code> (a PHP
function), <code>pad:</code> and <code>app:</code> (a built-in or an application pipe
function), <code>function:</code>, <code>tag:</code> and the others the
<a href="?pages/prefix">prefix</a> page lists:</p>

{example 'fragments/expressions_12'}

<h2>Operators</h2>

<p>The operators bind in this order, strongest first. Those of one row bind equally and are
applied left to right - <code>10 - 2 + 3</code> is 11 - except <code>**</code>, which binds
right to left. Round brackets group as usual.</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>operators</th><th>what they do</th></tr>
  <tr><td><code>**</code></td><td>power, right to left: <code>2 ** 3 ** 2</code> is <code>2 ** 9</code></td></tr>
  <tr><td><code>!</code>, a sign <code>-</code> <code>+</code> before a value</td><td>not, and the signs - weaker than <code>**</code>: <code>-3 ** 2</code> is -9</td></tr>
  <tr><td><code>*</code> <code>/</code> <code>%</code></td><td>multiply, divide, remainder</td></tr>
  <tr><td><code>+</code> <code>-</code></td><td>add, subtract</td></tr>
  <tr><td><code>.</code></td><td>join as text</td></tr>
  <tr><td><code>lt</code> <code>le</code> <code>gt</code> <code>ge</code> - <code><</code> <code><=</code> <code>></code> <code>>=</code></td><td>order</td></tr>
  <tr><td><code>eq</code> <code>ne</code> - <code>==</code> <code>=</code> <code>!=</code> <code><></code></td><td>equal, not equal</td></tr>
  <tr><td><code>not</code></td><td>denies what follows, a comparison included</td></tr>
  <tr><td><code>and</code> - <code>&amp;&amp;</code></td><td>both hold</td></tr>
  <tr><td><code>xor</code></td><td>exactly one holds</td></tr>
  <tr><td><code>or</code> - <code>||</code></td><td>either holds</td></tr>
  <tr><td><code>??</code></td><td>the left side, or the right one when the left is empty or missing</td></tr>
  <tr><td><code>? :</code> and <code>?:</code></td><td>the inline ternary, weakest of all</td></tr>
</table>

<p>The tests <code>in</code>, <code>like</code>, <code>matches</code>, <code>range</code>,
<code>between</code> and <code>contains</code> read infix as well; they have
<a href="#tests">a section of their own</a>.</p>

<h3>Arithmetic</h3>

<p>As in PHP: <code>/</code> answers a decimal when it does not divide evenly, <code>%</code>
works on whole numbers. A text that is a number counts as one - <code>'5' + '5'</code> is 10 -
a text that is not, <code>'a' + 1</code>, is an error, and so is a division by zero.</p>

{example 'fragments/expressions_13'}

<h3>Precedence</h3>

{example 'fragments/expressions_14'}

<h3>Joining text</h3>

<p>The dot binds weaker than <code>+</code> and <code>-</code>: in <code>1 + 2 . 3</code> the
sum comes first and is then joined with the 3, and in <code>1 . 5 + 5</code> the 1 is joined
with 10. After a value a dot is the join, also right against it - <code>'a'.1</code> - and
only where no value stands before it does a dot start a number.</p>

{example 'fragments/expressions_15'}

<h3>Comparing</h3>

<p>Each comparison has a word and a symbol: <code>eq</code> or <code>==</code> (a single
<code>=</code> too), <code>ne</code>, <code>!=</code> or <code><></code>, and
<code>lt le gt ge</code> or <code>< <= > >=</code>. The words read better in a
template full of HTML. Numbers, and texts that are numbers, compare as numbers -
<code>'2' lt '10'</code> holds; other texts compare character by character, case counting.
PHP's <code>===</code> and <code>!==</code> are not there. A comparison answers
<code>1</code> or nothing:</p>

{example 'fragments/expressions_16'}

<h3>Logic</h3>

<p><code>and</code>, <code>or</code>, <code>xor</code> and <code>not</code>, with
<code>&amp;&amp;</code>, <code>||</code> and <code>!</code> as their symbols. The word
<code>not</code> binds weaker than the comparisons, so <code>not $a eq $b</code> denies the
comparison; <code>!</code> binds as tightly as a sign, so <code>!$a eq $b</code> compares
<code>!$a</code> with <code>$b</code>. <code>and</code> and <code>or</code> stop at a left
side that decides: <code>$n gt 0 and 10 / $n gt 1</code> never divides by zero.</p>

{example 'fragments/expressions_17'}

<h3>A default: ??</h3>

<p><code>a ?? b</code> answers <code>a</code> unless it is empty - <code>''</code>, NULL, FALSE,
an empty list - or a field that does not exist; then it answers <code>b</code>. A 0 is a value
and stays. A field in front of <code>??</code> may be missing, also under the strict check:
giving it a default is what the operator is for. The right side is worked out only when it
is wanted. In a pipe it takes the piped value, and the <code>default</code> function does
the same:</p>

{example 'fragments/expressions_18'}

<h3>The inline ternary</h3>

<p><code>cond ? then : else</code> binds weakest of all: everything before the
<code>?</code> is the condition, and each branch runs to its <code>:</code> or to the end -
<code>0 ? 'yes' : 'no' . '!'</code> joins the <code>'!'</code> to the no. Only the branch
chosen is worked out. Ternaries in a row read from the right, <code>a ? b : c ? d : e</code>
being <code>a ? b : (c ? d : e)</code>. The short form <code>a ?: b</code> answers
<code>a</code> itself when it holds, and with nothing before the <code>?</code> the piped
value is the condition:</p>

{example 'fragments/expressions_19'}

{example 'fragments/expressions_20'}

<h2>Truth</h2>

<p>Where a condition is wanted - <code>{if}</code>, <code>where=</code>, the
ternary, <code>and</code> and <code>or</code> - a value is tested as PHP tests it:
<code>''</code>, <code>'0'</code>, 0, NULL, FALSE and an empty list are false, every other
value is true - the texts <code>'0.0'</code>, <code>'false'</code> and a space among
them.</p>

{example 'fragments/expressions_21'}

<p>The comparisons, the tests and the logic operators answer <code>1</code> for true and
<code>''</code> for false: written by {tag 'echo'} a truth is a 1 or nothing at all, and truths
add up as numbers.</p>

{example 'fragments/expressions_22'}

<h2 id="tests">Tests: in, like, matches, range, between, contains</h2>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>test</th><th>holds when</th></tr>
  <tr><td><code>$x in (a, b, ...)</code></td><td>the value equals one of the list</td></tr>
  <tr><td><code>$x like 'A%'</code></td><td>the value matches the SQL pattern: <code>%</code> any run of characters, <code>_</code> one character, <code>\\%</code> and <code>\\_</code> themselves; case is ignored</td></tr>
  <tr><td><code>$x matches '/re/'</code></td><td>the regular expression matches</td></tr>
  <tr><td><code>$x range (a, b)</code></td><td>a <= value <= b, the ends included</td></tr>
  <tr><td><code>$x between (a, b)</code></td><td>a < value < b, the ends left out</td></tr>
  <tr><td><code>$x contains y</code></td><td>the text holds y - or, for a list, an item of it equals y</td></tr>
</table>

<p>A <code>not</code> between the value and the test denies the test, as SQL writes it:
<code>$s not in (...)</code>, <code>not like</code>, <code>not matches</code>,
<code>not range</code>. The value is everything left of the test - <code>5 + 1 in (6,
7)</code> tests 6.</p>

{example 'fragments/expressions_23'}

<p><code>like</code> ignores case; <code>_</code> stands for exactly one character:</p>

{example 'fragments/expressions_24'}

<p>A backslash in a PAD string is an escape, so the backslash a regular expression needs is
written twice: <code>'/a\\.b/'</code>. A <code>{n}</code> quantifier would open a
tag - repeat the class, as below, or let the page's PHP hand the pattern over.</p>

{example 'fragments/expressions_25'}

{example 'fragments/expressions_26'}

<p><code>contains</code> looks into a text, or into a list for an item equal to the one asked
for:</p>

{example 'fragments/expressions_27'}

<p>Each test is a pipe function too, so it can stand after a pipe or be called, its value the
first argument:</p>

{example 'fragments/expressions_28'}

<p>Together with <code>and</code> and <code>or</code> they make the conditions of the
<code>where</code> option, which the <a href="?pages/data_handling">data handling</a> page
covers with the other options:</p>

{example 'fragments/expressions_29'}

<h2>Functions</h2>

<p>The built-in pipe functions - <code>upper</code>, <code>left</code>, <code>replace</code>,
<code>date</code> and the rest of the {tag 'functions'} list - are used two ways. After a pipe
they take the value on its left: <code>$s | left(2)</code>. Written as a call with nothing
piped in they take it as their first argument: <code>left($s, 2)</code>, as PHP's own
functions do - so they nest, and stand wherever a value can. The number of parameters is
checked.</p>

{example 'fragments/expressions_30'}

{example 'fragments/expressions_31'}

<p><code>php:name</code> calls a PHP function, and so does a plain name followed by
<code>(</code> that is no PAD function - <code>ucfirst('word')</code>; the setting
<code>$padPhpFunctions</code> decides which PHP functions a template may call. A piped value
goes in as the only argument - <code>'abc' | php:strrev</code> - and into a call with
arguments where <code>@</code> stands: <code>$n | php:number_format(@, 2)</code>.</p>

{example 'fragments/expressions_32'}

<p>A file in the application's <code>_functions/</code> directory is a pipe function as well,
the piped value its <code>$value</code> - this manual has <code>_functions/stars.php</code>.
<code>function:</code> asks for whatever function kind the name is, <code>app:</code> for the
application's own (see <a href="?pages/extending">extending</a>):</p>

{example 'fragments/expressions_33'}

<h2 id="pipes">Pipes</h2>

<p>A <code>|</code> hands the value on its left to what follows; the parts run left to right,
each over what the one before answered:</p>

{example 'fragments/expressions_34'}

<p>A part after a pipe is an expression of its own, and the piped value fills the place of
the operand it lacks. An operator that opens the part takes it as its left side -
<code>| + 1</code>, <code>| . ' EUR'</code>, <code>| ?? 'none'</code>. A space between such an
operator and its operand is required: <code>| + 1</code>, never <code>| +1</code>.</p>

{example 'fragments/expressions_35'}

{example 'fragments/expressions_36'}

<p><code>@</code> stands for the piped value wherever the part needs it, as often as it
needs it:</p>

{example 'fragments/expressions_37'}

<p>A part that is a printf format - it starts with <code>%</code> and is one conversion -
formats the value as PHP's <code>sprintf</code> does. A <code>%</code> that is no format is
the remainder: <code>| % 3</code>.</p>

{example 'fragments/expressions_38'}

<p>A pipe inside round or square brackets belongs to that group: <code>($n | + 1) * 2</code>
adds before it multiplies, <code>upper($s | trim)</code> trims the argument, and in a list or
an argument list the pipe works on its own item. Outside brackets a pipe always ends the
whole expression before it.</p>

{example 'fragments/expressions_39'}

<p>A field tag with a pipe, <code>{$x | upper}</code>, writes its answer through
the sanitize chain, like every field tag. {tag 'echo'} writes it raw - the right one for HTML
the page made itself, the wrong one for what a visitor typed:</p>

{example 'fragments/expressions_40'}

<h2>Dates</h2>

<p><code>date(format, modifier)</code> reads a Unix timestamp, a date in text or a date object
the page's PHP made; the modifier is what PHP's <code>strtotime</code> reads, such as
<code>'+1 week'</code>. Written as a call it keeps PHP's order, the format first:
<code>date('Y', $created)</code>. Dates written <code>YYYY-MM-DD</code> compare correctly as
plain text. <code>now</code> is the current time, and the
<a href="?pages/locale">locale</a> page has <code>localDate</code>:</p>

{example 'fragments/expressions_41'}

<h2>Lists meeting operators</h2>

<p>An arithmetic operator or a comparison that meets a list works with the sum of its
numbers. A list holding more than numbers, or met by the dot, is an error. A field that holds
a list is handed over with the <code>array:</code> prefix:</p>

{example 'fragments/expressions_42'}

{example 'fragments/expressions_43'}

<h2>Numbers at the edges</h2>

<p>What is not a number - a NAN such as <code>php:sqrt(-1)</code> - is empty. <code>%</code>
works on whole numbers, as PHP's does; <code>php:fmod</code> keeps the fraction. Decimals are
written with PHP's precision, so <code>0.1 + 0.2</code> comes out as 0.3:</p>

{example 'fragments/expressions_44'}

<h2>Values are text</h2>

<p>An expression's answer is a value, and a value never becomes template code: a field that
holds braces - from a database, a form, a file - is written as the text it is. To run it as
PAD on purpose, say so where it is used, with the <code>code</code> pipe (or
<code>sandbox</code>, which runs it in an isolated pass):</p>

{example 'fragments/expressions_45'}

<h2>When an expression is wrong</h2>

<p>Under the strict syntax check - <code>$padCheckSyntax</code>, on by default - a mistake in
an expression is an error that names the fault and its place, and the page answers with the
error report instead of guessing. The report shows the template's file, line and column with
the lines around it (see <a href="?pages/template_errors">errors in the template</a>). What
some mistakes are told:</p>

<table border="1" cellpadding="8" cellspacing="0" style="border-collapse: collapse;">
  <tr style="background: #f0f0f0;"><th>written</th><th>the error says</th></tr>
  <tr><td><code>{echo (1 + 2}</code></td><td>the ( opened at position 1 is never closed</td></tr>
  <tr><td><code>{echo 'abc}</code></td><td>the string opened with ' at position 1 is never closed</td></tr>
  <tr><td><code>{echo $name | uppr}</code></td><td>there is no pipe function named 'uppr'</td></tr>
  <tr><td><code>{echo nofunc(1)}</code></td><td>there is no function named 'nofunc'</td></tr>
  <tr><td><code>{if $typo eq 1}</code></td><td>there is no field named '$typo'</td></tr>
  <tr><td><code>{echo $items + 1}</code></td><td>the field '$items' is a list, not a value</td></tr>
  <tr><td><code>{if $n eq}</code></td><td>the operator 'eq' has nothing on its right</td></tr>
  <tr><td><code>{echo $n + * 3}</code></td><td>the operators '+' and '*' stand side by side - a value is missing between them</td></tr>
  <tr><td><code>{if $n === 5}</code></td><td>'===' is no operator - eq (==) compares two values</td></tr>
  <tr><td><code>{echo $n | +1}</code></td><td>a pipe operator needs a space before its operand - write '| + 1', not '| +1'</td></tr>
  <tr><td><code>{echo 5 &amp; 3}</code></td><td>'&amp;' is no operator or value</td></tr>
  <tr><td><code>{if $n not 5}</code></td><td>a 'not' after a value denies a test - write $a not in (...), not like, not matches or not range, or put it in front: not $a eq $b</td></tr>
  <tr><td><code>{echo 7 / 0}</code></td><td>a division by zero in /</td></tr>
  <tr><td><code>{echo 'a' * 2}</code></td><td>'a' is not a number for *</td></tr>
  <tr><td><code>{echo $n ? 'a'}</code></td><td>the ? of an inline ternary has no : - write cond ? then : else</td></tr>
  <tr><td><code>{echo [ 'a' => ]}</code></td><td>the key 'a' of a list has no value after its =></td></tr>
  <tr><td><code>{echo replace('abc')}</code></td><td>the function 'replace' wants 2 parameters after the value it works on - written as a call its first argument is that value: replace($value, ...)</td></tr>
  <tr><td><code>{echo php:str_repeat('x', -1)}</code></td><td>the PHP function 'str_repeat' refused its arguments: str_repeat(): Argument #2 ($times) must be greater than or equal to 0</td></tr>
  <tr><td><code>{echo 'a\qb'}</code></td><td>Unsupported \ char</td></tr>
</table>

<h2>The lenient walk</h2>

<p>With <code>$padCheckSyntax = FALSE</code> in <code>_config/config.php</code> nothing is
reported and the evaluator answers what it can: a text that is no number counts as 0
(<code>'a' + 1</code> is 1), a missing field is empty (<code>$nope + 1</code> is 1), an
unknown escape loses its backslash, and an expression that cannot be worked out at all - a
bracket never closed, a division by zero, a PHP function refusing its arguments - answers
nothing. That suits old templates; a new one is better off with the check, which finds the
typo the lenient walk hides.</p>
