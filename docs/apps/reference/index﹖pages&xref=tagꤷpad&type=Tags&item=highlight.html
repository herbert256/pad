App: alpine - Page: guide

guide.pad 		Result 
{pad:meta title='Alpine on a PAD page'/}
<header class="example-head">
  <p class="lede">
    Alpine reads attributes, PAD writes them. Both love braces - so give each its own, hand
    Alpine its state as JSON, and let it talk back to the page that wrote it.
  </p>
</header>

<h2>1. The braces</h2>
<p>PAD reads every <code>{</code> of a template as the start of a tag; Alpine writes objects
   with them. Three ways that never collide:</p>
<div class="grid">
  <div class="card">
    <h3>State from PHP</h3>
    <p>The ^ sigil writes a field as JSON, escaped for the attribute - <code>x-data="{^profile}"</code>.
       No brace of Alpine's in the template, and a quote in a value stays text.</p>
  </div>
  <div class="card">
    <h3>Components in a file</h3>
    <p><code>Alpine.data('tabs', ...)</code> in a script of <code>www/</code>, called by name:
       <code>x-data="tabs({^tabs})"</code> - the file never meets the PAD parser.</p>
  </div>
  <div class="card">
    <h3>A space after the brace</h3>
    <p><code>x-data="{ open: false }"</code> written as <code>{ open: false }</code> -
       a brace with a space after it is no PAD tag. It works for a short object; prefer the other two.</p>
  </div>
</div>

<h2>2. Load order</h2>
<p>The application's scripts first, Alpine last and deferred - a page's components register
   themselves on <code>alpine:init</code> before Alpine walks the page:</p>
{pad:highlight 'html'}
<script src="alpine-app.js"></script>                         <!-- pad.get, pad.post -->
<script defer src="https://unpkg.com/alpinejs@3/dist/cdn.min.js"></script>
...
<script src="examples/search.js"></script>                    <!-- Alpine.data('search', ...) -->
{/pad:highlight}

<h2>3. Talking back</h2>
<p>A page answers JSON when asked - <code>?page&amp;padFormat=json</code> - with only what its PHP
   names in <code>$padExpose</code>; the templates do not run for it. A post carries the session's
   token in a header, read from <code><meta name="csrf-token" content="{pad:csrf token/}"></code>:</p>
{pad:highlight 'js'}
const answer = await pad.get('examples/search', { q: this.q });   // the JSON of $padExpose
const saved  = await pad.post('examples/todos', { op: 'add', text }); // X-CSRF-Token sent
{/pad:highlight}

<h2>4. One set of rules</h2>
<p>Keep a form's rules in PHP: <code>padValidate ( $rules )</code> checks the post,
   <code>padValidateClient ( $rules )</code> hands them to the component, {pad:validator} brings the
   checker, and <code>padValidate.field ( rules.email, value, form )</code> answers in the server's
   words.</p>

<h2>5. Events from the server</h2>
<p><code>padSse()</code> streams JSON events; an <code>EventSource</code> opened in
   <code>x-init</code> - in a component that closes it again in <code>destroy()</code> - turns them
   into state.</p>

<div class="callout"><p>Values are text: whatever a visitor typed, the ^ sigil writes it as JSON escaped for the attribute,
   and <code>x-text</code> puts it in as text. Avoid <code>x-html</code> with data that is not yours.</p></div>

App: htmx - Page: guide
PHP
 HTML
guide.pad 		Result 
{pad:meta title='How PAD answers htmx'/}
<header class="example-head">
  <p class="lede">
    htmx asks for HTML and swaps it in. A PAD page is HTML with names on its parts - so the
    same template answers the browser's first visit and every question htmx asks after it.
  </p>
</header>

<h2>1. Name the part</h2>
<p>A {pad:fragment} around the part that changes; the element around it gets the same name
   as its id:</p>
{pad:highlight 'pad'}
<input name="q" hx-get="?products" hx-trigger="input changed delay:300ms" hx-target="#results">

<ul id="results">
  {pad:fragment 'results'}
    {local:products}<li>{$name}</li>{/local:products}
  {/pad:fragment}
</ul>
{/pad:highlight}

<h2>2. PAD answers the part alone</h2>
<p>htmx sends <code>HX-Request: true</code> and the id of the element it swaps in
   <code>HX-Target</code>. When the page has a fragment of that name, the answer is that fragment
   and nothing else - no wrapper, no rest of the page; when it has none the page renders whole,
   as it always did. A request can also name the fragment itself, for an element without an id
   or another part than the target:</p>
{pad:highlight 'pad'}
<tr hx-get="?orders&p=2&padFragment=rows" hx-trigger="revealed" hx-swap="afterend">
{/pad:highlight}
<p>The page's PHP runs as for any request - <code>$q</code> is the request's value - and may narrow
   what the fragment shows: <code>$padFragmentOnly = 'row'</code> sets the answer from PHP. A
   fragment inside a loop answers with the first row it renders, so narrow the rows to the one
   asked for.</p>

<h2>3. Posts carry the token</h2>
<p>With <code>$padCsrf</code> on, a post without the session's token is refused before the page
   runs. A {pad:form} carries it as a field; for an <code>hx-post</code> on anything else, put
   the header once on an element around the page - the body, or here the one the frame's page
   stands in - and htmx sends it with every request below; the ^ sigil writes the array as JSON
   for the attribute:</p>
{pad:highlight 'pad'}
<body hx-headers="{^headers}">          <!-- $headers = [ 'X-CSRF-Token' => padCsrfToken () ] -->
{/pad:highlight}

<h2>4. Forms check the same rules twice</h2>
<p>Fields with <code>rules=</code> are checked on the server before the PHP runs, and with
   <code>client</code> in the browser first. Posted through htmx, a form that broke a rule comes
   back as its own fragment, refilled, with PAD's messages beside the fields:</p>
{pad:highlight 'pad'}
<div id="signup">{pad:fragment 'signup'}
  {pad:form 'signup', client, error, hx-post='?signup', hx-target='#signup'}
    {pad:input 'email', label='E-mail', rules='required|email'/}
  {/pad:form}
{/pad:fragment}</div>
{/pad:highlight}

<h2>5. More than one place</h2>
<p>An answer can update other parts of the page as well: elements in it marked
   <code>hx-swap-oob="true"</code> go where their id is - the cart count in the header, a summary
   beside the list.</p>

<h2>6. Pushed by the server</h2>
<p><code>padSse()</code> keeps a page's connection open and sends events; with htmx's sse
   extension each event's HTML is swapped in as it arrives:</p>
{pad:highlight 'pad'}
<div hx-ext="sse" sse-connect="?ticker" sse-close="done">
  <ol sse-swap="tick" hx-swap="afterbegin"></ol>
</div>
{/pad:highlight}

<div class="callout"><p>The page cache knows htmx: a request for a part is answered fresh and never stored, and a
   fragment chosen by a header is never stored under the page's address.</p></div>

{pad:meta title='Islands of any framework'/}
<p class="lede">
  PAD writes the page and marks the islands; one small runtime mounts a component of any
  framework on each; Vite builds the components and {pad:vite} links the build.
</p>

<h2>1. The island, in the template</h2>
<p>An element names its component and carries its props - the ^ sigil writes a field as JSON for the
   attribute - and <code>data-load</code> says when its code is fetched. What stands inside shows
   until the component takes over.</p>
{pad:highlight 'pad'}
<div data-island="VueCounter" data-load="visible" data-props="{^counter}">
  <p>{$counter.start}</p>
</div>

{pad:vite 'src/main.js'/}
{/pad:highlight}

<h2>2. The registry, in the build</h2>
<p><code>_frontend/src/main.js</code> names every island and pairs it with its framework. Both are
   fetched by <code>import()</code> when an island of the name is due - a page without a Vue island
   loads no Vue:</p>
{pad:highlight 'js', file='_frontend/src/main.js'/}

<h2>3. An adapter per framework</h2>
<p>An adapter is a dozen lines: it mounts a component on an element with props and answers how to
   unmount it. Each is a module of its own, so it travels with its framework:</p>
{pad:highlight 'js', file='_frontend/src/adapters/svelte.js'/}

<h2>4. Talking to PAD, and to each other</h2>
<p><code>pad-islands.js</code> also exports <code>get(page, params)</code> - the JSON of a page's
   <code>$padExpose</code> - <code>post(page, body)</code> with the session's CSRF token, and
   <code>store(name, initial)</code>: state any framework subscribes to. A React island writes it, a
   Vue and a Svelte island show it.</p>

<h2>5. Build and dev server</h2>
<div class="cols-2">
  <div>
{pad:highlight 'bash'}
cd apps/islands/_frontend
npm install
npm run build     # www/islands/build/ with .vite/manifest.json
npm run dev       # the dev server; build/hot holds its address
{/pad:highlight}
  </div>
  <div>
    <p>{pad:vite 'src/main.js'/} reads the manifest and writes the entry's CSS, its chunks as
       <code>modulepreload</code> and its module script. While <code>npm run dev</code> runs, a hook of
       <code>vite.config.js</code> writes the dev server's address into <code>build/hot</code>, and
       {pad:vite} asks the dev server instead - a save in the editor shows at once.</p>
  </div>
</div>

<div class="callout"><p>Each framework compiles its own files: <code>*.react.jsx</code>, <code>*.solid.jsx</code>, <code>*.vue</code>,
   <code>*.svelte</code>. Preact needs no compiler - its components are written with <code>htm</code>.</p></div>

    <h2>2. The island, in the template</h2>

<h2>3. The component, in www/</h2>
<p>A plain file under <code>www/react/</code>, served as it is - so its braces never meet the PAD parser.
   <code>PadReact.island</code> mounts it on every island of that name, the JSON as its props.</p>
{pad:highlight 'js', file='_guide/orders.js'/}

<h2>4. Talking back</h2>
<div class="cols-2">
  <div>
    <p>The page answers JSON when asked - but only what <code>$padExpose</code> names. The templates do not
       run for such a request. A post needs the session's CSRF token, which <code>PadReact.post</code>
       sends in a header when <code>$padCsrf</code> is on.</p>
{pad:highlight 'php'}
// orders.php - one more line
$padExpose = [ 'orders' ];

// a post from the component
if ( padRequestIs ( 'POST' ) ) {
  $errors = padValidate ( [ 'qty' => 'required|integer|min:1' ] );
  if ( ! $errors )
    db ( "UPDATE orders SET qty={0} WHERE id={1}", [ $qty, $id ] );
}
{/pad:highlight}
  </div>
  <div>
    <p>From the component it is one call each - and <code>{pad:fragment 'name'}</code> in the template
       lets a component fetch one rendered part of a page as HTML.</p>
{pad:highlight 'js'}
// ?orders&padFormat=json
const { orders } = await PadReact.get('orders', { status: 'open' });

// POST ?orders&padFormat=json, X-CSRF-Token: ...
const answer = await PadReact.post('orders', { id: 7, qty: 2 });

// ?orders&padFragment=summary - HTML
const html = await PadReact.fragment('orders', 'summary');

// as a hook: asked again whenever status changes
const { data, loading } = PadReact.useData('orders', { status }, first);
{/pad:highlight}
  </div>
</div>

<h2>The runtime</h2>
<p><code>www/react/pad-react.js</code> - plain JavaScript, loaded by <code>_inits.pad</code> on every page.</p>
<table class="table">
  <thead><tr><th>Call</th><th>What it does</th></tr></thead>
  <tbody>
    <tr><td><code>PadReact.island(name, Component)</code></td><td>Renders <code>Component</code> on every <code>[data-island=name]</code>, with the JSON of <code>data-props</code> as props (a list arrives as <code>props.data</code>) and what PAD rendered inside as <code>props.serverHtml</code>.</td></tr>
    <tr><td><code>PadReact.get(page, params)</code></td><td>The page's exposed data: <code>?page&amp;...&amp;padFormat=json</code>, parsed.</td></tr>
    <tr><td><code>PadReact.post(page, body, { token })</code></td><td>Posts the body form-encoded with the <code>X-CSRF-Token</code> header from <code><meta name="csrf-token"></code>; <code>token: false</code> leaves it out.</td></tr>
    <tr><td><code>PadReact.fragment(page, name, params)</code></td><td>One <code>{pad:fragment}</code> of the page as HTML.</td></tr>
    <tr><td><code>PadReact.useData(page, params, first)</code></td><td>A hook: <code>{ data, loading, error }</code>, asked again when the params change, the request before aborted.</td></tr>
    <tr><td><code>PadReact.useDebounced(value, ms)</code></td><td>The value once it stood still for <code>ms</code> - for a search box.</td></tr>
  </tbody>
</table>
<p class="small muted">A request that does not succeed throws an error with <code>status</code> and the parsed <code>body</code>. Every request is
   told to the page as a <code>pad:request</code> event - the request log under the examples listens to it.</p>

<h2>Good to know</h2>
<div class="grid">
  <div class="card">
    <h3>Keep JSX out of templates</h3>
    <p>PAD reads every <code>{ }</code> of a template. Components live in <code>www/</code>, loaded with
       <code><script type="text/babel" src></code>; for a short inline script there is <code>{pad:ignore}</code>.</p>
  </div>
  <div class="card">
    <h3>Values are text</h3>
    <p>A field in <code>data-props</code> is escaped for the attribute and never runs as PAD, whatever a visitor typed
       into it - React escapes it once more when it renders.</p>
  </div>
  <div class="card">
    <h3>Server first</h3>
    <p>Give the island its first data in the props and put real HTML inside it: the page shows something before any
       script ran, and search engines see it.</p>
  </div>
  <div class="card">
    <h3>Going to production</h3>
    <p>Babel in the browser is for learning. Compile the components with esbuild or Vite into one file, load the
       production React builds, and drop <code>type="text/babel"</code> - the PAD side stays as it is.</p>
  </div>
</div>
