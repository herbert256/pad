The group option folds the rows of any data tag into one occurrence per distinct value of a field. Each group holds that value, $count - the number of rows in the group - and rows, the group's own rows as nested data. Inside {array:rows} a field is the row's own value again.

HTML
fragments/grouping_1.pad 		Result 
{pad:data 'orders'}
  [ {"customer":"Ann","number":101,"total":40}, {"customer":"Bob","number":102,"total":15},
    {"customer":"Ann","number":103,"total":25}, {"customer":"Cleo","number":104,"total":60},
    {"customer":"Bob","number":105,"total":35} ]
{/pad:data}

{data:orders group='customer', sum='total'}
  <h4>{$customer}: {$count} orders, {$total}</h4>
  {array:rows}
    <p>Order {$number}: {$total}</p>
  {/array:rows}
{/data:orders}

Aggregates

sum, avg, min and max name the fields to aggregate over each group's rows. The aggregate is stored under the field's own name - {$total} above is the sum - and under the aggregate joined to it - {$sum_total}, {$avg_total} - so one field can be summed and averaged at once. A field list such as sum='total, quantity' aggregates each of them.

In order with the other options

Handling options run in the order they are written. Groups come in the order their first row appears: a sort written before the group orders the groups and the rows inside them, a sort written after it orders the groups - also on an aggregate, as above. first, page and where written after the group count groups: {data:orders group='customer', where='$count gt 1'} keeps the customers with more than one order. Several fields - group='year, month' - group on the combination, and {array:rows group='month'} groups again inside a group.
