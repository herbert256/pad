# Syntax highlighters

`padHighlight`, `padHighlightTokens`, the `highlight` pipe and `{widget:highlight}` read language definitions from `pad/subs/widgets/highlighters/types`. Existing canonical languages retain their output within the tokenization size limit and PHP uses its native tokenizer. New lexical grammars cover Python (`py`), Go (`golang`), Rust (`rs`), unified diff (`patch`) and TypeScript (`ts`, `tsx`). TypeScript now recognizes type declarations rather than using the JavaScript alias. Go follows its [string and rune literal rules](https://go.dev/ref/spec#String_literals); Rust distinguishes [lifetimes, character literals and raw strings](https://doc.rust-lang.org/reference/tokens.html). Python, Go, Rust and TypeScript consume unterminated strings through their line/EOF boundary to avoid retrying every escaped quote. These are lexical coloring rules, not parsers: embedded languages, nested Rust comments and Python formatted-string interpolation are not parsed separately.

Tokenization is limited to 65536 source bytes, bounding regex work. Captures are processed one token at a time to bound working memory. Larger snippets are returned in full as escaped uncolored text. Every token and unmatched character is escaped centrally. Rules cannot insert raw source HTML. Existing line numbers, marking, dedenting and file restrictions are unchanged. Language files return `aliases` and ordered `rules` using existing `hl-*` token classes; PHP keeps its tokenizer path. Invalid language paths are never included.

Run `php tests/subsystems/highlighters.php` for compatibility hashes, grammar, HTML-injection and long-input fixtures.
