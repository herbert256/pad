<p><code>{foo}</code> has no use of its own: it answers the line <code>Foo tag from pad</code>.
It exists so that the manual can show what a name resolves to when several kinds of thing
carry it - an application tag in <code>_tags/foo.php</code>, a pipe function, a PHP function,
a data or bool store, a content block.</p>

<p>A bare <code>{foo}</code> is looked up in a fixed order, and an application tag comes
before the built-in one: a <code>_tags/foo.php</code> in the page's directory or one of its
parents wins. A type prefix names the kind outright - <code>{pad:foo}</code> is always the
built-in tag, <code>{app:foo}</code> always the application's, and <code>php:</code>,
<code>function:</code>, <code>data:</code>, <code>bool:</code> and the other prefixes each name
their own kind.</p>

<p>The second example below has a <code>_tags/foo.php</code> in its own directory, so the
bare name and the <code>app:</code> prefix find that one, while <code>pad:foo</code> still
reaches the built-in.</p>
