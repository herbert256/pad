What this audit found

The first audit found one design fault and its many consequences: values were re-read as template code. Its fix, $padProtectValues, is sound where it was applied. This audit finds the places it wasn't, and the boundaries that were never drawn. These fall into four seams:

  • Value-to-source edges the fix didn't cover.
  • A field resolver that reads the engine's own namespace.
  • A DATA directory that holds secrets and is served over HTTP.
  • A notion of "local" that the engine's requests to itself inherit.

Beyond the seams, the audit found:

  • An evaluator fault that silently mis-computes negation.
  • A Tidy pass that rewrites modern markup.
  • Error-recovery options that never fire for the common tag kinds.
  • The sequence runner's edges: overflow, membership and from ≤ 0.
  • A test corpus with some answers that cannot fail.
  • About forty documentation claims that are false today.

Fifteen of the first audit's "Fixed" findings, and four of its applications-sweep fixes, turned out to be incomplete. Each is listed with the finding that shows it, in First-audit fixes.

Four seams

Most serious findings sit on one of four seams. Each is a place where a boundary the first audit drew stops short, or where none was ever drawn. Fixing a seam closes several findings at once, so the remediation order follows them.

1 · Values are text — except at the edges

$padProtectValues swaps the syntax characters of every value for private-use stand-ins and restores them as the page is written out. The swap is applied where values were known to land:

  • a {$x};
  • a tag's single-value answer;
  • a ternary side;
  • a piped value.

Four edges escape it:

  • A custom tag's $padContent is source by design. A request value passed to the documented button tag therefore runs (C1).
  • A data=, {data 'n', $v} or {curl $v} value is sniffed. As a path it includes PHP; as a URL it is fetched (H2).
  • The stand-ins are restored even when the request supplied them. They are the one character class no escaper touches (H1).
  • A {page} name lands in an inline script, unvalidated (M2).

2 · The field resolver is its own namespace

Request promotion was locked down: padValidVar, the $padRequestVars list, no cookies, and engine names refused. The object: form refuses engine names. But {$x} resolves through padFieldLevel(), which:

  • reads $GLOBALS[$x] with no engine filter, so {$padSqlPassword} answers, as does {$$sel} with sel from the query;
  • scans every global array ($_COOKIE, $_SERVER, $_ENV, $_FILES) for the name.

A cookie still presets {$isAdmin} (H3). The session is a third route: every key in it becomes a global, across every app on the host (M3).

3 · DATA is served, and it holds secrets

www/README.md documents www/DATA → ../DATA as the way to browse dumps over HTTP, and Apache lists the directory.

What lands there:

  • Error reports with the application's config source, database password included (H4).
  • The track mode's copy of every request: passwords, bearer tokens and session cookies in clear (H5).
  • 624 MB of traces with no retention (L17).
  • Any file a template writes, a .php included, which then executes (L5).

The 0600 file modes from the first fix don't help, because the web server owns the files it serves.

4 · "Local" is inherited by the engine's own requests

padLoopback() trusts a loopback address that carries no forwarding header. Every request the engine makes to itself matches that description: {get}, {page app=…}, {curl 'SELF://…'}, and the harvest crawls. Each also:

  • is addressed by the visitor's Host header;
  • carries the visitor's User-Agent.

A remote visitor can therefore:

  • reach the loopback-only switches;
  • receive the full local error report or the JSON channel;
  • point the server at any host and port (H6).

The developer apps go one step further and need no trick at all (H7).

These were attacked on suspicion and held up. They are listed so that the findings above can be read at their true size, and so that the fixes they record get the credit.

The trust boundary, where it was drawn

  • Hostile values are inert. {$v}, {!v}, {echo $v}, {echo '{$v}'}, {echo {$v}}, {$v | html_entity_decode} and a closing {/x | html_entity_decode} all keep {php:getcwd} and {echo 7*7} as text. padSpliceQuote keeps {echo {$n} + 1} working and {${$hi}} resolving.
  • $padPhpFunctions holds against case variants, the bare-name fallback, pipes, function:, app:, a namespace backslash, call_user_func chains and parenthesised names. A refused function is named in the error at every site.
  • object: refuses engine names, and constant: reads only real constants.
  • No dangerous sinks. There is no eval, unserialize, create_function, assert or preg_replace /e anywhere in pad/. Every extract() and $$ was traced, and none is reachable with keys an attacker chooses.
  • Script execution is escaped. exec escapes both the path and the arguments.

SQL, files and routing

  • The select builder binds a request value as a quoted, escaped literal (0 or 1=1 matches nothing). order= and group= enforce column lists, and where=$cond is refused.
  • db() quotes or coerces bare placeholders, doubles backticks in identifiers and refuses multi-statement queries. The x keys are the documented raw escape hatch.
  • The file layer. padFileGet, padFilePut and padFileCheck reject .., control characters and NUL. Writes stay inside DATA and are atomic, through a temp file and a rename. padDirContained is based on realpath.
  • Page routing. ?_lib/x, ?_config/config, ?../_common/index and ?.DS_Store are all 404. www/pad.php resolves only real entry scripts, and /pad.php is a 404.
  • Parsers. XML is read without LIBXML_NOENT or a DTD load, so there is no XXE. YAML has decode_php=0. The CSV quote and comma fixes hold.

Requests, sessions, errors

  • Request promotion. padValidVar takes ASCII identifiers only, and PHP's dot and space conversion cannot produce a pad, pq or _ name. A declared session name is never filled from the request.
  • Cookies are HttpOnly and SameSite=Lax, and Secure over https. Strict session mode is on. padSesID and padReqID are checked against the 8-character shape.
  • Headers. header() refuses CR and LF, and padRedirect cannot send a visitor off-site.
  • Remote error pages. A visitor gets only Error: <id>, even with a spoofed Host. Log forging is blocked.
  • The page cache is bypassed by a foreign cookie or an Authorization header, is keyed on app, host and URI, never stores a non-200 response or a session cookie, and validates ETags.
  • Recursion is bounded. The restart guard, the 100-level limit and the {while} cap all hold. The 21 throwing templates were all contained by the try guards.

Applications and the harness

  • The crawl. 584 pages and 2,849 links were crawled. No in-scope link is broken, no manual page 500s or renders empty, and classicModels matches the database row for row.
  • The apps' own code.
    • No app builds SQL from request data, and the React providers bind their parameters.
    • The apps/?browse source viewer refuses traversal and redacts secrets.
    • The examples search is contained.
    • www/chess builds the DOM without innerHTML.
    • The React pages use getAttribute('data') throughout.
  • The gate fails closed on a missing, stale, same-second or foreign result, on a non-2xx trigger, and on new or zero tests. gate.sh proves 11 of these refusals.
  • The comparator requires an exact code for HTTP answers and a 2xx for patterns. The host rewrite is bounded to whole host names.

Remediation, in order

  1. Close the value-to-source edges.
    • Protect what padTagParm() returns (C1).
    • Strip the stand-in code points from all input (H1).
    • Stop sniffing a value from data= or {curl} as a file or a URL, and validate padDataFileName (H2).
    • Validate and JSON-encode the {page} and {ajax} names (M2).
    Pin each one with a Framework case written from the documented pattern.
  2. Give the field resolver the engine's rules: no engine names and no superglobal scan, with one classifier shared with request promotion (H3). Promote only the declared session names, and name sessions per app (M3).
  3. Take DATA out of the docroot and redact by value.
    • Drop the README advice and the develop links.
    • Exclude $padConfigApp from reports and redact known secret values (H4).
    • Redact the track payload, set its mode and add retention (H5, L17).
    • Make pruning atomic (M9).
    • Refuse executable extensions in {file} (L5).
  4. Stop the engine's own requests from inheriting trust. Use a fixed internal base and a per-boot marker header, and stop forwarding the visitor's User-Agent (H6).
  5. Guard the developer apps with padLocal() or a switch that defaults off, and require POST plus a token for their actions (H7). Contain the reference app (H8).
  6. Fix the evaluator's prefix sign (H9), the fractional modulo (L10) and the missing comma between options (M5). Each is a few lines with a clear case.
  7. Correct the docs.
    • Fix the escaping rules first (H10, M1).
    • Then the rest of the table (M16) and the manual (M12).
    • Turn each documented example into a case.
  8. Make the suites able to fail: literal answers with masked random cells (M13), a fixed runner User-Agent (M14), a lint that rejects patterns which cannot fail, and a timed restart verdict (M15). Then re-answer the cases that encode bugs.
  9. Work through the remaining Medium items (M4, M6–M8, M10, M11, M17–M23), then the Low items by area.
