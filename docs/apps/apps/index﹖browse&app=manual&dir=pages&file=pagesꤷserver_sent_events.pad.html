pages/server_sent_events.pad 

{meta title='Server-sent events'}

<p>A page usually answers once. With <code>padSse()</code> in its PHP it keeps the
connection open and sends events while they happen - what the browser's
<code>EventSource</code> reads, and what htmx's sse extension, a React or an Alpine component
listen to. There is no template: the stream is the whole answer.</p>

{ignore}
<code><?php

  // ticker.php - the producer sends the events itself
  padSse ( function ( $send, $lastId ) {
    foreach ( [ 'one', 'two', 'three' ] as $n => $word ) {
      $send ( 'word', [ 'n' => $n, 'word' => $word ], $n );
      sleep ( 1 );
    }
  }, [ 'retry' => 3000 ] );

?></code>
{/ignore}

<p>The browser side is a few lines, with no library:</p>

{ignore}
<code>const source = new EventSource('?ticker');
source.addEventListener('word', event => show(JSON.parse(event.data)));</code>
{/ignore}

<h2>On an interval</h2>

<p>Given <code>every</code>, PAD calls the producer itself, every so many seconds, and sends
what it answers as the event named by <code>event</code>: an array goes as JSON,
<code>NULL</code> sends nothing that round, <code>FALSE</code> ends the stream.</p>

{ignore}
<code><?php

  // stats.php - a fresh number every two seconds, for at most a minute
  padSse ( fn () => [ 'orders' => db ( "FIELD count(*) FROM orders" ) ],
           [ 'every' => 2, 'for' => 60, 'event' => 'stats' ] );

?></code>
{/ignore}

<table border="1" cellpadding="4">
  <tr><th>Option</th><th>Meaning</th></tr>
  <tr><td><code>every</code></td><td>Seconds between two calls of the producer; without it the producer is called once and loops itself</td></tr>
  <tr><td><code>for</code></td><td>How long a stream with <code>every</code> runs at most - 60 seconds unless said otherwise</td></tr>
  <tr><td><code>event</code></td><td>The name of the event an answer of the producer is sent as - <code>message</code> unless said otherwise</td></tr>
  <tr><td><code>retry</code></td><td>Milliseconds the browser waits before it reconnects when the stream ended</td></tr>
</table>

<h2>What to know</h2>

<ul>
  <li><code>$send ( $event, $data, $id )</code> answers whether the visitor is still
      connected; a long loop stops when it says no. Text data that runs over lines goes as
      several <code>data:</code> lines, which the browser joins again.</li>
  <li>An event needs data: the browser drops one whose data is empty, so an event a page
      closes the stream on says something - <code>$send ( 'done', 'done' )</code>.</li>
  <li>The browser reconnects by itself and sends the id of the last event it had - the
      producer gets it as its second argument, <code>padSseLastId()</code> reads it anywhere.</li>
  <li>The session is written and closed before the first event, so the visitor's other
      requests do not wait for the stream; read what the producer needs from it first.</li>
  <li>A stream holds a PHP worker for as long as it runs: keep <code>for</code> short and let
      the browser reconnect. Nothing of the answer is cached, compressed or buffered by PAD;
      <code>X-Accel-Buffering: no</code> asks nginx not to hold the events back.</li>
  <li>In the browser - an application packed by <code>pad pack</code>, see
      {manual 'offline_applications'} - one PHP answers the whole tab, so a stream is one round
      there: the <code>every</code> form calls its producer once and asks the browser back after
      the interval, a <code>FALSE</code> with nothing sent is answered 204 and ends it, and the
      loop form ends at the first event sent a tenth of a second after it began.
      <code>padWasm()</code> says where a page runs.</li>
</ul>

<p>The htmx application streams rows of HTML that its sse extension swaps in
(<a href="{$padHost}htmx/?examples/live">htmx/?examples/live</a>), the Alpine application JSON
an <code>EventSource</code> turns into state
(<a href="{$padHost}alpine/?examples/live">alpine/?examples/live</a>).</p>
