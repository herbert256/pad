# tree-sitter-pad - a Tree-sitter grammar for PAD templates

Native PAD highlighting for Zed, Helix and Neovim, plus what a syntax tree gives beyond
colour: folding of tag pairs, structural selection, and text objects such as "inside this
`{items}` loop".

```
{orders sort='id'}                      (block
  <li>{$id}: {echo $amount | money}</li>   (open_tag (tag_name (identifier)) (arguments (option ...)))
{/orders}                                  (body (text) (field_tag (variable)) (text) (tag ...) (text))
                                           (close_tag (tag_name (identifier))))
```

## What it parses

- **Text** around the tags - injected as HTML (`queries/injections.scm`), one combined
  document, so a `<script>` interrupted by tags still reads as one.
- **Tags**: `{name ...}`, `{/name}`, fields `{$x}` `{!x}` `{?x}` `{#x}` `{&x}` `{^x}`,
  prefixed names `{app:badge}`, property tags `{first@items}`, whitespace control
  `{~items~}`, comments `{# #}` and `{-- --}`, constructs `@page@`.
- **Pairs as blocks.** Whether `{orders}` opens a block is decided the way the engine
  decides it (`pad/level/tag.php`): only when a `{/orders}` closes it further on, with as
  many `{orders}` openers as `{/orders}` closers in between; `{orders /}` is always single.
  The external scanner (`src/scanner.c`) searches ahead for that close and keeps a stack of
  the open names, so `{if}` inside `{if}` nests and `{else}` stays a single tag inside its
  pair. A close inside a comment does not count, as the engine strips comments first.
- **`{ignore}` ... `{/ignore}`** keeps its content as one `raw_text` node - JavaScript,
  CSS, JSON - which the injection hands to HTML.
- **Inside a tag** the grammar is flat: the name, then `arguments` - strings, numbers,
  variables, options (`sort='id'`), pipes (`| money`, `| function:money`, `| %.2f`),
  operators, word operators (`eq`, `and`), `prop@tag` references and the `@` placeholder.
  Enough to colour every part without modelling PAD's expression language.

Every template under `apps/` parses without an error node except the regression tests that
are broken on purpose (`apps/regression/errors`, `framework/lenient`) and two exotic forms -
a pair written inside a tag's parameters, and `{${$hi}}`.

## The built-in names come from pad/

A tag name is a keyword when `pad/tags/` has it (plus the clauses `else`, `elseif`,
`when`), an application's tag otherwise; a pipe function is built in when `pad/functions/`
has it; a bare word among the arguments is an option when it is one of the option names.
Those lists sit between the generated markers of `queries/highlights.scm`, written by
`php editors/generate.php` from the same directories as the editors' completion lists -
and `helix/highlights.scm` is the same file in Helix's capture names. `./ci.sh` fails while
either is stale, like the completion lists. The patterns come in exclusive pairs (`any-of`
and `not-any-of` over one list), so no editor's rule for overlapping patterns decides a
colour.

## Files

| File | For |
|------|-----|
| `grammar.js`, `src/scanner.c` | the grammar and its external scanner |
| `src/parser.c`, `src/grammar.json`, `src/node-types.json`, `src/tree_sitter/` | generated by `tree-sitter generate --abi 14` - committed, so editors build without the CLI |
| `queries/highlights.scm` | highlights - nvim-treesitter capture names, which Zed reads too |
| `queries/injections.scm` | HTML in the text and in `{ignore}` - Neovim, Helix, Zed |
| `queries/folds.scm` | Neovim folding: pairs, `{ignore}`, comments |
| `queries/textobjects.scm` | nvim-treesitter-textobjects: `@block.inner/outer` for a pair, `@call` for a tag, `@parameter`, `@comment` |
| `helix/highlights.scm` | the highlights in Helix's names (generated) |
| `helix/textobjects.scm` | Helix and Zed vim mode: a pair is the `function` object (`mif`, `maf`), arguments are `parameter`s |
| `zed/` | the Zed extension: `extension.toml` and `languages/pad/config.toml` |
| `test/corpus/`, `test/highlight/` | `tree-sitter test` |
| `test/check.js` | the check ci.sh runs, with or without the CLI |

## Neovim (nvim-treesitter)

```lua
vim.filetype.add({ extension = { pad = 'pad' } })

-- nvim-treesitter, master branch
require('nvim-treesitter.parsers').get_parser_configs().pad = {
  install_info = {
    url = '/Users/herbert/pad/editors/tree-sitter-pad',
    files = { 'src/parser.c', 'src/scanner.c' },
  },
  filetype = 'pad',
}

-- nvim-treesitter, main branch
vim.api.nvim_create_autocmd('User', { pattern = 'TSUpdate', callback = function()
  require('nvim-treesitter.parsers').pad = {
    install_info = { path = '/Users/herbert/pad/editors/tree-sitter-pad' },
  }
end })
```

Then `:TSInstall pad`, and put the queries where Neovim looks for them:

```bash
mkdir -p ~/.config/nvim/queries/pad
cp /Users/herbert/pad/editors/tree-sitter-pad/queries/*.scm ~/.config/nvim/queries/pad/
```

Folding by pairs: `vim.wo.foldmethod = 'expr'` and
`vim.wo.foldexpr = 'v:lua.vim.treesitter.foldexpr()'`. With nvim-treesitter-textobjects,
`@block.inner` is the inside of a pair - map it to `ib` and `vib` selects the inside of the
`{items}` loop around the cursor.

## Helix

`~/.config/helix/languages.toml`:

```toml
[[language]]
name = "pad"
scope = "text.html.pad"
file-types = ["pad"]
injection-regex = "pad"
block-comment-tokens = { start = "{--", end = "--}" }
language-servers = ["pad-lsp"]      # see editors/lsp/README.md

[[grammar]]
name = "pad"
source = { path = "/Users/herbert/pad/editors/tree-sitter-pad" }
```

```bash
hx --grammar build
mkdir -p ~/.config/helix/runtime/queries/pad
cp /Users/herbert/pad/editors/tree-sitter-pad/helix/*.scm \
   /Users/herbert/pad/editors/tree-sitter-pad/queries/injections.scm \
   ~/.config/helix/runtime/queries/pad/
```

`mif` / `maf` select inside / around the pair at the cursor, `]f` moves to the next one.

## Zed

Assemble the extension from `zed/` and the queries, then *zed: install dev extension* on the
directory:

```bash
mkdir -p ~/pad-zed && cp -R /Users/herbert/pad/editors/tree-sitter-pad/zed/* ~/pad-zed/
cp /Users/herbert/pad/editors/tree-sitter-pad/queries/highlights.scm \
   /Users/herbert/pad/editors/tree-sitter-pad/queries/injections.scm \
   /Users/herbert/pad/editors/tree-sitter-pad/helix/textobjects.scm \
   ~/pad-zed/languages/pad/
```

In `~/pad-zed/extension.toml` set `rev` to a commit of the repository (`git rev-parse HEAD`)
- for a local build `repository = "file:///Users/herbert/pad"`. Zed compiles the grammar to
WebAssembly from `src/` itself.

## Developing

```bash
npm install -g tree-sitter-cli            # or npx tree-sitter-cli
cd editors/tree-sitter-pad
tree-sitter generate --abi 14             # after every change to grammar.js
tree-sitter test                          # corpus + highlight assertions
tree-sitter parse ../../apps/demo/todo.pad
php ../generate.php                       # after a built-in is added to pad/
node test/check.js                        # what ci.sh runs
```

ABI 14 keeps the parser loadable by older Neovim and Helix releases. The CLI compiles with
`$CC` (or `cc`); on a machine where another `cc` comes first on the `PATH`, `test/check.js`
uses `/usr/bin/cc`.
