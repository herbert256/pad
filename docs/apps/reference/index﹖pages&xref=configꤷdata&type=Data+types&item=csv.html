pages/charts.pad 		Result 
{meta title='Charts'}

<p>{tag 'chart'} draws a chart as inline SVG on the server. There is no JavaScript, so the
chart prints, works where scripts do not run, and caches like any other output. A
<code>bar</code> chart puts columns on a zero baseline; a <code>line</code> chart draws a line
over a light wash with the last point marked.</p>

{example 'fragments/charts_1'}

<h2>Where the numbers come from</h2>

<ul>
  <li><code>data='sales'</code> - a {tag 'data'} store, a sequence store, an array of the page's PHP, or a <code>_data</code> file of that name.</li>
  <li><code>value=</code> names the field with the number, <code>label=</code> the field for the axis. Without them the first numeric field is the value and the first other field the label.</li>
  <li><code>sequence='fibonacci', rows=12</code> - the first terms of a sequence, for demo data straight away.</li>
</ul>

<h2>Sparklines</h2>

<p>{tag 'sparkline'} is a line chart the size of a word, without axes, to stand in a sentence
or a table cell.</p>

{example 'fragments/charts_2'}

<h2>Accessible and themeable</h2>

<p>Every chart is an image to a screen reader (<code>role="img"</code>), named by its
<code>title=</code> and described by a list of its values. Each bar and point carries its own
tooltip. The colours are CSS custom properties - <code>--pad-chart-series</code>,
<code>--pad-chart-text</code>, <code>--pad-chart-grid</code>, <code>--pad-chart-surface</code> -
set on <code>.pad-chart</code>, and their defaults follow the page's
<code>color-scheme</code>, light or dark.</p>

 HTML
pages/hashing_and_encryption.pad 		Result 
{meta title='Hashing and encryption'}

<p>Three jobs every application with users meets: keeping passwords so that nobody - the
database's reader included - can read them back; handing a value to the browser that it
cannot read or change; and sending a link that works for the one who got it, until it
expires. PHP has the building blocks - <code>password_hash</code>, sodium,
<code>hash_hmac</code> - and these helpers put them together the safe way.</p>

<table border="1" cellpadding="6" cellspacing="0" style="border-collapse: collapse;">
  <tr><th>function</th><th>what it answers</th></tr>
  <tr><td><code>padHash ( $password )</code></td><td>the password hashed with <code>password_hash</code> and PHP's default algorithm - the text to store</td></tr>
  <tr><td><code>padHashCheck ( $password, $hash )</code></td><td>whether the password matches the hash</td></tr>
  <tr><td><code>padHashNeedsRehash ( $hash )</code></td><td>whether the hash was made with weaker settings than PHP's default now</td></tr>
  <tr><td><code>padEncrypt ( $value )</code></td><td>the value sealed: JSON-encoded, encrypted and signed, as one URL-safe string</td></tr>
  <tr><td><code>padDecrypt ( $payload, $default = NULL )</code></td><td>the value back - or the default for a payload that was changed, cut short or sealed with another key</td></tr>
  <tr><td><code>padSignedUrl ( $page, $vars = [], $expires = NULL )</code></td><td>a link to a page of this application with an expiry time and a signature</td></tr>
  <tr><td><code>padSignatureValid ()</code></td><td>whether this request came by such a link, unchanged and not expired</td></tr>
</table>

<h2>Passwords</h2>

<p>A password is never stored, only its hash. <code>padHash</code> makes one with a new
random salt each time, so two users with the same password get different hashes;
<code>padHashCheck</code> tells whether a password typed at login matches the stored hash.</p>

{example 'fragments/hashing_and_encryption_1'}

<ul>
  <li>After a successful login, <code>padHashNeedsRehash</code> says whether the stored hash
  was made with older settings - a lower cost, an older algorithm. The password is at hand
  right then, so the hash can be made again and stored.</li>
  <li>A password that is no text, or a hash that is none - the <code>NULL</code> of a user
  that does not exist - simply does not match: <code>padHashCheck</code> answers
  <code>FALSE</code>, never an error.</li>
</ul>

<h2>Sealed values</h2>

<p><code>padEncrypt</code> seals a value - text, a number, an array: whatever JSON holds -
so it can travel through the browser in a cookie, a hidden field or a link, and come back
unread and unchanged. Anyone can carry the payload; only the application can open it.</p>

{example 'fragments/hashing_and_encryption_2'}

<ul>
  <li>The value is JSON-encoded and sealed with sodium's <code>secretbox</code> and a random
  nonce, so the same value sealed twice gives two different payloads.</li>
  <li>A payload that was changed in a single character, cut short, or sealed with another
  key opens to the default - <code>NULL</code> unless one is given. An object comes back as
  an array.</li>
</ul>

<h2>Signed links</h2>

<p>A link in a mail - <em>confirm your address</em>, <em>download your invoice</em> - has to
work without a login, for the one who got it, and stop working after a while.
<code>padSignedUrl</code> adds the time it expires and a signature over the application, the
page and every value; <code>padSignatureValid ()</code>, in the page the link leads to, says
whether the request came by such a link.</p>

{example 'fragments/hashing_and_encryption_3'}

<p>The page the link leads to checks it before anything else:</p>

// invoice.php
if ( ! padSignatureValid () )
  padRedirect ( 'link_expired' );

$invoice = db ( "RECORD * FROM invoices WHERE id = {0}", [ $id ] );

<ul>
  <li>The expiry is a number of seconds, a <code>DateInterval</code> or a moment such as
  <code>'+2 days'</code>; without one the link never expires.</li>
  <li>A value changed, added or removed, another page, an expiry moved or passed - each makes
  the signature invalid. The order of the values does not count, and the link holds in the
  clean form too.</li>
  <li>The link is absolute, since it is mostly mailed; the values are visible in it - sign
  what must not change, seal what must not be read.</li>
</ul>

<h2>The key</h2>

<p>Sealing and signing use the application key. Without a setting it is the file
<code>DATA/keys/<application>.key</code>, made the first time it is needed - 32 random
bytes, readable by its owner only, under <code>DATA/</code> where no URL reaches. Set
<code>$padAppKey</code> in <code>_config/config.php</code> - 32 bytes, or
<code>'base64:'</code> and 32 bytes in base64, the form the key file holds - when several
servers must read each other's values, and keep it out of version control. A new key makes
every value sealed and every link signed before it unreadable. The error reports never show
it.</p>

{meta title='Template emails'}

<p>A mail is a PAD template, rendered to an HTML part and a text part and handed to a
transport. Templates live in <code>_mail/</code>, looked up like <code>_include/</code>:
<code>_mail/welcome.pad</code> is the HTML part, <code>_mail/welcome.txt</code> the text part
- without one, the text is made from the HTML - and <code>_mail/welcome.php</code> runs first.
<code>_inits.pad</code> and <code>_exits.pad</code> in the same <code>_mail/</code> are the
email's layout, with <code>@page@</code> where the mail goes:</p>

{example 'fragments/mail_1'}

<p>From a template, {mail} sends the same way. With a template it is
<code>{mail to=$email, template='welcome', subject='Welcome'}</code>; as a pair,
the content is the HTML part, rendered where it stands - in a loop with the fields of the
row:</p>

{example 'fragments/mail_2'}

<ul>
  <li><code>from</code>, <code>cc</code>, <code>bcc</code> and <code>replyTo</code> set the other
      headers; an address is <code>ann@example.com</code> or <code>Ann <ann@example.com></code>,
      several separated by commas. A line break in any of them is refused.</li>
  <li><code>$padMailTransport</code> says where it goes. <code>'file'</code>, the default, writes
      every message as an <code>.eml</code> under <code>DATA/mail/</code> instead of sending it,
      keeping the newest <code>$padMailKeep</code>; <code>'mail'</code> sends through PHP's
      <code>mail()</code>; the name of a function of the application gets the message - the
      place for SMTP through a library.</li>
  <li><code>$padMailFrom</code> is the sender; <code>$padMailLast</code> the last message of
      the request.</li>
</ul>

App: manual - Page: pages/markdown
PHP
 HTML
pages/markdown.pad 		Result 
{meta title='Markdown'}

<p>Help texts, release notes and content kept in a database are easier to write as Markdown.
{tag 'markdown'} writes what it wraps as HTML: the content renders first, so fields and tags
in it resolve, and the result is then read as Markdown. The text is dedented first, so the
block can be indented along with the template around it.</p>

{example 'fragments/markdown_1'}

<h2>The markdown pipe</h2>

<p>A value - a post body from the database - goes through the <code>markdown</code> pipe, or
is given to the tag as its parameter: <code>{markdown $post.body}</code>. The HTML it
makes is safe by construction, so a field whose last pipe is <code>markdown</code> skips the
sanitize chain that would escape the markup again.</p>

{example 'fragments/markdown_2'}

<h2>What is safe</h2>

<ul>
  <li>Raw HTML in the text is escaped, not passed on. The <code>html</code> option of the tag lets the template author's own markup through; the pipe has no such form.</li>
  <li>A link or image whose URL names a scheme other than http, https, mailto, ftp or tel - <code>javascript:</code>, <code>data:</code> - keeps only its text.</li>
  <li>The HTML made from a value stays a value: PAD tags written in a post are shown, never run.</li>
  <li>Braces in the template's own Markdown - code samples - need the <code>ignore</code> option: <code>{markdown ignore}</code>.</li>
</ul>

<p>The built-in renderer is a CommonMark subset: headings, paragraphs, emphasis, code spans
and code blocks, lists, links, images, block quotes and rules. Reference-style links, tables
and footnotes are not supported.</p>

{meta title='Errors in the template'}

<p>An error names the place in the template where it stands - the file, the line and the
column, the lines around it with a marker under the spot - next to the engine's own PHP file
and line. This page, <code>fragments/template_errors_typo.pad</code>, misspells the
<code>$total</code> its PHP sets:</p>

{ignore}
<code><table>
  <tr>
    <td>{$totl | upper}</td>
  </tr>
</table></code>
{/ignore}

<p>and its error report says where:</p>

{example 'fragments/template_errors_1', onlyResult}

<h2>What the report holds</h2>

<ul>
  <li><b>The spot</b> - the template file from the application root, its line and column, and the tag as written. The marker stands under what the message names: the field of <code>{$totl | upper}</code>, the function of <code>{echo $x | uppr}</code>.</li>
  <li><b>Did you mean</b> - for a field, a pipe function or a tag that does not exist, the nearest name there is: the fields visible where the error stands, the functions and tags of the engine, the application and <code>_common</code>.</li>
  <li><b>Included by</b> - an error in an <code>_include</code> snippet or in a page built by <code>{page}</code> also names the tag that brought it in.</li>
  <li><b>Wrapped by</b> - the <code>_inits.pad</code> files the page sits in.</li>
  <li><b>An editor link</b> - <code>vscode://file/...:line:column</code> opens the spot.</li>
</ul>

<h2>Where it shows</h2>

<p>On the error page of a local request, in the JSON body a local tool gets (as <code>template</code>:
<code>file</code>, <code>line</code>, <code>column</code>, <code>tag</code>, <code>excerpt</code>,
<code>suggest</code>, <code>included</code>, <code>wrapped</code>, <code>link</code>), on the
console, and at the end of the log line as <code>file:line:column</code>. A visitor from
elsewhere still sees only the request id.</p>

<p>The build joins the <code>_lib</code> snippets, the <code>_inits.pad</code> and
<code>_exits.pad</code> of every directory and the page into one text, and keeps a map of
which part came from which file. When a spot cannot be traced back for certain - text a
page's PHP printed, a tag's output read again as template - the report leaves the position
out rather than guess.</p>
